Dasar RouterOS & Cara Akses

Panduan singkat untuk pemula: mengenal RouterOS, cara masuk ke router, dan dasar memakai command line. Cocok sebagai langkah pertama sebelum konfigurasi lain.

Apa itu RouterOS

RouterOS adalah sistem operasi jaringan dari MikroTik untuk router, switch, dan access point. Fiturnya: routing, firewall, VPN, wireless, QoS, sampai otomasi.

Versi yang dipakai di buku ini: RouterOS 7.26. Sintaks v7 sedikit berbeda dari v6 — terutama menu /routing dan fitur Bridge VLAN.

Cara masuk ke router

WinBox (GUI, paling ramah)

  1. Unduh WinBox dari mikrotik.com, buka aplikasinya.
  2. Tab Neighbors akan menampilkan router via MAC (tanpa perlu IP).
  3. Klik MAC-nya, login (default user admin, password kosong / sesuai).

SSH (baris perintah)

ssh admin@192.168.88.1

Di CLI, tekan Tab untuk melengkapi perintah dan ? untuk bantuan.

WebFig (browser)

Buka http://192.168.88.1 di browser.

Dasar command line

Setiap perintah dijalankan di menu tertentu, misalnya:

/ip/address/print
/ip/address/add address=192.168.88.1/24 interface=ether2
  • print — tampilkan isi menu
  • add — tambah entri
  • set — ubah entri
  • remove — hapus entri
  • [find ...] — cari entri, mis. remove [find address=192.168.88.1/24]
  • .. — naik satu level, / — ke root

Tips: / di depan = path absolut, jadi aman dijalankan dari mana saja.

Simpan & pindahkan konfigurasi

/export file=backup-config
/system/backup/save name=full-backup
  • /export → skrip teks (bisa dibaca & diedit)
  • /system/backup → backup biner lengkap (untuk restore penuh)

Angka penting

  • /ip/address/print — pastikan IP benar
  • /system/identity/set name=ROUTER-INTI — beri nama router (berguna untuk NOC)
  • /system/clock/set time-zone-name=Asia/Jakarta

IP Address, Gateway & Routing Dasar

Mengatur alamat IP, default gateway, dan route statis — fondasi supaya router bisa berkomunikasi ke jaringan lain.

1. Memberi alamat IP ke interface

/ip/address/add address=192.168.88.1/24 interface=ether2
/ip/address/print
  • IP dipasang di interface fisik (ether) atau di bridge kalau portnya sudah jadi member bridge.
  • Kolom actual-interface menunjukkan interface sebenarnya tempat IP terpasang.

2. Menghubungkan dua router langsung (back-to-back)

# Router A
/ip/address/add address=10.10.10.1/30 interface=ether1
# Router B
/ip/address/add address=10.10.10.2/30 interface=ether1

Tes dari Router A: /ping 10.10.10.2

3. Default gateway (route ke internet)

/ip/route/add gateway=192.168.1.1

Kalau WAN pakai DHCP client, gateway biasanya otomatis.

4. Route statis ke jaringan tertentu

/ip/route/add dst-address=10.20.0.0/24 gateway=192.168.88.2

Cek hasil: /ip/route/print where dst-address=10.20.0.0/24

5. Address list (dipakai firewall/BGP)

/ip/firewall/address-list/add list=LAN address=192.168.88.0/24

6. DNS

/ip/dns/set servers=8.8.8.8,1.1.1.1
/ip/dns/set allow-remote-requests=yes

Konsep singkat

  • connected route muncul otomatis saat IP dipasang
  • static route kita tentukan manual
  • dynamic route dari OSPF/BGP/DHCP
  • route dibandingkan lewat distance (makin kecil makin diprioritaskan)

Sering bikin gagal

  • Interface sudah jadi bridge port → pasang IP di bridge, bukan di ether
  • ether1 masih ada DHCP client → bentrok, matikan dulu
  • Lupa gateway → tidak ada jalan keluar ke internet

Firewall & Keamanan Router

Mengamankan router supaya tidak mudah diserang dari internet. Ini ringkasan praktis dari bab Securing your router dan Firewall.

Prinsip utama

Firewall input chain melindungi router itu sendiri. Konfigurasi default MikroTik sudah menutup akses manajemen dari WAN (defconf: drop all not coming from LAN). Jangan hapus rule itu.

1. Input chain dasar (router tanpa default config)

/ip/firewall/filter
add chain=input action=accept connection-state=established,related,untracked \
    comment="accept established,related,untracked"
add chain=input action=drop connection-state=invalid comment="drop invalid"
add chain=input action=accept in-interface=ether1 protocol=icmp comment="accept ICMP"
add chain=input action=drop in-interface=ether1 comment="block everything else"

Sesuaikan ether1 dengan interface WAN (kalau PPPoE/LTE, ganti). Salah interface bisa membuat kamu kehilangan akses.

2. Kalau router sudah pakai default config

Tambahkan accept di depan rule defconf dengan place-before:

add chain=input action=accept in-interface-list=WAN protocol=tcp dst-port=8291 \
    comment="allow WinBox" \
    place-before=[find comment="defconf: drop all not coming from LAN"]

3. Hardening checklist

  • Update RouterOS ke versi stabil terbaru
  • Ganti user admin, pakai password ≥12 karakter:
/user/add name=myname password="..." group=full
/user/disable admin
  • Satu akun per admin; pakai SSH key
  • Batasi user ke IP tertentu: /user/set 0 address=192.168.88.0/24
  • Matikan MAC-server:
/tool/mac-server/set allowed-interface-list=none
/tool/mac-server/mac-winbox/set allowed-interface-list=none
/tool/mac-server/ping/set enabled=no
  • Matikan Neighbor Discovery: /ip/neighbor/discovery-settings/set discover-interface-list=none
  • Matikan bandwidth server: /tool/bandwidth-server/set enabled=no
  • Matikan service tak terpakai: /ip/service/disable telnet,ftp,www,api
  • Ganti port SSH & kuatkan kripto:
/ip/service/set ssh port=2200
/ip/ssh/set strong-crypto=yes
  • Matikan proxy/SOCKS/UPnP: /ip/proxy/set enabled=no, /ip/socks/set enabled=no, /ip/upnp/set enabled=no
  • Disable interface yang tidak dipakai

4. Proteksi brute-force SSH

Rule menaikkan sumber lewat 3 address-list, blacklist di koneksi ke-4:

/ip/firewall/filter
add chain=input action=add-src-to-address-list protocol=tcp dst-port=22 \
    connection-state=new in-interface-list=WAN src-address-list=connection3 \
    address-list=bruteforce_blacklist address-list-timeout=1d \
    comment="SSH brute force: blacklist" \
    place-before=[find comment="defconf: drop all not coming from LAN"]
# (lanjut: connection2->connection3, connection1->connection2, first->connection1)
add chain=input action=accept protocol=tcp dst-port=22 in-interface-list=WAN \
    src-address-list=!bruteforce_blacklist comment="SSH brute force: accept" \
    place-before=[find comment="defconf: drop all not coming from LAN"]
add chain=input action=drop protocol=tcp dst-port=22 in-interface-list=WAN \
    comment="SSH brute force: drop blacklisted" \
    place-before=[find comment="defconf: drop all not coming from LAN"]

Peringatan

  • Jangan expose WinBox/SSH ke internet. Pakai VPN (WireGuard) untuk akses jauh.
  • Kalau terpaksa buka dari WAN: password kuat, batasi source address, aktifkan brute-force protection, update terus, dan pantau log.

DHCP, DNS & NAT

Membuat client di LAN otomatis dapat IP dan bisa internet.

1. DHCP Server (bagi IP ke client)

/ip/pool/add name=dhcp_pool ranges=192.168.88.10-192.168.88.254
/ip/dhcp-server/add name=dhcp1 interface=bridge1 address-pool=dhcp_pool
/ip/dhcp-server/network/add address=192.168.88.0/24 gateway=192.168.88.1 \
    dns-server=192.168.88.1

Cara cepat (interaktif): /ip/dhcp-server/setup lalu tekan Enter tiap nilai.

2. DHCP Client (router ambil IP dari upstream)

/ip/dhcp-client/add interface=ether1 disabled=no

Cek: /ip/dhcp-client/print

3. DNS

/ip/dns/set servers=1.1.1.1,8.8.8.8 allow-remote-requests=yes
  • allow-remote-requests=yes → router melayani DNS untuk client LAN.
  • Kalau router bukan DNS server, set allow-remote-requests=no biar aman.

4. NAT (masquerade) — client LAN bisa internet

Lewat satu IP publik dari WAN:

/ip/firewall/nat/add chain=srcnat out-interface-list=WAN action=masquerade \
    comment="NAT ke internet"
  • Pastikan interface WAN masuk ke interface-list WAN: /interface/list/member/add list=WAN interface=ether1 (atau pppoe-out1).

5. Forward firewall dasar

Router dengan konfigurasi default sudah punya rule forward. Kalau dari nol, minimal izinkan established/related dari LAN dan drop sisanya:

/ip/firewall/filter
add chain=forward action=accept connection-state=established,related
add chain=forward action=accept in-interface-list=LAN out-interface-list=WAN
add chain=forward action=drop connection-state=invalid

6. Port forwarding (akses server internal dari luar)

/ip/firewall/nat/add chain=dstnat action=dst-nat protocol=tcp dst-port=8080 \
    to-addresses=192.168.88.10 to-ports=80 comment="forward web"

Hati-hati: buka port seminimal mungkin.

Bridge & VLAN (Bridge VLAN Filtering)

Menggabungkan port dan memisahkan jaringan dengan VLAN — penting untuk FTTH dan jaringan ISP.

1. Bridge dasar

/interface/bridge/add name=bridge1
/interface/bridge/port/add interface=ether2 bridge=bridge1
/interface/bridge/port/add interface=ether3 bridge=bridge1

Pasang IP di bridge, bukan di ether-nya:

/ip/address/add address=192.168.88.1/24 interface=bridge1

2. VLAN dengan Bridge VLAN Filtering (v7)

Aktifkan filtering di bridge:

/interface/bridge/set bridge1 vlan-filtering=yes

Tentukan PVID untuk port access:

/interface/bridge/port/set [find interface=ether2] pvid=10
/interface/bridge/port/set [find interface=ether3] pvid=20

Tandai VLAN (tagged) dan untagged pada bridge:

/interface/bridge/vlan/add bridge=bridge1 vlan-ids=10 tagged=bridge1 untagged=ether2
/interface/bridge/vlan/add bridge=bridge1 vlan-ids=20 tagged=bridge1 untagged=ether3

Port trunk (ke switch lain) → tagged:

/interface/bridge/vlan/add bridge=bridge1 vlan-ids=10,20 tagged=bridge1,ether4

Beri IP per VLAN (interface VLAN):

/interface/vlan/add name=vlan10 vlan-id=10 interface=bridge1
/ip/address/add address=192.168.10.1/24 interface=vlan10

Konsep penting

  • Access port: satu VLAN, untagged.
  • Trunk port: banyak VLAN, tagged.
  • PVID: VLAN default untuk trafik untagged yang masuk port.
  • vlan-filtering=yes mengaktifkan pengecekan tag di bridge.

Sering bikin gagal

  • Pasang IP di ether yang sudah jadi bridge port → tidak jalan
  • Lupa vlan-filtering=yes → VLAN tidak difilter
  • CPU forwarding: hardware offload kadang perlu bridge tertentu; untuk trafik routing antar-VLAN, pastikan desain interface VLAN-nya benar.

PPPoE Server & Client (untuk ISP)

Menyiapkan RouterOS sebagai access concentrator PPPoE untuk pelanggan, dan sebagai client ke upstream.

Bagian A — PPPoE Server (sisi ISP)

1. Pool IP untuk pelanggan

/ip/pool/add name=pppoe-pool ranges=10.10.0.2-10.10.255.254

2. Profile PPP

/ppp/profile/add name=pelanggan local-address=10.10.0.1 remote-address=pppoe-pool \
    dns-server=1.1.1.1,8.8.8.8

3. PPPoE Server di interface

/interface/pppoe-server/server/add service-name=internet interface=bridge1

Bisa juga satu server melayani banyak interface / satu interface banyak server.

4. Akun pelanggan (secrets)

/ppp/secret/add name=pelanggan1 password=Rahasia123 service=pppoe profile=pelanggan

5. Cek sesi aktif

/ppp/active/print
/interface/pppoe-server/server/print

Bagian B — PPPoE Client (ke upstream)

/interface/pppoe-client/add name=pppoe-out1 interface=ether1 \
    user=userISP password=passISP add-default-route=yes use-peer-dns=yes disabled=no

Tambahkan ke interface-list WAN supaya kena NAT/firewall:

/interface/list/member/add list=WAN interface=pppoe-out1

Monitor: /interface/pppoe-client/monitor pppoe-out1 once

Catatan praktis ISP

  • MTU 1492: PPPoE membawa header tambahan; pastikan clamping MSS kalau ada masalah akses halaman tertentu:
/ip/firewall/mangle/add chain=forward protocol=tcp tcp-flags=syn \
    action=change-mss new-mss=1400 tcp-mss=1400-2000 comment="MSS clamp PPPoE"
  • Queue per pelanggan: pakai profile rate-limit atau simple queue.
  • Isolasi: default, PPPoE server tidak meneruskan trafik antar-client.
  • RADIUS: bisa pakai untuk autentikasi terpusat (menu /radius).

Troubleshooting singkat

  • Sesi tidak naik → cek service-name, interface, dan secret/password
  • Pelanggan dapat IP tapi tidak internet → cek NAT, route, dan firewall forward
  • Cek log: /log/print atau filter topik pppoe

Queue & Manajemen Bandwidth

Membatasi dan membagi bandwidth — sering dipakai ISP untuk paket pelanggan.

1. Simple Queue (percepat, per target)

Membatasi trafik per IP/client:

/queue/simple/add name=pelanggan1 target=10.10.0.2/32 \
    max-limit=10M/10M comment="Paket 10 Mbps"
  • max-limit=upload/download
  • target bisa IP, subnet, atau interface.

2. Queue per PPPoE (via profile rate-limit)

/ppp/profile/set [find name=pelanggan] rate-limit="10M/10M"

Lebih rapi untuk banyak pelanggan karena ikut sesi PPPoE.

3. Queue Tree (kontrol per kelas trafik)

Butuh mangle untuk menandai trafik dulu:

/ip/firewall/mangle/add chain=forward action=mark-packet \
    new-packet-mark=web passthrough=no protocol=tcp dst-port=80,443
/queue/tree/add name=web parent=global packet-mark=web max-limit=50M

4. PCQ (bagi rata otomatis antar client)

Cocok untuk hotspot/RT-RW net:

/queue/type/add name=pcq-down kind=pcq pcq-rate=0 pcq-classifier=dst-address
/queue/simple/add name=download target=192.168.0.0/16 \
    max-limit=100M queue=pcq-down/pcq-down

pcq-rate=0 artinya pembagian otomatis dari total.

Konsep

  • Simple Queue: paling gampang, urutannya: dari paling spesifik ke umum.
  • Queue Tree: kontrol detail per kelas, butuh mangle.
  • PCQ: pembagian dinamis per client.

Tips

  • Ukuran burst bisa membantu trafik sesaat: burst-limit, burst-time
  • Untuk hulu (upload), queue bekerja di interface keluar — perhatikan arah.
  • Monitor: /queue/simple/print stats

Routing: Statis, OSPF & BGP

Ringkasan cara router saling bertukar rute.

1. Static route (paling dasar)

/ip/route/add dst-address=10.20.0.0/24 gateway=192.168.88.2
/ip/route/add dst-address=0.0.0.0/0 gateway=192.168.1.1   # default

Cek: /ip/route/print

2. OSPF (dinamis, dalam satu organisasi)

Menyalakan instance dan menambahkan interface:

/routing/ospf/instance/add name=ospf1
/routing/ospf/area/add name=backbone area-id=0.0.0.0 instance=ospf1
/routing/ospf/interface-template/add networks=10.0.0.0/24 area=backbone

Intent: OSPF otomatis bertukar rute antar router di area yang sama. Cek tetangga: /routing/ospf/neighbor/print

3. BGP (antar-AS, internet)

Menu: /routing/bgp/instance, /routing/bgp/connection, /routing/bgp/session. local.role wajib diisi (ebgp, ibgp, ibgp-rr, atau role RFC 9234).

Contoh eBGP dasar:

/routing/bgp/instance/add name=myInstance as=65531
/routing/bgp/connection/add name=toR2 remote.address=192.168.1.2 \
    instance=myInstance local.role=ebgp

Cek sesi: /routing/bgp/session/print (flag E = established)

Umumkan prefix sendiri (harus ada route match / IGP):

/ip/firewall/address-list/add list=my-nets address=103.x.x.0/24
/routing/bgp/connection/set [find name=toR2] output.network=my-nets

Jebakan BGP (FAQ buku)

  • eBGP ke loopback gagal → set multihop=yes
  • Rute tidak di-advertise ke peer lain → cek output filter / beda instance
  • Best path tidak jalan → hanya berlaku dalam satu instance
  • listen=yes jangan dibuka di link publik tanpa firewall

VPN: WireGuard, IPsec & L2TP

Menghubungkan site/lokasi secara aman.

1. WireGuard (rekomendasi buku, cepat & modern)

Side A

/interface/wireguard/add name=wg0 listen-port=13231
/ip/address/add address=10.0.0.1/24 interface=wg0
/interface/wireguard/peers/add interface=wg0 public-key="<pubkey B>" \
    endpoint-address=<ip-publik-B> endpoint-port=13231 \
    allowed-address=10.0.0.2/32 persistent-keepalive=25s
/ip/firewall/filter/add chain=input action=accept protocol=udp dst-port=13231 \
    comment="WireGuard"

Side B

/interface/wireguard/add name=wg0 listen-port=13231
/ip/address/add address=10.0.0.2/24 interface=wg0
/interface/wireguard/peers/add interface=wg0 public-key="<pubkey A>" \
    endpoint-address=<ip-publik-A> endpoint-port=13231 allowed-address=10.0.0.1/32

Lihat kunci publik router sendiri:

/interface/wireguard/print

Akses manajemen router lewat tunnel WireGuard lebih aman daripada membuka WinBox/SSH ke internet.

2. IPsec

Untuk site-to-site dengan perangkat non-WireGuard:

/ip/ipsec/policy/add src-address=192.168.10.0/24 dst-address=192.168.20.0/24 \
    tunnel=yes action=encrypt proposal=default peer=peer1
/ip/ipsec/peer/add name=peer1 address=<ip-lawan> exchange-mode=ike2
/ip/ipsec/identity/add peer=peer1 secret="kunci-bersama"

Cek: /ip/ipsec/active-peers/print, /ip/ipsec/policy/print

3. L2TP (client ke server)

/interface/l2tp-client/add name=l2tp-out connect-to=<ip-server> \
    user=<nama> password=<sandi> disabled=no

Bisa dibungkus IPsec untuk keamanan tambahan.

Tips umum

  • Selalu batasi firewall: hanya izinkan UDP port VPN yang dipakai
  • Pakai allowed-address yang spesifik, jangan 0.0.0.0/0 kalau tidak perlu
  • Untuk NOC: VPN jadi jalur utama akses router, bukan port-forward

Referensi buku

  • Manual: 14 Virtual Private Networks → WireGuard, IPsec, L2TP
  • Manual: 02 Getting Started → Securing your router

Maintenance: Backup, Upgrade & Monitoring

Rutinitas agar router tetap sehat dan bisa dipulihkan.

1. Backup

/system/backup/save name=full-2026-11-25
/export file=config-2026-11-25
  • /system/backup → biner lengkap (restore penuh)
  • /export → skrip teks (bisa diedit/dibaca) Ambil filenya lewat WinBox Files atau /file/print + FTP/SFTP.

2. Restore

/system/backup/load name=full-2026-11-25
# atau
/import file=config-2026-11-25.rsc

3. Upgrade RouterOS

/system/package/update/check-for-updates
/system/package/update/install

Router reboot setelah install. Selalu cek versi stabil dan changelog sebelum upgrade produksi:

/system/resource/print
/system/routerboard/print

4. Logging

/system/logging/add topics=error,warning,critical action=memory
/system/logging/add topics=critical action=disk
/log/print

Kirim log ke syslog server supaya terpusat:

/system/logging/action/add name=remote type=remote remote=192.168.1.50
/system/logging/add topics=info action=remote

5. Monitoring

  • SNMP: /snmp/set enabled=yes contact="NOC" location="..." lalu tambah community
  • Graphing: /tool/graphing/add interface=all
  • Resource: /system/resource/print (CPU, RAM, disk)
  • Cek koneksi: /ping 8.8.8.8, /tool/traceroute 8.8.8.8
  • Torch (lihat trafik real-time): /tool/torch interface=ether1

6. Troubleshooting cepat

  • Cek interface: /interface/print (flag R = running)
  • Cek route: /ip/route/print
  • Cek koneksi: /ip/firewall/connection/print
  • Cek log: /log/print

Wajib dilakukan

  • Gunakan akun staf IT masing-masing untuk pekerjaan harian agar riwayat aktivitas tercatat.
  • Pindahkan (Migrate) VM ke node lain sebelum me-reboot salah satu node PVE saat pemeliharaan.

Dilarang

BAB I — Arsitektur Sistem & Persiapan

1.1 Tujuan dan Ruang Lingkup

Dokumen ini berfungsi sebagai acuan standar bagi tim IT dalam melakukan instalasi, konfigurasi, operasional harian, pencadangan data (backup), dan pemulihan bencana (disaster recovery) pada infrastruktur virtualisasi kantor yang terdiri atas 3 (tiga) unit server fisik: dua server komputasi Proxmox Virtual Environment (PVE) dan satu server pencadangan khusus Proxmox Backup Server (PBS).

1.2 Topologi dan Alokasi Server

Gunakan skema penamaan (hostname) dan pengalamatan IP statis yang seragam sebelum memulai instalasi. Nilai IP di bawah ini merupakan contoh standar yang dapat disesuaikan dengan segmen VLAN/subnet server kantor:

pve-node1.dputr.local

  • Peran Server: Compute Node 1
  • Contoh Alamat IP: 192.168.10.11/24
  • Fungsi Utama: Menjalankan VM/CT produksi utama

pve-node2.dputr.local

  • Peran Server: Compute Node 2
  • Contoh Alamat IP: 192.168.10.12/24
  • Fungsi Utama: Menjalankan VM/CT produksi & target migrasi

pbs-server.dputr.local

  • Peran Server: Backup & QDevice
  • Contoh Alamat IP: 192.168.10.13/24
  • Fungsi Utama: Penyimpanan backup terdeduplikasi & pemberi suara ke-3 (Quorum)

1.3 Catatan Arsitektur: Quorum pada Cluster 2-Node

Secara bawaan, Proxmox Cluster menggunakan protokol Corosync yang membutuhkan suara mayoritas (quorum) lebih dari 50% untuk mengizinkan perubahan konfigurasi dan menjalankan High Availability. Pada cluster yang hanya memiliki 2 node, matinya 1 node mengakibatkan suara tersisa 1 dari 2 (50%), sehingga cluster terkunci (read-only) untuk mencegah kondisi split-brain.

Untuk mengatasi hal tersebut pada infrastruktur 3 server ini, Server PBS (pbs-server) wajib difungsikan sekaligus sebagai Corosync QDevice (pemberi suara ke-3 tanpa menjalankan VM). Dengan demikian, jika salah satu node PVE mengalami gangguan, node PVE yang tersisa tetap memiliki 2 dari 3 suara (66,7%) dan operasional tetap berjalan normal.

1.4 Persiapan Perangkat Keras dan BIOS/UEFI

Sebelum instalasi dilakukan pada ketiga server, pastikan persyaratan berikut telah terpenuhi:

  • Virtualisasi CPU: Aktifkan fitur Intel VT-x / VT-d atau AMD-V / AMD-Vi pada BIOS/UEFI (wajib untuk pve-node1 dan pve-node2).
  • Konfigurasi Penyimpanan:
  • Jika menggunakan ZFS (direkomendasikan untuk fitur replikasi antar node), atur RAID Controller ke mode HBA / IT Mode (nonaktifkan Hardware RAID).
  • Jika menggunakan Hardware RAID, buat konfigurasi RAID 1 untuk OS dan RAID 10/5/6 untuk penyimpanan VM, lalu gunakan filesystem LVM-Thin atau ext4.
  • Jaringan: Disarankan memisahkan trafik manajemen/cluster dan trafik jaringan VM/backup menggunakan port NIC fisik terpisah atau VLAN.
  • Media Instalasi: Siapkan USB bootable berisi berkas ISO resmi terbaru untuk Proxmox VE dan Proxmox Backup Server (gunakan tool seperti BalenaEtcher, Ventoy, atau Rufus dalam mode DD Image).

BAB II — Instalasi & Konfigurasi Proxmox VE

Lakukan seluruh langkah pada bab ini secara bergantian pada pve-node1 dan pve-node2.

2.1 Prosedur Instalasi Proxmox VE

  1. Booting Media Instalasi: Nyalakan server, masuk ke Boot Menu, dan pilih USB bootable Proxmox VE. Pilih Install Proxmox VE (Graphical).
  2. Persetujuan Lisensi (EULA): Baca ketentuan lisensi lalu klik I agree.
  3. Target Harddisk & Filesystem: Pilih disk tujuan instalasi. Klik Options untuk memilih filesystem: gunakan ZFS (RAID1) jika tersedia 2 disk OS tanpa Hardware RAID, atau ext4 / LVM jika menggunakan Hardware RAID.
  4. Lokasi dan Zona Waktu: Atur Country ke Indonesia, Time zone ke Asia/Jakarta (atau sesuai zona waktu kantor), dan Keyboard Layout ke U.S. English.
  5. Kredensial Administrator: Masukkan kata sandi root yang kuat (kombinasi huruf besar, kecil, angka, dan simbol) serta alamat email resmi tim IT untuk notifikasi sistem.
  6. Konfigurasi Jaringan: Pilih antarmuka manajemen (Management Interface). Masukkan Hostname (FQDN) (contoh: pve-node1.dputr.local), IP Address (CIDR), Gateway, dan DNS Server internal.
  7. Konfirmasi dan Instalasi: Periksa ringkasan konfigurasi, pastikan opsi Automatically reboot after successful installation dicentang, lalu klik Install. Cabut USB instalasi saat server melakukan reboot.

2.2 Akses Antarmuka Web (Web GUI)

Setelah server menyala kembali, akses antarmuka manajemen melalui peramban web pada komputer admin:

  • URL:https://<IP-Node>:8006 (contoh: https://192.168.10.11:8006)
  • Username:root | Realm:Linux PAM standard authentication

2.3 Konfigurasi Pasca-Instalasi (Wajib)

Lakukan langkah berikut pada kedua node segera setelah instalasi selesai:

  1. Pengaturan Repositori: Jika kantor tidak menggunakan lisensi berbayar (Enterprise), buka menu Node > Updates > Repositories. Pilih repositori pve-enterprise dan ceph (enterprise), lalu klik Disable. Klik Add, lalu tambahkan repositori No-Subscription.
  2. Pembaruan Sistem: Buka Node > Shell dan jalankan perintah berikut untuk memperbarui paket sistem dan kernel:
apt update && apt full-upgrade -y

Lakukan reboot jika terdapat pembaruan kernel (reboot).
3. Sinkronisasi Waktu (NTP): Pastikan waktu antar server sinkron agar Corosync Cluster dan jadwal backup berjalan akurat. Periksa status melalui shell:

chronyc tracking

Jika server tidak terhubung langsung ke internet, arahkan konfigurasi /etc/chrony/chrony.conf ke NTP Server internal kantor, lalu jalankan systemctl restart chrony.

BAB III — Cluster 2-Node & Quorum (QDevice)

Pastikan pve-node1 dan pve-node2 dapat saling berkomunikasi melalui jaringan (ping) dan belum memiliki VM/CT di node yang akan bergabung (pve-node2).

3.1 Membuat Cluster di Node 1 dan Menggabungkan Node 2

  1. Pada Web GUI pve-node1: Buka menu Datacenter > Cluster. Klik Create Cluster. Isi Cluster Name (contoh: cluster-dputr) dan pilih Cluster Network (IP manajemen/khusus cluster). Klik Create. Setelah terbentuk, klik Join Information lalu klik Copy Information.
  2. Pada Web GUI pve-node2: Buka menu Datacenter > Cluster. Klik Join Cluster. Tempel (paste) informasi yang telah disalin ke kolom Information. Masukkan kata sandi root dari pve-node1, pilih Cluster Network, lalu klik Join 'cluster-dputr'.
  3. Verifikasi: Tunggu hingga antarmuka Web GUI termuat ulang. Kedua node kini dapat dikelola dari satu dasbor terpusat.

3.2 Menjadikan Server PBS sebagai Corosync QDevice

Catatan Prasyarat: Jalankan langkah ini setelah Server PBS selesai diinstal pada Bab IV (Bagian 4.1 & 4.2).

  1. Instalasi layanan QNetd pada Server PBS (pbs-server): Masuk ke shell pbs-server dan jalankan:
apt update && apt install corosync-qnetd -y
  1. Instalasi paket QDevice pada kedua Node PVE (pve-node1 dan pve-node2): Jalankan perintah berikut pada shell masing-masing node PVE:
apt update && apt install corosync-qdevice -y
  1. Mendaftarkan QDevice ke Cluster: Cukup jalankan dari shell pve-node1:
pvecm qdevice setup 192.168.10.13

(Ganti 192.168.10.13 dengan IP aktual pbs-server. Masukkan kata sandi root PBS saat diminta).
4. Verifikasi Status Quorum: Jalankan pvecm status pada pve-node1. Pastikan keluaran menunjukkan Total votes: 3, Quorum: 2, dan Qdevice berstatus aktif.

BAB IV — Instalasi & Integrasi PBS

4.1 Prosedur Instalasi PBS

  1. Lakukan booting server ke-3 menggunakan USB bootable Proxmox Backup Server.
  2. Pilih Install Proxmox Backup Server (Graphical) dan setujui EULA.
  3. Pilih disk khusus Sistem Operasi (pisahkan disk OS dari disk kapasitas besar yang akan digunakan sebagai Datastore backup).
  4. Atur lokasi (Indonesia), zona waktu, kata sandi root, email admin, dan konfigurasi jaringan statis (pbs-server.dputr.local / 192.168.10.13/24).
  5. Selesaikan instalasi dan reboot. Akses Web GUI PBS melalui https://192.168.10.13:8007.

4.2 Konfigurasi Pasca-Instalasi PBS

  1. Buka menu Administration > Repositories. Nonaktifkan repositori pbs-enterprise (jika tanpa lisensi) dan tambahkan repositori No-Subscription.
  2. Buka Administration > Shell, lalu perbarui sistem:
apt update && apt full-upgrade -y

4.3 Pembuatan Datastore Backup

  1. Buka menu Administration > Storage / Disks.
  2. Siapkan disk penyimpanan data backup (disarankan menggunakan ZFS melalui tab ZFS > Create: ZFS dengan konfigurasi RAIDZ1/RAIDZ2 atau Mirror sesuai jumlah disk).
  3. Centang opsi Add as Datastore saat membuat ZFS pool, atau buat manual melalui menu Datastore > Add Datastore (contoh nama datastore: backup-produksi).

4.4 Manajemen Akses Aman (User & API Token)

Demi keamanan (prinsip hak akses minimum), integrasi PVE ke PBS tidak boleh menggunakan akun root. Buat akun khusus backup:

  1. Buka Access Control > User Management > Add: User name: pve-backup | Realm: pbs | Isi kata sandi.
  2. Buka Access Control > API Token > Add: User: pve-backup@pbs | Token name: cluster-token | Hapus centang Privilege Separation (atau atur izin terpisah). Catat dan simpan Secret yang muncul karena hanya ditampilkan satu kali.
  3. Buka Access Control > Permissions > Add > User Permission (dan API Token Permission): Path: /datastore/backup-produksi | User / API Token: pve-backup@pbs (dan tokennya) | Role: DatastoreBackup (memberi hak baca/tulis backup tanpa izin menghapus backup lama secara sembarangan).

4.5 Integrasi PBS ke Cluster Proxmox VE

  1. Ambil Fingerprint PBS: Pada Web GUI PBS, buka Dashboard, klik Show Fingerprint, lalu klik Copy.
  2. Tambahkan Storage di PVE: Pada Web GUI Cluster PVE (pve-node1), buka Datacenter > Storage > Add > Proxmox Backup Server.
  3. Isi parameter berikut:
  1. ID:pbs-dputr
  2. Server:192.168.10.13
  3. Username:pve-backup@pbs!cluster-token
  4. Password:(Masukkan Secret API Token yang telah dicatat)
  5. Datastore:backup-produksi
  6. Fingerprint:(Tempel Fingerprint dari langkah 1)
  7. Nodes:All (otomatis tersedia di Node 1 dan Node 2)
  1. Klik Add. Storage pbs-dputr kini aktif dan siap digunakan oleh seluruh cluster.

BAB V — Operasional VM, Container & Migrasi

5.1 Pengelolaan Media ISO dan Template

  • Mengunggah ISO: Pilih Node > local > ISO Images > Upload (atau gunakan Download from URL).
  • Mengunduh Template Container (LXC): Pilih Node > local > CT Templates > Templates, pilih distribusi Linux (misal Ubuntu Server atau Debian), lalu klik Download.

5.2 Standar Pembuatan Virtual Machine (VM)

Untuk performa dan stabilitas optimal di lingkungan produksi kantor, terapkan standar berikut saat mengklik Create VM:

  • OS: Pilih ISO yang sesuai; untuk VM Windows, sertakan juga ISO VirtIO Drivers pada CD/DVD tambahan.
  • System: Graphic card: Default / VirtIO-GPU. SCSI Controller: VirtIO SCSI single. Centang Qemu Agent (wajib menginstal layanan qemu-guest-agent di dalam OS tamu agar shutdown rapi dan IP terbaca di dasbor PVE).
  • Disks: Bus/Device gunakan SCSI (dengan opsi Discard dicentang agar ruang disk dapat diklaim kembali, dan SSD emulation jika menggunakan SSD).
  • CPU: Type pilih host (jika kedua node memiliki generasi CPU yang sama) atau x86-64-v2-AES (jika generasi CPU Node 1 dan Node 2 berbeda agar Live Migration berjalan mulus).
  • Network: Model pilih VirtIO (paravirtualized) untuk kecepatan jaringan maksimal.

5.3 Standar Pembuatan Container (LXC)

Gunakan LXC untuk layanan Linux ringan (seperti web server, reverse proxy, DNS internal, atau monitoring):

  • Selalu gunakan mode Unprivileged container (bawaan) demi keamanan isolasi kernel.
  • Aktifkan fitur Nesting (pada tab Options > Features) jika container akan menjalankan layanan modern berbasis systemd atau Docker.

5.4 Migrasi dan Replikasi Antar Node

  • Migrasi Manual: Klik kanan pada VM/CT > Migrate, pilih node tujuan (pve-node1 atau pve-node2), lalu klik Migrate.
  • Replikasi ZFS (Opsional untuk Pemulihan Cepat): Jika kedua node menggunakan penyimpanan ZFS dengan nama Storage ID yang sama, buka VM > Replication > Add. Atur interval replikasi (misal setiap 15 menit). Jika 1 node rusak mendadak, VM dapat segera dinyalakan di node satunya dengan kehilangan data minimal.

BAB VI — Backup, Verifikasi & Restore

6.1 Penjadwalan Backup Otomatis (Backup Jobs)

Konfigurasi dilakukan terpusat di Datacenter > Backup > Add:

  • Node: All
  • Storage:pbs-dputr
  • Schedule: Di luar jam kerja kantor (contoh: 01:00 setiap hari).
  • Selection mode: All (atau pilih VM/CT produksi yang diprioritaskan).
  • Mode: Snapshot (memungkinkan backup berjalan tanpa mematikan VM).
  • Notification: Atur pengiriman laporan email jika terjadi kegagalan backup (On failure only atau Always).

6.2 Kebijakan Retensi (Prune), Verifikasi, dan Garbage Collection di PBS

Seluruh pemeliharaan data backup dilakukan langsung pada Web GUI PBS (Datastore > backup-produksi > Prune & GC dan Verify Jobs):

Prune Job

  • Jadwal Rekomendasi: Harian (03:00)
  • Konfigurasi Standar: Keep Daily: 7, Keep Weekly: 4, Keep Monthly: 6
  • Fungsi: Menghapus salinan backup usang secara otomatis sesuai kebijakan retensi.

Garbage Collection (GC)

  • Jadwal Rekomendasi: Mingguan (Minggu, 04:00)
  • Konfigurasi Standar: Otomatis
  • Fungsi: Membebaskan kapasitas disk fisik dari potongan data (chunks) yang tidak lagi terpakai pasca-Prune.

Verify Job

  • Jadwal Rekomendasi: Mingguan (Sabtu, 02:00)
  • Konfigurasi Standar: Re-verify after 30 days
  • Fungsi: Memeriksa integritas checksum seluruh file backup untuk memastikan data tidak korup dan pasti bisa di-restore.

6.3 Prosedur Pemulihan (Restore)

  1. Pemulihan Penuh (Full VM/CT Restore): Buka Node > Storage pbs-dputr > Backups. Pilih titik waktu backup VM/CT yang diinginkan, klik Restore. Tentukan Storage tujuan dan VM ID (gunakan ID baru jika hanya ingin melakukan pengujian tanpa menimpa VM produksi). Klik Restore.
  2. Pemulihan Berkas Tunggal (File-Level Restore): Pada daftar backup di pbs-dputr, pilih backup yang dimaksud lalu klik File Restore. Telusuri direktori di dalam disk VM/CT dan unduh berkas tertentu tanpa perlu memulihkan keseluruhan server.

BAB VII — Keamanan, Pemeliharaan & Gangguan

7.1 Standar Keamanan Infrastruktur

  • Autentikasi Dua Faktor (2FA/TOTP): Wajib diaktifkan untuk seluruh akun administrator pada PVE (Datacenter > Permissions > Two Factor) dan PBS (Access Control > Two Factor Authentication).
  • Pembatasan Akses Manajemen: Port manajemen PVE (8006), PBS (8007), dan SSH (22) hanya boleh dapat diakses dari jaringan/VLAN khusus tim IT atau melalui VPN kantor.
  • Manajemen Akun Staf IT: Buat akun individual untuk setiap staf IT dengan peran (Role) sesuai tugasnya; hindari berbagi akun root untuk operasional harian agar jejak audit (Syslog/Task History) jelas.
  • Proxmox Firewall: Aktifkan firewall di level Datacenter/VM untuk membatasi port yang terekspos ke jaringan pengguna.

7.2 Jadwal Pemeliharaan Rutin Tim IT

  • Harian: Memeriksa status hasil Backup Job semalam, status kesehatan node (CPU/RAM/Storage), dan log error pada dasbor PVE & PBS.
  • Mingguan: Memeriksa hasil Verify Job dan Garbage Collection di PBS, serta memantau kapasitas disk tersisa (pastikan di bawah 80%).
  • Bulanan: Memeriksa status kesehatan fisik disk (S.M.A.R.T.), melakukan pembaruan keamanan sistem (patching) secara bergantian per node (migrasi VM sebelum reboot), serta meninjau akun pengguna aktif.
  • Triwulanan: Melakukan Simulasi Uji Restore pada minimal 1 VM kritikal ke VM ID pengujian untuk memvalidasi bahwa backup benar-benar berfungsi saat darurat.

7.3 Penanganan Gangguan Umum (Troubleshooting)

Web GUI PVE tidak bisa diakses, tetapi VM masih berjalan

  • Kemungkinan Penyebab: Layanan pveproxy terhenti atau sertifikat SSL bermasalah.
  • Langkah Penanganan: Masuk via SSH ke node terkait, jalankan systemctl restart pveproxy pvedaemon.

Cluster terkunci (no quorum) saat 1 node mati

  • Kemungkinan Penyebab: QDevice belum dikonfigurasi atau layanan corosync-qnetd di PBS mati.
  • Langkah Penanganan: Periksa pvecm status. Pastikan pbs-server menyala dan jalankan systemctl status corosync-qnetd di PBS. (Darurat sementara: jalankan pvecm expected 1 di node hidup hanya untuk penyelamatan).

Backup ke PBS gagal (Timeout / Permission Denied)

  • Kemungkinan Penyebab: Jaringan ke PBS terputus, Datastore penuh, atau izin API Token berubah.
  • Langkah Penanganan: Cek koneksi ping ke IP PBS, cek sisa ruang disk di PBS, dan verifikasi izin role DatastoreBackup pada API Token.

VM tidak merespons saat diklik Shutdown

  • Kemungkinan Penyebab: qemu-guest-agent belum terinstal atau OS di dalam VM mengalami hang.
  • Langkah Penanganan: Gunakan opsi Stop (setara cabut daya) dari Web GUI, atau jalankan qm stop <VMID> melalui shell node.

Kapasitas disk PBS penuh padahal backup lama sudah di-Prune

  • Kemungkinan Penyebab: Garbage Collection (GC) belum berjalan atau masih dalam masa tunggu 24 jam.
  • Langkah Penanganan: Jalankan Garbage Collection secara manual di PBS (Datastore > Prune & GC > Start Garbage Collection).

Lampiran — Checklist Kesiapan Produksi

Sebelum infrastruktur dinyatakan siap beroperasi penuh (Go-Live), tim IT wajib memverifikasi seluruh poin berikut:

  • pve-node1, pve-node2, dan pbs-server terpasang dengan IP Statis dan NTP sinkron.
  • Repositori non-enterprise aktif dan seluruh server sudah diperbarui ke versi stabil terbaru.
  • Cluster PVE 2-node terbentuk dan QDevice pada pbs-server aktif (Total votes: 3 pada pvecm status).
  • Uji coba failover quorum: mematikan 1 node PVE tidak mengunci antarmuka node lainnya.
  • Datastore PBS terhubung ke Cluster PVE menggunakan API Token khusus (bukan root).
  • Backup Job, Prune Job, Verify Job, dan Garbage Collection telah terjadwal otomatis.
  • Uji coba Backup & Restore minimal 1 VM telah berhasil dilakukan.
  • Autentikasi 2FA telah diaktifkan pada akun administrator PVE dan PBS.
  • Seluruh tabel pada bagian Pra-Implementasi (IP aktual, Hostname, VLAN, Storage, dan Kebijakan Backup) telah diisi lengkap dan diarsipkan sebagai dokumen As-Built Tim IT.

Pengenalan & Login

e-monev PUPR adalah aplikasi monitoring dan evaluasi realisasi fisik & keuangan kegiatan di lingkungan Dinas PUPR Provinsi Jambi. Bab ini menjelaskan cara masuk (login), aturan password, dan apa yang terjadi setelah berhasil login.

Alamat akses

Aplikasi diakses lewat browser. Tanyakan alamat (URL) resmi ke admin/operator BPTR jika belum punya.

Cara login

  1. Buka halaman login. Isi Username dan Password.
  2. Pilih Tahun pada dropdown (tahun anggaran yang sedang dikerjakan).
  3. Isi kotak captcha — aplikasi menampilkan soal penjumlahan dua angka (misalnya 4 + 7), ketik hasilnya.
  4. Klik tombol Login.

Jika captcha salah, aplikasi menolak login dan meminta diulang — ini bukan masalah pada username/password.

Password default & wajib ganti password

Akun baru (baik dibuat otomatis lewat menu Pegawai, atau manual lewat menu Users) biasanya memakai password default 123456. Sistem memeriksa kekuatan password setiap kali login:

  • Password dianggap lemah jika: panjang kurang dari 8 karakter, tidak mengandung kombinasi huruf besar + huruf kecil + angka, termasuk daftar password umum (123456, password, admin, emonev, pupr, jambi, dsb), atau memuat username itu sendiri.
  • Jika password lemah, atau akun ditandai wajib ubah password oleh admin (misalnya setelah admin melakukan Reset Password), aplikasi akan mengunci semua halaman lain dan memaksa user langsung ke halaman Profil untuk membuat password baru sebelum bisa memakai menu apa pun.

Syarat password baru yang diterima: minimal 8 karakter, ada huruf besar, huruf kecil, dan angka, bukan password umum, dan tidak memuat username.

Setelah login

User akan diarahkan ke Dashboard. Menu di sisi kiri (sidebar) berbeda-beda untuk setiap orang — hanya menu yang diizinkan untuk level (peran) akun tersebut yang ditampilkan. Lihat Manajemen User, Level & Hak Akses Menu untuk detail pengaturan level.

Secara umum level PPTK/operator bidang hanya melihat & mengurus data milik bidangnya sendiri (kegiatan, subkegiatan, rekap), sedangkan level admin punya akses ke seluruh data dan menu pengaturan.

Mengubah profil & password sendiri

Buka menu Profil (ikon/nama user di pojok, atau otomatis terbuka saat wajib ganti password). Di sini user bisa mengubah foto dan password sendiri. Password baru tetap harus memenuhi syarat kekuatan password di atas.

Logout

Klik menu Logout untuk keluar. Sesi akan dihapus sepenuhnya — login ulang diperlukan untuk kembali memakai aplikasi.

Alih PPTK (Serah Terima Rekap)

Fitur Alih PPTK digunakan saat terjadi pergantian pejabat PPTK, untuk memindahkan kepemilikan data rekap (realisasi) yang sudah diinput dari PPTK lama ke PPTK baru — tanpa harus menginput ulang dari awal.

Langkah 1 — Isi form

  1. Pilih PPTK lama (pemilik data saat ini) dan PPTK baru (penerima).
  2. Mulai periode: pilih Bulan + Tahun data yang mau dipindah. Kosongkan Tahun untuk memindahkan semua periode sekaligus.
  3. Kegiatan yang dipindah: pilihan multi-select, otomatis diisi berdasar kegiatan milik PPTK lama yang dipilih. Biarkan kosong untuk memindahkan semua kegiatan.
  4. Klik lanjut untuk membuka Pratinjau.

Langkah 2 — Pratinjau

Halaman pratinjau menampilkan ringkasan: PPTK lama, PPTK baru, periode, kegiatan yang dipilih, jumlah rekap yang akan dipindah, dan jumlah bentrok (jika ada).

  • Jika ada bentrok — PPTK baru sudah punya rekap pada kombinasi bidang + subkegiatan + bulan + tahun yang sama — proses tidak bisa dilanjutkan. Rapikan/hapus data yang bentrok dulu di salah satu sisi.
  • Jika tidak ada rekap yang cocok dengan filter, proses juga tidak bisa dilanjutkan (tidak ada yang perlu dipindah).
  • Jika aman, centang kotak konfirmasi “Saya mengerti data ini akan dipindah ke PPTK baru” — tombol Pindahkan baru aktif setelah dicentang.

Langkah 3 — Pindahkan

Setelah klik Pindahkan, sistem memvalidasi ulang bentrok (untuk menghindari kondisi balapan jika ada proses lain berjalan bersamaan), lalu memindahkan kepemilikan rekap header & detail ke PPTK baru. Jejak audit “siapa yang terakhir mengubah data” tidak diubah — hanya kepemilikan (PPTK) yang berpindah. Setiap alih PPTK tercatat di log aplikasi.

Setelah selesai, aplikasi menampilkan jumlah rekap yang berhasil dialihkan.

PENTING

Proses ini tidak bisa dibatalkan setelah dijalankan. Pastikan PPTK lama/baru, periode, dan daftar kegiatan sudah benar sebelum menekan Pindahkan.

Tanda Tangan Elektronik (TTE)

Menu TTE (judul halaman: “History Dokumen”) dipakai untuk mengunggah dokumen yang perlu ditandatangani secara elektronik, dan memantau status tanda tangannya. Proses tanda tangan sesungguhnya dilakukan oleh sistem eksternal (API TTE), e-monev hanya mengunggah dan menampilkan status.

Melihat riwayat dokumen

Pilih Bidang, Bulan, Tahun, lalu tabel History TTE akan tampil: judul/jenis dokumen, tautan Lihat untuk membuka dokumen, dan Status:

  • Selesai — semua pihak sudah menandatangani.
  • Menunggu — masih menunggu tanda tangan.
  • Ditolak — ada pihak yang menolak menandatangani.

Di bawah setiap dokumen ditampilkan daftar penandatangan (Nama, Jabatan, urutan/Priority tanda tangan, dan waktu ditugaskan).

Mengunggah dokumen baru

  1. Klik tombol upload/tambah, pilih file Dokumen PDF (wajib format PDF).
  2. Pilih Jenis Dokumen.
  3. Pada bagian Penanda Tangan, klik Tambah Entri untuk setiap pejabat yang harus menandatangani: pilih Pejabat dan Priority (urutan tanda tangan — angka lebih kecil menandatangani lebih dulu).
  4. Submit. Dokumen dikirim ke sistem TTE eksternal untuk diproses.

Menghapus dokumen

Dokumen hanya bisa dihapus selama statusnya belum “Selesai”. Aplikasi meminta konfirmasi sebelum menghapus, dan permintaan hapus dikirim langsung ke sistem TTE eksternal.

Manajemen User, Level & Hak Akses Menu (RBAC)

Bab ini untuk admin yang mengatur siapa saja yang bisa login dan menu apa saja yang boleh mereka lihat/pakai. Ada 4 menu terkait: Users, Level, Master Menu, dan Master Menu Level.

Users (akun login)

  • Tambah/Ubah user: Nama*, Username*, Password* (kosongkan saat mengubah = password tetap, tidak berubah), Foto (opsional), Level* (dropdown). Username harus unik.
  • Reset Password (tombol di daftar): sistem membuat password acak 10 karakter, menandai akun wajib ganti password di login berikutnya, dan menampilkan password sementara itu satu kali saja di layar — catat/sampaikan segera ke pemilik akun, karena tidak akan ditampilkan lagi setelah halaman ditutup.

Level

CRUD sederhana untuk nama peran/level (misalnya Administrator, PPTK, dst). Level inilah yang dipakai di menu Users dan diatur hak akses menunya lewat Master Menu Level di bawah.

Master Menu

Daftar semua menu yang tersedia di aplikasi (template untuk semua level). Field: Nama Menu, Icon, Link (nama controller, atau controller/method), Status (menu induk atau submenu), Parent (menu induk, jika ini submenu). Biasanya hanya perlu diubah saat ada modul baru dikembangkan — jarang diubah oleh admin harian.

Master Menu Level — mengatur hak akses per level

Ini cara admin menentukan menu & hak akses apa saja yang dimiliki setiap level:

  1. Pilih Level dari dropdown, klik Pilih.
  2. Tampil tiga kolom drag-and-drop:
    • Menu Level (kiri) — menu yang sudah aktif untuk level ini.
    • Tong Sampah (tengah) — seret menu ke sini untuk menghapus akses menu tersebut dari level ini.
    • Menu Master (kanan) — semua menu yang tersedia; seret ke kolom “Menu Level” untuk menambahkan akses.
  3. Urutan menu di kolom kiri bisa diatur langsung dengan menyeret (drag) item.
  4. Klik Simpan — aplikasi menyimpan ulang seluruh menu & urutan untuk level ini, dan otomatis memperbarui hak akses modul (controller/method) yang sesuai, sehingga menu yang dihapus di sini juga akan diblokir aksesnya walau diakses lewat URL langsung.

Tombol Tambah Manual tersedia untuk menambah satu entry menu-level tanpa drag-drop, dan setiap baris bisa diubah/dihapus langsung (Nama Menu, Icon, Link, Status, Parent, Urutan, Level, Aktif).

Prosedur: menambah user baru dengan akses yang benar

  1. Pastikan Level yang sesuai sudah ada.
  2. Atur menu & akses modul level itu lewat Master Menu Level (langkah di atas) — lakukan ini sebelum ada user yang memakai level tersebut, supaya saat pertama login menunya sudah benar.
  3. Buat akun baru lewat Users (untuk level non-PPTK), atau otomatis lewat Pegawai jika levelnya PPTK/operator bidang — lihat bab Data Master.
  4. Sampaikan ke user: login pertama memakai password default/sementara, dan sistem akan memaksa ganti password sebelum bisa memakai menu lain (lihat bab Pengenalan & Login).

Setelah hak akses menu suatu level diubah, user dengan level itu yang sedang login harus logout & login ulang agar menunya diperbarui — perubahan akses tidak langsung berlaku pada sesi yang sedang berjalan.

Catatan jaringan

Dari dalam server, mengakses domain publik aplikasi sendiri (misalnya curl https://program.jambiprov.go.id) biasanya timeout (hairpin NAT) — ini normal. Untuk tes cepat dari server, akses langsung lewat localhost:<port> sesuai tabel di atas (mis. curl localhost:8080/api/v1/...).

Reverse proxy / TLS untuk domain publik (program.jambiprov.go.id dan subdomain-subdomainnya) tidak berjalan di server BPTR ini — tidak ada nginx/Traefik lokal yang aktif. Routing domain ke port-port di atas diatur di infrastruktur lain (DNS + reverse proxy terpusat, dikelola Diskominfo/pihak jaringan). Lihat bab berikutnya untuk detail pemetaan domain.

Troubleshooting, Backup & Maintenance Docker

Checklist & perintah yang berguna saat ada laporan aplikasi (e-monev, program.jambiprov, awasi, TTE) tidak bisa diakses atau berjalan lambat.

1. Cek status container

docker ps                 # semua container yang SEDANG berjalan
docker ps -a               # termasuk yang berhenti/crash (kolom STATUS akan
                            # menunjukkan "Exited (kode) ..." kalau bermasalah)

Kalau sebuah container "Exited" padahal seharusnya selalu jalan (restart: unless-stopped di compose-nya), coba jalankan ulang:

docker start <nama-container>
# atau, dari folder compose-nya:
docker compose up -d

2. Baca log

docker logs --tail 200 <nama-container>
docker logs -f <nama-container>      # ikuti log realtime (Ctrl+C untuk berhenti)

Untuk backend Go, ada juga file log lama out_backend-apps.log dan folder outlog/ di backend/ (log dari sebelum aplikasi dipindah ke Docker) — biasanya tidak relevan lagi untuk debugging terkini.

3. Disk penuh / hampir penuh

df -h /                     # cek persentase disk terpakai
docker system df            # rincian pemakaian disk oleh Docker (image, container, volume, build cache)
docker builder prune -af    # aman dijalankan — hanya bersihkan build cache lama

PERINGATAN

Jangan jalankan docker system prune -a --volumes tanpa memeriksa dulu — perintah ini bisa ikut menghapus volume data (termasuk datafile/ milik backend yang berisi file upload) jika volume tersebut sedang tidak dipakai container manapun saat itu. Gunakan docker builder prune (hanya build cache) sebagai pilihan pertama yang aman.

4. Rebuild image gagal

Image emonev_web (PHP/Apache, berbasis Debian) pernah gagal di-rebuild karena perintah apt-get update di dalam Dockerfile-nya exit code 100 (kemungkinan masalah mirror/registry paket Debian yang dipakai image dasar tersebut sudah usang). Untuk container ini, perubahan konfigurasi Apache dilakukan lewat bind mount (mengubah file konfigurasi di host langsung), bukan dengan rebuild image. Jangan asumsikan semua image di server ini bisa di-rebuild dengan mulus — service berbasis Alpine (backend Go, Nuxt) umumnya lebih aman untuk di-rebuild dibanding image Debian/Ubuntu lama.

5. Backup database

Untuk e-monev (database monevdb), sudah ada skrip siap pakai:

/home/bptr/apps/bidang-monev/emonev/backup-mysql.sh
/home/bptr/apps/bidang-monev/emonev/restore-mysql.sh

Hasil backup harian tersimpan di folder .../emonev/backups. Untuk database programdb (dipakai backend program.jambiprov), lakukan dump manual lewat tunnel SSH (lihat bab Arsitektur Server BPTR) atau docker exec ke container database-db-program-1 langsung:

docker exec database-db-program-1 \
  mysqldump -u root -p programdb > programdb-backup-$(date +%Y%m%d).sql

Simpan hasil dump di luar server (unduh ke laptop/penyimpanan terpisah) — jangan hanya disimpan di disk server yang sama (kapasitas terbatas & berisiko hilang bersamaan jika server bermasalah).

6. Alat bantu lain

Portainer agent (portainer_agent, port 9001) berjalan di server untuk mendukung manajemen Docker lewat GUI Portainer, jika dipakai dari instance Portainer pusat (tidak ada Portainer server lokal di host ini, hanya agent-nya).

Kebiasaan shell yang perlu diperhatikan saat menjalankan perintah di atas lewat skrip: Mac memakai sed -i '' (bukan sed -i polos), dan shell zsh tidak melakukan word-splitting pada $variabel tanpa quoting seperti bash — perhatikan ini kalau menyalin perintah dari skrip lama ke terminal interaktif.
