Panduan Proxmox VE & Proxmox Backup Server (Bahasa Indonesia)

BAB V — Operasional VM, Container & Migrasi

5.1 Pengelolaan Media ISO dan Template

  • Mengunggah ISO: Pilih Node > local > ISO Images > Upload (atau gunakan Download from URL).
  • Mengunduh Template Container (LXC): Pilih Node > local > CT Templates > Templates, pilih distribusi Linux (misal Ubuntu Server atau Debian), lalu klik Download.

5.2 Standar Pembuatan Virtual Machine (VM)

Untuk performa dan stabilitas optimal di lingkungan produksi kantor, terapkan standar berikut saat mengklik Create VM:

  • OS: Pilih ISO yang sesuai; untuk VM Windows, sertakan juga ISO VirtIO Drivers pada CD/DVD tambahan.
  • System: Graphic card: Default / VirtIO-GPU. SCSI Controller: VirtIO SCSI single. Centang Qemu Agent (wajib menginstal layanan qemu-guest-agent di dalam OS tamu agar shutdown rapi dan IP terbaca di dasbor PVE).
  • Disks: Bus/Device gunakan SCSI (dengan opsi Discard dicentang agar ruang disk dapat diklaim kembali, dan SSD emulation jika menggunakan SSD).
  • CPU: Type pilih host (jika kedua node memiliki generasi CPU yang sama) atau x86-64-v2-AES (jika generasi CPU Node 1 dan Node 2 berbeda agar Live Migration berjalan mulus).
  • Network: Model pilih VirtIO (paravirtualized) untuk kecepatan jaringan maksimal.

5.3 Standar Pembuatan Container (LXC)

Gunakan LXC untuk layanan Linux ringan (seperti web server, reverse proxy, DNS internal, atau monitoring):

  • Selalu gunakan mode Unprivileged container (bawaan) demi keamanan isolasi kernel.
  • Aktifkan fitur Nesting (pada tab Options > Features) jika container akan menjalankan layanan modern berbasis systemd atau Docker.

5.4 Migrasi dan Replikasi Antar Node

  • Migrasi Manual: Klik kanan pada VM/CT > Migrate, pilih node tujuan (pve-node1 atau pve-node2), lalu klik Migrate.
  • Replikasi ZFS (Opsional untuk Pemulihan Cepat): Jika kedua node menggunakan penyimpanan ZFS dengan nama Storage ID yang sama, buka VM > Replication > Add. Atur interval replikasi (misal setiap 15 menit). Jika 1 node rusak mendadak, VM dapat segera dinyalakan di node satunya dengan kehilangan data minimal.
