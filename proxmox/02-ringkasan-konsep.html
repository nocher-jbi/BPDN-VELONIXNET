Panduan Proxmox VE & Proxmox Backup Server (Bahasa Indonesia)

Ringkasan Konsep & Panduan Cepat

Bagian ini dirancang khusus bagi Tim IT DPUTR untuk memberikan pemahaman menyeluruh mengenai arsitektur, alur kerja harian, batasan operasional, serta checklist serah terima proyek sebelum memasuki bagian teknis detail.

A. Gambaran Besar 3 Server DPUTR (Bahasa Sederhana)

  • Server 1 (pve-node1) & Server 2 (pve-node2) — Proxmox VE: Berfungsi seperti "gedung utama" yang menampung banyak server virtual (VM/Container) di dalamnya (misalnya server website DPUTR, aplikasi e-Office/GIS/SIMBG, database, dll.). Keduanya digabung dalam satu Cluster, sehingga Tim IT cukup membuka satu alamat web untuk mengelola seluruh aplikasi di kedua server. Jika satu server perlu dimatikan untuk perawatan, aplikasi bisa dipindahkan (migrate) ke server satunya.
  • Server 3 (pbs-server) — Proxmox Backup Server & QDevice: Memiliki dua peran krusial: (1) "Brankas Cadangan Otomatis" yang menyimpan salinan data harian semua VM/aplikasi dengan teknologi deduplikasi (hemat kapasitas disk), dan (2) "Wasit / Pemberi Suara ke-3 (Quorum)" agar saat salah satu server utama mati mendadak, server utama yang masih hidup tetap bisa beroperasi normal dan tidak terkunci.

B. Alur Kerja Harian Tim IT DPUTR (Cukup 5–10 Menit/Hari)

  1. Login ke Web GUI Proxmox VE (https://<IP-Node1>:8006) menggunakan akun masing-masing (plus kode 2FA).
  2. Cek panel kiri: pastikan ikon pve-node1, pve-node2, dan storage pbs-dputr semuanya bertanda centang hijau.
  3. Cek menu Tasks di bagian bawah: pastikan tidak ada tugas Backup semalam yang berstatus ERROR.
  4. Cek penggunaan CPU, RAM, dan Disk pada menu Summary tiap node (waspada jika kapasitas disk mendekati 80%).

C. Aturan Emas: Hal yang BOLEH dan DILARANG (Do's & Don'ts) bagi Tim IT DPUTR

Wajib dilakukan

  • Ambil Snapshot sebelum melakukan update besar pada aplikasi/OS di dalam VM.
  • Gunakan akun staf IT masing-masing untuk pekerjaan harian agar riwayat aktivitas tercatat.
  • Pindahkan (Migrate) VM ke node lain sebelum me-reboot salah satu node PVE saat pemeliharaan.
  • Lakukan uji coba Restore ke VM ID baru secara berkala (minimal per triwulan).

Dilarang

  • Mematikan server fisik secara paksa (cabut kabel listrik/tekan tombol power lama) tanpa Shutdown VM terlebih dahulu.
  • Menggunakan atau membagikan kata sandi root ke pihak luar atau menyimpan Secret API Token secara terbuka.
  • Menghapus manual file backup di dalam disk PBS lewat terminal Linux (selalu gunakan fitur Prune & Garbage Collection di Web GUI).
  • Menjalankan update sistem (apt full-upgrade) pada kedua node PVE secara bersamaan di jam kerja.

D. Daftar Serah Terima Proyek (Handover) ke Tim IT DPUTR

  1. Dokumen As-Built: Tabel Pra-Implementasi yang telah diisi lengkap dengan alamat IP aktual, VLAN, dan topologi jaringan DPUTR.
  2. Amplop / Brankas Kredensial Tertutup: Kata sandi root PVE & PBS, akun admin individu Tim IT, serta Secret API Token backup.
  3. Bukti Uji Fungsi (User Acceptance Test / UAT): Tangkapan layar status Cluster Quorum (3 votes), uji live migration VM antar node, serta uji Backup & Restore yang berhasil.
  4. Sesi Pelatihan (Knowledge Transfer): Pelaksanaan simulasi praktik langsung pengelolaan harian bersama Tim IT DPUTR.
