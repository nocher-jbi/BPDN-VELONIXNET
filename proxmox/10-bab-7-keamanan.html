Panduan Proxmox VE & Proxmox Backup Server (Bahasa Indonesia)

BAB VII — Keamanan, Pemeliharaan & Gangguan

7.1 Standar Keamanan Infrastruktur

  • Autentikasi Dua Faktor (2FA/TOTP): Wajib diaktifkan untuk seluruh akun administrator pada PVE (Datacenter > Permissions > Two Factor) dan PBS (Access Control > Two Factor Authentication).
  • Pembatasan Akses Manajemen: Port manajemen PVE (8006), PBS (8007), dan SSH (22) hanya boleh dapat diakses dari jaringan/VLAN khusus tim IT atau melalui VPN kantor.
  • Manajemen Akun Staf IT: Buat akun individual untuk setiap staf IT dengan peran (Role) sesuai tugasnya; hindari berbagi akun root untuk operasional harian agar jejak audit (Syslog/Task History) jelas.
  • Proxmox Firewall: Aktifkan firewall di level Datacenter/VM untuk membatasi port yang terekspos ke jaringan pengguna.

7.2 Jadwal Pemeliharaan Rutin Tim IT

PeriodeAktivitas Pemeliharaan
HarianMemeriksa status hasil Backup Job semalam, status kesehatan node (CPU/RAM/Storage), dan log error pada dasbor PVE & PBS.
MingguanMemeriksa hasil Verify Job dan Garbage Collection di PBS, serta memantau kapasitas disk tersisa (pastikan di bawah 80%).
BulananMemeriksa status kesehatan fisik disk (S.M.A.R.T.), melakukan pembaruan keamanan sistem (patching) secara bergantian per node (migrasi VM sebelum reboot), serta meninjau akun pengguna aktif.
TriwulananMelakukan Simulasi Uji Restore pada minimal 1 VM kritikal ke VM ID pengujian untuk memvalidasi bahwa backup benar-benar berfungsi saat darurat.

7.3 Penanganan Gangguan Umum (Troubleshooting)

Gejala GangguanKemungkinan PenyebabLangkah Penanganan
Web GUI PVE tidak bisa diakses, tetapi VM masih berjalanLayanan pveproxy terhenti atau sertifikat SSL bermasalah.Masuk via SSH ke node terkait, jalankan systemctl restart pveproxy pvedaemon.
Cluster terkunci (no quorum) saat 1 node matiQDevice belum dikonfigurasi atau layanan corosync-qnetd di PBS mati.Periksa pvecm status. Pastikan pbs-server menyala dan jalankan systemctl status corosync-qnetd di PBS. (Darurat sementara: jalankan pvecm expected 1 di node hidup hanya untuk penyelamatan).
Backup ke PBS gagal (Timeout / Permission Denied)Jaringan ke PBS terputus, Datastore penuh, atau izin API Token berubah.Cek koneksi ping ke IP PBS, cek sisa ruang disk di PBS, dan verifikasi izin role DatastoreBackup pada API Token.
VM tidak merespons saat diklik Shutdownqemu-guest-agent belum terinstal atau OS di dalam VM mengalami hang.Gunakan opsi Stop (setara cabut daya) dari Web GUI, atau jalankan qm stop <VMID> melalui shell node.
Kapasitas disk PBS penuh padahal backup lama sudah di-PruneGarbage Collection (GC) belum berjalan atau masih dalam masa tunggu 24 jam.Jalankan Garbage Collection secara manual di PBS (Datastore > Prune & GC > Start Garbage Collection).
