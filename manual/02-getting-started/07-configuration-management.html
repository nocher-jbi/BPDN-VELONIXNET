Configuration Management

Manage the RouterOS configuration: undo and redo changes, use safe mode to avoid locking yourself out, export the configuration as a script and import it on another router, run scripts automatically after upload, and...

Configuration Management

RouterOS records every configuration change, so you can undo it, and offers safe mode, which undoes your changes when the connection to the router is lost. The configuration can be exported as a script, imported on the same or another router, and reset to the defaults. For a binary copy of the whole configuration, see Backup.

Undo and redo changes

Every configuration change, made from the CLI, WinBox, WebFig or the API, is recorded in /system/history. The /undo and /redo commands, or the Undo and Redo buttons in WinBox, take back the last change or apply it again. Each further /undo takes back the change before it. The history keeps the last 100 changes and is cleared when the router reboots.

Add a firewall rule and look at the history:

/ip/firewall/filter/add chain=forward action=drop
/system/history/print

Flags: U - UNDOABLE
Columns: ACTION, BY, POLICY, TIME
  ACTION              BY     POLICY  TIME
U filter rule added   admin  write   2026-11-23 09:39:35
U user admin changed  admin  write   2026-11-23 09:39:34
                             policy

Undo the change. The rule is removed, and the history marks the action as redoable (R):

/undo
/system/history/print

Flags: U - UNDOABLE, R - REDOABLE
Columns: ACTION, BY, POLICY, TIME
  ACTION              BY     POLICY  TIME
R filter rule added   admin  write   2026-11-23 09:39:35
U user admin changed  admin  write   2026-11-23 09:39:34
                             policy

/redo adds the rule again. The detailed history shows the commands that undo and redo each action, also for changes made over the API or in the GUI:

/redo
/system/history/print detail proplist=action,redo,undo

Flags: U - UNDOABLE
U action="filter rule added"
  redo=/ip firewall filter add action=drop chain=forward
  undo=/ip firewall filter remove *1

U action="user admin changed"

Work safely with safe mode

A configuration change can cut your own connection to the router, for example a firewall rule or a wrong address. Safe mode protects against this: if the session that holds safe mode ends without releasing it, the router undoes every change made while safe mode was on, including changes made from other sessions.

  • In the CLI, press Control+X (or F4). The router answers Taking Safe Mode session... Success! and the prompt shows <SAFE>, for example [admin@MikroTik] <SAFE>.
  • In WinBox, select Safe Mode in the toolbar.

[gambar: WinBox window with the Safe Mode button in the toolbar and an open terminal]

Changes made in safe mode are listed with the F (floating-undo) flag in /system/history/print. How the session ends decides what happens to them:

Action Changes
Control+X again (Releasing Safe Mode... Success!) Kept. Safe mode ends.
Control+D Undone. The session ends.
/quit, then y at You are in Safe Mode. Quitting will unroll changes. Quit? [y/N]: Undone. The session ends.
The client closes the connection, for example the terminal window is closed Undone.
The connection is cut without being closed, for example by a firewall rule Undone when the router detects that the session is gone, which can take about a quarter of an hour.

If your connection drops and the old session still holds safe mode when you log in again, press Control+X and answer u to the question that follows to undo its changes at once.

Pressing Control+X twice keeps the changes made so far and starts safe mode again with an empty list. Change the configuration in small steps: safe mode remembers at most 100 changes. With more, the session leaves safe mode and no changes are undone.

Only one session can hold safe mode. When another session presses Control+X, the router asks:

Safe Mode is taken by current user in another session.
Unroll, release or abort [u/r]?
  • u undoes the changes of the other session and gives safe mode to this session. The other session sees Safe Mode unrolled by another user.
  • r keeps the changes of the other session and gives safe mode to this session. The other session sees Safe Mode released by another user.
  • Control+C leaves safe mode with the other session.

Export the configuration

The export command prints the configuration as RouterOS commands, which can be imported on the same or another router. Run it from the root menu for the whole configuration, or from a menu for that menu and its sub-menus. Export is a CLI command.

By default, the export contains only settings that differ from the defaults. Arguments:

  • file writes the export to a file (.rsc) instead of the terminal.
  • verbose also exports default values.
  • terse writes every command on one line with its full menu path.
  • show-sensitive includes passwords, keys and other secrets, which are left out by default (see List of menus with sensitive parameters).
  • path exports only the listed menus. A menu with ! in front is left out.
  • where exports only the items that match a condition.
  • compact is the default and gives the same output as a plain export.

Arguments can be combined, for example /export path=/ip/firewall,!/ip/firewall/nat file=fw.

Export the addresses to the file address.rsc:

/ip/address/add address=192.0.2.1/24 interface=ether1
/ip/address/export file=address
/file/print where name=address.rsc

Columns: NAME, TYPE, SIZE, LAST-MODIFIED
# NAME         TYPE    SIZE  LAST-MODIFIED
0 address.rsc  script   146  2026-11-23 09:39:50

Export the whole firewall configuration except NAT:

/ip/firewall/address-list/add list=mylist address=198.51.100.1
/ip/firewall/address-list/add list=other address=198.51.100.2
/ip/firewall/nat/add chain=srcnat action=masquerade out-interface=ether1
/export path=/ip/firewall,!/ip/firewall/nat

# 2026-11-23 09:40:04 by RouterOS 7.25.1
# system id = aX+jcgZWr+J
#
/ip firewall address-list
add address=198.51.100.1 list=mylist
add address=198.51.100.2 list=other
/ip firewall filter
add action=drop chain=forward

Export one address list:

/ip/firewall/address-list/export where list=mylist

# 2026-11-23 09:40:07 by RouterOS 7.25.1
# system id = aX+jcgZWr+J
#
/ip firewall address-list
add address=198.51.100.1 disabled=no dynamic=no list=mylist

If a menu does not answer the export command in time, the export prints #error exporting "/<menu>" (timeout) for it and continues with the next menu.

WARNING

The export does not contain:

  • User accounts and their passwords. User groups and SSH public keys (/user/ssh-keys) are exported, so create the users on the new router before you import.
  • Certificates. Export and import them separately, see Certificates.
  • The databases of The Dude and User Manager.

Import the file on the same RouterOS version where possible: a command or parameter that does not exist in the other version stops the import.

Import a configuration

/import runs a script file (.rsc) line by line. The file can contain any console command, including scripts.

/ip/address/remove [find address="192.0.2.1/24"]
/import address.rsc

Script file loaded and executed successfully

The import adds to the existing configuration and removes nothing. Firewall rules from the file are added after the rules that are already there, also when they are the same, and an entry that already exists, such as an address or an address-list entry, makes the import fail. On a router with the default configuration, remove or adapt the default items that the file also contains before you import.

The import stops at the first line that fails and reports it, for example:

Script Error: failure: already have such address (/ip/address/add; line 5) (:import; line 1)

line 5 is the line in the file. The lines before it stay applied. To replace the whole configuration of a router with a file, export it with show-sensitive so that it contains passwords and keys, reset the router and run the file instead of the default configuration (add keep-users=yes, as the file contains no users):

/system/reset-configuration no-defaults=yes keep-users=yes \
    run-after-reset=config.rsc

A failing line in such a file is logged as error while running run-after-reset script: followed by the error.

Check a file before you import it

verbose=yes prints each line with its number before it runs, so you can see where an import stops. With dry-run, the router only checks the syntax and changes nothing: it does not find entries that already exist. from-line starts the import at a line of the file, for example to continue after you fixed the line that failed. dry-run and from-line work only together with verbose=yes.

/import address.rsc verbose=yes dry-run

#line 1
# 2026-11-23 09:39:50 by RouterOS 7.25.1
#line 2
# system id = aX+jcgZWr+J
#line 3
#
#line 4
/ip address
#line 5
add address=192.0.2.1/24 interface=ether1 network=192.0.2.0
No syntax errors found in the import file

Import automatically after upload

A file whose name ends in .auto.rsc runs as soon as it is uploaded over FTP or SFTP. The router writes the result to a file with the same name and the .auto.log extension, for example Script file loaded and executed successfully, or the script error. Files created on the router or downloaded with /tool/fetch do not run automatically.

Troubleshoot an import

Before you import an export from another router, check the file for:

  • Interface names: renamed interfaces can clash with the default names on the new router. In this export, ether6 is renamed to ether2 while ether2 still exists, so the second line fails:

routeros /interface/ethernet set [ find default-name=ether5 ] auto-negotiation=no name=ether1-gateway set [ find default-name=ether6 ] name=ether2 set [ find default-name=ether7 ] name=ether3 set [ find default-name=ether8 ] name=ether4 set [ find default-name=ether1 ] name=ether5 set [ find default-name=ether2 ] name=ether6 set [ find default-name=ether3 ] name=ether7 set [ find default-name=ether4 ] name=ether8

  • Interfaces that do not exist on the new router: a command for a missing interface fails.
  • Default entries written with add instead of set by an older version: change them to set.

Then check the syntax with verbose=yes dry-run, run the import with verbose=yes to find the line that fails, fix the file, and continue with from-line from that line.

Startup delay

A script that runs at boot, for example a default configuration script or an import right after a reset, can start before all interfaces exist. Wait for them before the commands that use them. This script waits until there are at least 10 interfaces (count them on your router with /interface/print count-only) or 30 seconds, and logs a warning if they did not appear:

{
:local i 0
#Number of interfaces. It is necessary to reconfigure this number for each device (/interface/print count-only)
:local x 10
#Max time to wait
:local t 30
while ($i < $t && [:len [/interface/find]] < $x) do={
:put $i
:set $i ($i + 1)
:delay 1
}
if ($i = $t) do={
:log warning message="Could not load all physical interfaces"
} else={
#Rest of your script
}
}

Reset the configuration

/system/reset-configuration removes the configuration, reboots the router and applies the default configuration (see Default configurations). In an interactive session it asks Dangerous! Reset anyway? [y/N]: first. To reset with the button on the router, see RouterOS configuration reset.

  • Users are removed, and admin gets its default password back: none, or the password printed on the device sticker. Without a password, the router asks you to set one at the first login.
  • Before the reset, the router saves the old configuration to auto-before-reset.backup, so a reset made by mistake can be undone by restoring it. Files on the router are kept.
  • At the first interactive login after a reset, the router offers to show the software license.
  • If a custom default configuration script is installed, for example with Netinstall or TR-069, the reset runs that script instead of MikroTik's default configuration.

Arguments change what the reset does, for example:

  • keep-users=yes keeps users and their passwords.
  • no-defaults=yes does not apply the default configuration.
  • skip-backup=yes saves no backup.
  • run-after-reset runs a script file after the reset instead of the default configuration. A script that runs longer than two minutes is stopped, and the log shows error while running run-after-reset script: runtime limit exceeded (in rare cases std failure: timeout).
  • caps-mode=yes runs the CAPs mode script after the reset.
  • shutdown=yes powers the router off instead of rebooting. It starts with the reset configuration when it is powered on.

Reset without the default configuration and without a backup:

/system/reset-configuration no-defaults=yes skip-backup=yes

The same in WinBox:

[gambar: WinBox Reset Configuration dialog with No Default Configuration and Do Not Backup selected]

For all arguments, see /system/reset-configuration.

Related topics

Backup

Save the RouterOS configuration to a binary file, encrypt it, and restore it later on the same device.

Backup

The system backup saves the whole router configuration to a single binary file. Save a backup before a risky change, for example before an upgrade or a batch of firewall edits, and restore it when the configuration breaks. For a change that can cut your connection, or one you plan to undo, safe mode and undo/redo are lighter alternatives.

A backup restores reliably only on the device it was made on. The backup contains the device's MAC addresses, so restoring it on another device can leave the interfaces misconfigured. To copy a configuration between devices, export and import it instead.

WARNING

A backup contains sensitive parameters, such as passwords and keys; see the list of menus with sensitive parameters. A backup saved without a password stores the configuration in readable form. Encrypt the backup and keep it in a safe place.

Save a backup

Save the configuration to a backup file:

[admin@MikroTik] > /system/backup/save name=config-before-update password=StrongPass
Configuration backup saved

The command creates the file config-before-update.backup in the /file menu:

[admin@MikroTik] > /file/print where name~"config-before-update"
Columns: NAME, TYPE, SIZE, LAST-MODIFIED
# NAME                         TYPE    SIZE     LAST-MODIFIED      
0 config-before-update.backup  backup  35.8KiB  2026-10-16 07:15:38

Store a copy off the router, for example by downloading the file with WinBox or FTP. To create backups regularly, add a scheduler entry that runs the save command; see the scheduler example.

Provide a password to encrypt the backup file. Without a password, the backup is stored unencrypted. encryption selects the algorithm: aes-sha256 by default, or rc4 for compatibility with older RouterOS versions. dont-encrypt=yes stores the backup unencrypted even when a password is given.

Restore a backup

Give the backup name as you used with save, without the .backup extension. Load the backup file and confirm the reboot:

[admin@MikroTik] > /system/backup/load name=config-before-update password=StrongPass
Restore and reboot? [y/N]: y
Restoring system configuration
System configuration restored, rebooting now

The router reboots with the restored configuration. Answer n to cancel the restore. When password is omitted, RouterOS asks for it; for an unencrypted backup, any password works.

NOTE

Restore the backup on the same RouterOS version the backup was made on. To load a backup made on RouterOS v6, add force-v6-to-v7-configuration-upgrade=yes.

What the backup does not contain

The system backup does not include the databases of The Dude or User Manager. Both store their data separately on the device, so use their own backup mechanisms to save these databases.

Cloud backup

Store an encrypted copy of the backup on the MikroTik cloud server and download it later to the same or a replacement device. See Cloud backup.

Troubleshoot

  • The restore fails with failure: bad password. The password does not match the one used with save; a wrong password is reported during the restore, after the confirmation.
  • A script that runs load without the password argument fails with missing value(s) of argument(s) password. Pass the password as an argument; the interactive prompt is not available in scripts.

Default Configuration Passwords

Find the default login credentials for MikroTik RouterOS devices fresh from the factory or after a full reset.

MikroTik devices ship from the factory with a default configuration that includes a preset password. The same password is re-applied whenever you perform a standard system reset. Knowing how to locate this password is essential for initial device access.

Watch our official explainer

Default passwords: WHY?! — a short overview of why MikroTik devices now ship with unique factory passwords.

Earlier MikroTik models typically used the username admin with no password — type admin for the login and press Enter when prompted. Later models are manufactured with a unique default password per device.

Custom-branded units

Custom-branded or OEM units may have a different default password. If you cannot locate a standard sticker, the device can still be reset with the Netinstall utility.

Where to Find the Password

The default password is printed in several physical locations:

  • On the device itself, on the serial number sticker
  • On the device packaging, also on the serial number sticker
  • On the printed Quick Guide sheet included inside the product box

Some MikroTik indoor wireless devices (such as the hAP ac³ and hAP ax³) have a dedicated product information compartment — a small panel on the underside of the device that houses the sticker with default credentials. Look for a compartment near the Ethernet ports or under an RF connector cover. Open the panel to reveal the serial number and default password printed on the sticker inside.

WARNING

Always check for these stickers before contacting support. There is no public lookup for the default password — the only digital source is the password database kept by the distributor that supplied the device (see below).

If You Cannot Find the Password

If the stickers are missing or illegible, contact the MikroTik distributor that supplied the device. Provide the device serial number and the name of the seller or shop where you purchased the unit. Distributors maintain a password database and can retrieve the default password from the serial number.

TIP

Watch our video guide: Secret CSV password file for seamless configuration — learn how to use a CSV password file for automated device setup.

If you cannot reach the distributor or the password is not retrievable, you can still regain access by reinstalling RouterOS with Netinstall or performing a full configuration reset.

CAP

This configuration type is used when a device needs to operate as a wireless client device controlled by CAPsMAN.

When the CAP default configuration is loaded, ether1 is the management port with a DHCP client configured. All other Ethernet interfaces are bridged, and wlan1 is managed by CAPsMAN.

To load the CAP configuration, see RouterOS configuration reset.

RouterOS configuration reset

This page provides comprehensive instructions for resetting MikroTik RouterOS configurations, covering both physical button methods and GUI/CLI commands. It details LED indicators for each reset action, backup loader...

RouterOS configuration reset

How to Reset Configuration

To reset RouterOS to its factory defaults (including removing the current password), follow these steps:

  1. Disconnect the device from power.
  2. Press and hold the reset button.
  3. While holding the button, reconnect power to the device.
  4. Watch the LEDs. One of the LEDs (typically the USR/User LED) will begin flashing.
  5. Release the reset button when the LED starts flashing.

[gambar: Reset button]

The device will reboot with the default configuration.

Reset From RouterOS

If you still have access to the device, you can restore the default configuration directly from RouterOS:

  • Run /system/reset-configuration in the terminal.
  • Or open System → Reset Configuration in WinBox or WebFig.

The command resets users and the admin password, saves a backup first, and has options to keep users, skip the default configuration or run your own script. See Reset the configuration.

Using the Reset Button

MikroTik devices include a reset button that can perform several functions depending on how long it is held during startup.

TIP

Watch the official MikroTips series: reset sequence.

Load the Backup RouterBOOT Loader

Press and hold the reset button before applying power, then release it after approximately 3 seconds. This loads the backup RouterBOOT loader.

This can be useful if the device is unable to boot because of a failed RouterBOOT upgrade. Once booted with the backup loader, you can either force the backup loader in RouterBOARD settings or reinstall RouterBOOT from an .fwf file.

Reset the RouterOS Configuration

Press and hold the reset button until the LED starts flashing, then release it. The device will reset its RouterOS configuration to the factory defaults.

Enable CAPs Mode

Continue holding the button for approximately 5 additional seconds after the LED begins flashing. When the LED becomes solid, release the button to enable CAPs mode.

CAPs mode can also be enabled from the command line: /system/reset-configuration caps-mode=yes

Start Netinstall Mode

Press and hold the reset button while powering on the device. Continue holding the button until the LED sequence completes (typically blinking → solid → off), then release it.

The device will enter Netinstall mode and start searching for a Netinstall server on the network.

TIP

Watch the official MikroTips series: Netinstall.

For detailed Netinstall instructions, see the Netinstall documentation.

Reset Jumper Method

Older RouterBOARD models are also fitted with a reset jumper hole. Some devices might need an opening of the enclosure. RB750/RB951/RB751 have the jumper hole under one of the rubber feet of the enclosure.

Short the reset jumper using a metal screwdriver and boot the board until the configuration is cleared:

WPS

Some devices have a WPS button, or a reset button with WPS functionality that can be used to simplify wireless client connections without manually entering a password. Some models also support WPS synchronization between devices. For model-specific information about WPS and reset button functionality, refer to the User Manual for your device.
