Installation and Upgrade

This section covers installation and upgrade tasks. Use it for Netinstall and related procedures when installing or recovering RouterOS.

Upgrade

MikroTik devices are preinstalled with RouterOS, so installation is usually not needed, except in the case of installing RouterOS on a bare metal x86 PC or a virtual machine with CHR images. The upgrade procedure on already installed devices is straightforward.

Version numbering

RouterOS versions are numbered sequentially, where a period is used to separate sequences; it does not represent a decimal point, and the sequences do not have positional significance. An identifier of 2.5, for instance, is not "two and a half" or "halfway to version three"; it is the fifth second-level revision of the second first-level revision. Therefore v5.2 is older than v5.18, which is newer.

RouterOS versions are released in several "release chains": Long term, Stable, Testing, and Development. When upgrading RouterOS, you can choose a release chain from which to install the new packages:

  • Long term: Released rarely, and includes only the most critical fixes. Upgrades within one number branch do not contain new features. When a Stable release has been out for a while and seems to be stable enough, it gets promoted into the long-term branch, replacing an older release, which is then moved to the archive. This consecutively adds new features.
  • Stable: Released every few months, including all tested new features and fixes.
  • Testing: Released every few weeks, undergoes only basic internal testing, and should not be used in production.
  • Development: Released when necessary. Includes raw changes and is available for software enthusiasts for testing new features.

Standard upgrade

The package upgrade feature connects from the router to the MikroTik download server over HTTPS and checks if a newer RouterOS version is available in the selected release channel. This menu can also be used for downgrading by changing the channel to one that offers an older, but more stable release. The feature connects from the router, not your computer, so the router itself needs HTTPS connectivity to the MikroTik server.

After selecting the Check for Updates button in QuickSet or in the System → Packages menu, the Check for Updates window will open with the current changelog or the latest changelog (if a newer version exists). If a newer version is available, the Download and Download&Install buttons will appear. Selecting Download downloads the newest version (a manual device reboot is required), while selecting Download&Install starts the download and automatically reboots the device after a successful download.

From the command line, check for a new version, then install it:

/system/package/update/check-for-updates
/system/package/update/install

check-for-updates shows the installed version and the latest version in the channel, with the status New version is available. install works like Download&Install: it downloads the new packages and reboots the router to install them. To download now and reboot later, use /system/package/update/download: the status changes to Downloaded, please reboot router to upgrade it, and the router installs the packages at the next reboot. If the router is up to date, the status is System is already up to date. If it cannot reach the server, the status starts with ERROR:, for example ERROR: IPv4: could not resolve dns name (timeout) or ERROR: IPv4: server is not responding; see Troubleshooting below.

Make a backup before an upgrade.

The versions offered depend on the selected release channel. The channel offers only its latest version; to install a specific version, upload its package files. A channel can also offer an older version than the installed one, for example long-term on a router that runs the stable release; installing it downgrades the router. On RouterOS 6.49, the upgrade channel offers RouterOS v7 and installs it in one step.

If extra packages are installed, the router downloads their new versions too.

Check for Updates settings

The connection to the MikroTik download server can be fine-tuned in the System → Packages → Check for Updates window, or with the /system/package/update/set command:

  • Channel: Upgrade channel to use when checking for new versions. The release chains are described in the Version numbering section.
  • Mode: Protocol for connecting to the MikroTik download server. Use http only if your network blocks HTTPS. HTTPS is recommended.
  • IP version: IP version preference for connecting to the MikroTik download server.
  • Check certificate: Whether and how to validate the server SSL certificate. Always use yes to ensure a secure connection. yes-without-crl can be used to skip CRL validation.
/system/package/update/set channel=stable mode=https \
    ip-version=auto check-certificate=yes

WARNING

On RouterBOARD devices, it is strongly recommended to upgrade the bootloader after RouterOS update. To upgrade the bootloader, execute the /system/routerboard/upgrade command in CLI, followed by a reboot. Alternatively, navigate to the GUI System → RouterBOARD menu and select the "Upgrade" button, then reboot the device.

You can automate the upgrade process by running a script in the system scheduler. This script asks the MikroTik upgrade server for a new version in the selected channel and, if the status is New version is available, installs it. Save it as a script and add a scheduler entry that runs it every week; the script waits 10 seconds for the server's answer:

/system/script/add name=auto-upgrade source={
/system/package/update/check-for-updates
:delay 10s
:local status [/system/package/update/get status]
:if ($status = "New version is available") do={
    /system/package/update/install
}
}
/system/scheduler/add name=auto-upgrade interval=7d \
    start-time=03:00:00 on-event=auto-upgrade

The script installs whatever the channel offers. With the long-term channel on a router that runs a newer stable release, it installs the older long-term release.

Troubleshooting

If the router does not offer a version you expect, check the channel first: a new version is in the testing or development channel before it reaches stable. If the status shows an ERROR:, verify that the router can resolve and reach the upgrade server, upgrade.mikrotik.com.

:put [:resolve upgrade.mikrotik.com]

The result should be 159.148.147.251. If the address does not resolve or resolves to a different IP, review your DNS settings. See the DNS article for more information.

Once DNS resolution is confirmed, verify that the device can reach the server:

/tool/ping address=159.148.147.251

If the ping fails, check your firewall rules, routing, or upstream connectivity. A failed ping alone does not prove that the server is unreachable: continue with the next check.

Once the IP connectivity is confirmed working, verify that TCP port 443 is reachable. The router prints Connected to 159.148.147.251 if it is; press Control+C to close the connection:

/system/telnet 159.148.147.251 port=443

Manual upgrade

You can upgrade RouterOS in the following ways:

  • WinBox – drag and drop files to the Files menu.
  • WebFig - upload files from the Files menu.
  • FTP or SFTP - upload files to the root directory.

WARNING

On RouterBOARD devices, it is strongly recommended to upgrade the bootloader after upgrading RouterOS. To upgrade the bootloader, execute the /system/routerboard/upgrade command in CLI, followed by a reboot. Alternatively, navigate to the GUI System → RouterBOARD menu and select the "Upgrade" button, then reboot the device.

Warning: RouterOS cannot be upgraded through a serial cable. Only RouterBOOT is upgradeable with this method.

Manual upgrade process

  • Open the MikroTik download page and choose the architecture of the router (System → Resources, or architecture-name in /system/resource/print).
  • Download the routeros package and the extra packages that are installed on the router. File names are listed on the Packages page.
  • Upload packages to the device with one of the methods listed above.

If you need to skip some specific package upgrade or a package file is no longer available, then use /system/package/update/install ignore-missing to skip missing packages.

Using WinBox

Choose your system type and download the upgrade package. Connect to your router with WinBox. Select the downloaded file with your mouse and drag it to the Files menu. If some files are already present, make sure to put the package in the root menu, not inside the hotspot folder! The upload will start.

After it finishes, reboot the device. The new version number will be seen in the WinBox title and in the Packages menu.

Packages

RouterOS features come in packages, files with the .npk extension. Most features are in the routeros package. Some features come as extra packages, for example Containers, The Dude or the drivers for Wi-Fi hardware. Packages are made only by MikroTik. Download them from the MikroTik download page or install them directly from the router.

Which packages a router needs

A router needs the routeros package and the driver packages for its hardware, for example switch-marvell on CRS8xx switches or extra-nic on arm64 boards that are not made by MikroTik. On devices with Wi-Fi, the Wi-Fi drivers are in a separate package:

  • 802.11ax and 802.11be (Wi-Fi 6 and 7) devices need a driver package such as wifi-qcom, wifi-qcom-be or wifi-mediatek (the package wifi-qcom was earlier called wifiwave2).
  • Earlier Wi-Fi devices (up to 802.11ac) and 60 GHz devices use the wireless package or, on some 802.11ac devices, wifi-qcom-ac.

See the Wireless manual for which package your device uses. Other packages are optional: install them only for the feature they add.

Install a package from the router

The router can download and install extra packages from the MikroTik download server. The router itself needs access to the server (HTTPS by default, see the mode setting in Upgrade).

  1. Check for updates. The packages that exist for the router's architecture and version appear in the list with the X (disabled) and A (available) flags.
  2. Enable the package.
  3. Apply the changes. The router downloads the package and reboots to install it.

Packages are made for an architecture. /system/resource/print shows the router's architecture-name, for example arm64 on a hAP ax²; the router lists only packages for its own architecture.

Install a package from a file

  1. Download the package for your router's architecture (/system/resource/print shows architecture-name) and RouterOS version from the MikroTik download page. The extra packages are in the "Extra packages" archive: extract the archive and upload only the .npk files you need.
  2. Upload the .npk file to the router, for example with WinBox (drag it to Files), SFTP or FTP.
  3. Reboot the router. It installs the package during the boot.

Use extra packages of the same version as the installed RouterOS. Upload the file to the root of the file system, not into a folder.

A package file whose name ends in .auto.npk is installed as soon as it is uploaded over FTP or SFTP: the router reboots by itself and installs it. Rename the file before the upload, for example to iot-7.25.1.auto.npk.

Check the installation

After the reboot, the log shows what was installed, and why a package was not. The routeros package appears as system:

 2026-11-23 09:56:17 system,info installed system-7.25.1
 2026-11-23 09:56:17 system,info installed iot-7.25.1

 2026-11-23 09:57:41 system,warning omitting package system-7.24.7: newer package system-7.25.1 is already installed

Uploaded package files are removed after the reboot.

Disable, uninstall and downgrade

A disabled package stays on the router but does not run; enable turns it on again. An uninstalled package is removed. The changes take effect after apply-changes; a scheduled disable also takes effect at the next reboot:

/system/package/print

/system/package/unschedule iot cancels the scheduled change.

/system/package/uninstall iot
/system/package/apply-changes

To install an older RouterOS version, upload the older routeros package and the matching versions of all installed extra packages (for example wifi-qcom), then run /system/package/downgrade. If an installed extra package is missing, the router reboots, logs missing package, and keeps the installed version. On a router whose device-mode limits the installable versions, a version outside the allowed list cannot be installed, see Device-mode. The router asks Router will be rebooted. Continue? [y/N]: and installs the older packages during the reboot. A plain reboot does not install older packages: the log shows omitting package ... newer package ... is already installed. To downgrade from the router without files, see Upgrade.

RouterBOOT

RouterBOOT manages RouterOS startup on MikroTik hardware, featuring a main and backup loader with force-backup-booter option. The reset button has multiple functions including configuration reset, CAPs mode...

RouterBOOT

RouterBOOT is responsible for starting RouterOS in MikroTik hardware devices, such as Access Points, routers, and other models. Since many new hardware families have been made by MikroTik, here and elsewhere, when the term RouterBOARD is used, it applies to all the other hardware families that run RouterOS as well.

Main and Backup loaders

By default, the main (regular) loader is used, but RouterBOARD devices also have a secondary (backup) bootloader, which can be used in case the main doesn't work. It is possible to call the backup loader with a configuration setting in RouterOS:

/system/routerboard/settings/set force-backup-booter=yes

It is also possible to use the backup booter by turning on the device, with the RESET button pushed. It is only possible to upgrade the main RouterBOOT, so in case of failure, you can use the backup booter to start the device and downgrade the main loader. For upgrade instructions, follow the separate instructions in RouterBOARD#UpgradingRouterBOOT

RouterBOARD reset button

RouterBOOT reset button has three functions:

  • Hold this button during boot time until the LED light starts flashing, and release the button to reset the RouterOS configuration (total 5 seconds).
  • Keep holding for 5 more seconds until the LED turns solid, then release now to turn on CAPs mode (total 10 seconds).
  • Or Keep holding the button for 5 more seconds until the LED turns off, then release it to make the RouterBOARD look for Netinstall servers.

WARNING

If you hold the button before applying power, backup RouterBOOT will be used in addition to all the above actions. To do the above actions without loading the backup loader, push the button right after applying power to the device.

Simple Upgrade

RouterBOOT can be upgraded from RouterOS by:

  • Run command /system/routerboard/upgrade.
  • Reboot your router to apply the upgrade (/system/reboot).
[admin@admin] > /system/routerboard/upgrade 
Do you really want to upgrade firmware? [y/n]

WARNING

Every ROS version has a new RouterBoot version included in it. Once you perform a ROS upgrade, we always recommend upgrading RouterBoot also.

Checking RouterBOOT version

This command shows the current RouterBOOT version of your device and the available upgrade which is included in the routeros-x.yy.npk package, or if you uploaded a *.FWF file corresponding to the device model:

[admin@admin] >  /system/routerboard/print 
                ;;; Firmware upgraded successfully, please reboot for changes 
                    to take effect!
       routerboard: yes
        board-name: hAP ac
             model: RouterBOARD 962UiGS-5HacT2HnT
     serial-number: 6737057562DD
     firmware-type: qca9550L
  factory-firmware: 3.29
  current-firmware: 6.49.5
  upgrade-firmware: 7.4beta5

In this case, you see, there is a newer version of the Bootloader firmware available already inside your current RouterOS version and it has been updated and requires a reboot.

WARNING

A downgrade is also possible by uploading an *.FWF file with an older version, which may be required for troubleshooting purposes when contacting MikroTik support.
