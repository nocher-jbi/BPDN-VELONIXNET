RAID

RAID technology in RouterOS enables data storage across multiple drives with improved performance and protection, supporting RAID levels 0,1,4,5,6, linear, and nested configurations. Includes configuration examples...

RAID

INFO

This feature requires the rose-storage package; see Storage.

RAID (Redundant Array of Independent Disks) stores data on multiple drives and combines them into one logical disk, for better performance, better protection against disk failures, or both.

RouterOS supports software RAID levels 0, 1, 4, 5, 6, linear, and nested RAID (a RAID array made of other RAID arrays). When a member of a redundant array fails, the array keeps working in a degraded state. With a hot spare, the rebuild starts on the spare at once; otherwise, replace the failed disk.

Create a RAID 6 array

The same procedure applies to the other RAID types. This example creates a RAID 6 array of six disks, nvme1 to nvme6. All data on the disks is lost.

Create the RAID block device:

/disk/add type=raid slot=raid6 raid-type=6 raid-device-count=6

Add the disks to the array. raid-role is the position of each disk in the array, starting from 0:

/disk/set nvme1 raid-master=raid6 raid-role=0
/disk/set nvme2 raid-master=raid6 raid-role=1
/disk/set nvme3 raid-master=raid6 raid-role=2
/disk/set nvme4 raid-master=raid6 raid-role=3
/disk/set nvme5 raid-master=raid6 raid-role=4
/disk/set nvme6 raid-master=raid6 raid-role=5

Format the RAID block device:

/disk/format raid6 file-system=ext4

Check the array with /disk/print detail where slot=raid6:

7 BM type=raid slot="raid6" slot-default="" parent="" fs-label="raid6-fs"
     fs-uuid="3ffda391-66ff-40f1-8837-e716898d8a45" fs=ext4
     model="RAID6 2-parity-disks" size=8 585 740 288 free=8 346 079 232
     total-inodes=524 288 free-inodes=524 277 use=0% mount-point="raid6"
     mount-filesystem=yes mount-read-only=no compress=no sector-size=512
     raid-type=6 raid-device-count=6 raid-max-component-size=none
     raid-chunk-size=1M raid-master=none state="active"
     raid-uuid="9aea18da-07061d4e-fbd0175e-7ab46c87" nvme-tcp-export=no
     iscsi-export=no nfs-sharing=no smb-sharing=no media-sharing=no
     media-interface=none swap=no

state shows the condition of the array, for example active or clean, degraded by 1 when a member is missing, and the progress of a rebuild (sync:recover, recovery = 76.6%).

WARNING

Avoid using multiple partitions on a single physical disk in multiple RAID arrays. Using the same physical disk in multiple RAID arrays can result in low performance.

Replace a failed disk

A failed member has the f (raid-member-failed) flag in /disk/print. To replace a member that has not failed, for example a disk that reports errors, mark it as failed first:

/disk/set nvme3 raid-member-failed=yes

Remove the failed disk from the array, and add the new disk with the same raid-role:

/disk/set nvme3 raid-master=none
/disk/set nvme7 raid-master=raid6 raid-role=2

The rebuild starts at once; state shows its progress and returns to clean when it is done. A role that a failed disk still holds cannot be given to another disk: failure: already have device with raid-role=2 in this raid.

Monitor the array

Monitor the array for failures. This script checks every 30 seconds for members with the raid-member-failed flag, writes ERROR: RAID has failed! to the log and sends an e-mail:

/system/scheduler
add interval=30s name=MRaidHealthCheckCall on-event=MraidHealthCheck policy=ftp,read,write,policy,test,sniff start-time=startup
/system/script
add dont-require-permissions=no name=MraidHealthCheck owner=admin policy=ftp,read,write,policy,test,sniff source=":global CheckRAID;\
    \n:local sysadmin; \
    \n\
    \n:set  \$sysadmin \"<servername@domain.tld>\";\
    \n\
    \n:local temp [/disk/print count-only where raid-member-failed];\
    \n:if ( \$temp > 0 ) do={\
    \n   :if ( \$CheckRAID < 1 ) do={\
    \n      /log/info message=\"ERROR: RAID has failed!\";\
    \n      /tool/e-mail/send to= \$sysadmin subject=([/system/identity/get name].\" RAID failed\") body=(\"Go check it! Value: \".\$temp);\
    \n      :set \$CheckRAID 7;\
    \n      :delay 5s;\
    \n    }\
    \n   }       \
    \n   :if ( \$CheckRAID > 0 ) do={\
    \n      :set \$CheckRAID ( \$CheckRAID -1 );\
    \n   }\
    \n"

You will also need to configure your RouterOS device's e-mail server settings:

/tool/e-mail
set from=<raidcheck@domain.tld> port=587 server=smtp.domain.com tls=starttls

WARNING

Make sure you configure your e-mail server's settings under /tool/e-mail and change the e-mail address in the script above with the values that match your e-mail server's settings.

RAID types

RAID 0

All data is written evenly over all disks in this RAID, this configuration does not provide any fault tolerance but provides best performance.

[gambar: RAID 0 diagram: data striped across disks]

RAID 1

The same data is written to all drives (data is mirrored), this configuration provides best fault tolerance, but performance-wise write speeds will be equal to the slowest disk used in the array.

[gambar: RAID 1 diagram: data mirrored between disks]

RAID 4

Block-level data is striped across data disks, with parity bits stored on a dedicated disk. Performance will be limited to the parity writing speed.

[gambar: RAID 4 diagram: block-level striping with dedicated parity disk]

RAID 5

Block-level data is striped evenly over the available disks. It can be recovered from 1 disk failure.

[gambar: RAID 5 diagram: block-level striping with distributed parity]

RAID 6

Block-level data is striped evenly over the available disks. It can be recovered from 2 disk failures.

[gambar: RAID 6 diagram: block-level striping with double distributed parity]

RAID linear

Data is appended over multiple disks combining them into a single large disk. Provides no redundancy and is limited to the single disk read/write speed.

[gambar: RAID linear diagram: data appended across disks]

Nested RAID

Combination of multiple RAID configurations into another RAID. For example RAID 10 (RAID 1+0) combines disk mirroring (RAID 1) and disk striping (RAID 0)

[gambar: Nested RAID diagram: RAID 1+0 combining mirroring and striping]

Create a nested RAID 10 array

RAID 10 is a RAID 0 array made of RAID 1 arrays. This example uses four disks, nvme1 to nvme4, in two mirrors.

Create the RAID 0 array, and the two RAID 1 arrays as its members:

/disk/add type=raid slot=raid10 raid-type=0 raid-device-count=2
/disk/add type=raid slot=mirror1 raid-type=1 raid-device-count=2 \
    raid-master=raid10 raid-role=0
/disk/add type=raid slot=mirror2 raid-type=1 raid-device-count=2 \
    raid-master=raid10 raid-role=1

Add the disks to the mirrors:

/disk/set nvme1 raid-master=mirror1 raid-role=0
/disk/set nvme2 raid-master=mirror1 raid-role=1
/disk/set nvme3 raid-master=mirror2 raid-role=0
/disk/set nvme4 raid-master=mirror2 raid-role=1

Format the RAID 10 array:

/disk/format raid10 file-system=ext4

The array has the size of two disks (/disk/print detail where slot=raid10):

6 BM type=raid slot="raid10" slot-default="" parent="" fs-label="raid10-fs"
     fs-uuid="9efc2ffb-bd5e-4020-bf9d-0fdd23cf1147" fs=ext4
     model="RAID0 striped" size=4 290 772 992 free=4 139 458 560
     total-inodes=262 144 free-inodes=262 133 use=0% mount-point="raid10"
     mount-filesystem=yes mount-read-only=no compress=no sector-size=512
     raid-type=0 raid-device-count=2 raid-max-component-size=none
     raid-chunk-size=1M raid-master=none state="clean"
     raid-uuid="04cbbdec-baab5216-8ad762b2-2b74d214" nvme-tcp-export=no
     iscsi-export=no nfs-sharing=no smb-sharing=no media-sharing=no
     media-interface=none swap=no

For more disks, add more mirrors to the RAID 0 array. Other nested RAID types are built in the same way.

Set a hot spare disk

This page explains how to configure a hot spare disk for a RAID array in RouterOS, enabling automatic rebuild on disk failure by assigning a spare disk to the RAID setup.

Set a hot spare disk

A hot spare is a disk that waits in the array for a member to fail. When a member fails, the rebuild starts on the spare at once. The spare is a member of the array with raid-role=spare.

Add the RAID array with the desired number of disks:

/disk/add raid-device-count=4 raid-type=5 type=raid slot=raid5

Add the disks and the spare to the array. In this example, nvme5 is the spare:

/disk/set raid-master=raid5 raid-role=0 nvme1
/disk/set raid-master=raid5 raid-role=1 nvme2
/disk/set raid-master=raid5 raid-role=2 nvme3
/disk/set raid-master=raid5 raid-role=3 nvme4

/disk/set raid-master=raid5 raid-role=spare nvme5

When a member fails, the spare takes its raid-role, and the failed disk gets the f (raid-member-failed) flag and the role spare. During the rebuild, state of the array shows its progress, for example degraded by 1, clean, sync:recover, recovery = 97.4%, and clean when it is done. To put a new disk in place of the failed one, see Replace a failed disk.

Moving your RAID array to a different device

It is possible to move your RAID array from one device to another.

In this example we are using a RAID 5 array on an RDS2216 consisting of 4 members.

First, on the "new" device, create a RAID array with the same number of members and assign the member slots:

# New device
/disk/add raid-device-count=4 raid-type=5 type=raid slot=raid5

# New device - assign roles to the (currently empty) slots
/disk/set raid-master=raid5 raid-role=0 nvme1
/disk/set raid-master=raid5 raid-role=1 nvme2
/disk/set raid-master=raid5 raid-role=2 nvme3
/disk/set raid-master=raid5 raid-role=3 nvme4

On the "old" device, eject the disks you want to switch to the "new" device:

# Old device
/disk/eject nvme1
/disk/eject nvme2
/disk/eject nvme3
/disk/eject nvme4

Remove the disks from the "old" device and insert them into the assigned slots in the "new" one. RouterOS will automatically detect the RAID superblock and mount the array without any additional input.

Ramdisk

A ramdisk is a block device in RAM. Format it before use, or use it as a RAID member. It needs the rose-storage package and is empty after every reboot.

Ramdisk

A ramdisk is a block device in RAM. Like a disk, it needs a file system before it can hold files, and it can be a member of a RAID or be used anywhere else a device is needed. A tmpfs is a folder in RAM instead: it holds files without formatting, but it is not a device and cannot be formatted or be a RAID member.

INFO

Ramdisks need the rose-storage package (see Storage). To install the package when it is available on the router, enable it and apply the change. Applying the change reboots the router:

/system/package/enable rose-storage
/system/package/apply-changes

For more about packages, see Packages.

Create and format a ramdisk

Add a ramdisk of 500 MB:

/disk/add type=ramdisk ramdisk-size=500M

The first ramdisk gets the slot name ramdisk1, the next ones ramdisk2, ramdisk3 and so on. The size is rounded up to a multiple of 16 KiB. The router does not reserve the RAM when the ramdisk is added.

Format the ramdisk before you use it:

/disk/format ramdisk1 file-system=ext4

The formatted ramdisk is mounted at its slot name, so files go to paths such as ramdisk1/capture.pcap.

WARNING

The contents of a ramdisk are lost when the router reboots or loses power. After a reboot, the ramdisk is there again but empty and without a file system, so format it again before you use it.

Use ramdisks in a RAID

Ramdisks can be RAID members, for example to try a RAID configuration on a router without disks. To build a RAID 1 from two ramdisks, add the RAID and assign both ramdisks to it:

/disk/add type=raid raid-type=1 raid-device-count=2 slot=raid1
/disk/set ramdisk1 raid-master=raid1 raid-role=0
/disk/set ramdisk2 raid-master=raid1 raid-role=1

/disk/print then shows raid1 with the model RAID1 mirrored and the state clean, and both ramdisks as RAID members with the member state in_sync. After a reboot, the router assembles the RAID again from the empty ramdisks. For more about RAID, see RAID.

Remove a ramdisk

Remove a RAID that uses ramdisks first, then the ramdisks:

/disk/remove raid1
/disk/remove ramdisk1
/disk/remove ramdisk2

For all parameters, see the /disk CLI reference.

Rsync

INFO

This feature requires the rose-storage package; see Storage.

/file/sync keeps a file or folder in sync with another RouterOS device. When a file changes, only the changes are transferred.

A sync entry on one router (the host) connects to the other router (the remote device) and logs in with user and password, like WinBox: it needs the remote device's WinBox service port, TCP 8291, and a user on the remote device. The rsync daemon in /file/rsync-daemon is not needed for a sync between RouterOS devices. When a password is set, RouterOS also creates dynamic IPsec entries and encrypts the transfer.

WARNING

If the remote device's TCP port 8291 is not reachable, the status in /file/sync/print stays at making control connection to <ip>. With a password, the IPsec connection also needs UDP port 500 and IPsec ESP (protocol 50) between the devices.

Configuration example

Upload the file BtrfsDisk/rs2.txt to the BackupBtrfsDisk disk of the remote device 10.99.0.2, logging in as syncuser:

/file/sync/add local-path=BtrfsDisk/rs2.txt mode=upload \
    remote-address=10.99.0.2 remote-path=BackupBtrfsDisk/ \
    user=syncuser password=<password>

When the file is transferred, the entry has the status in sync on the host device (/file/sync/print):

# REMOTE-ADDRESS  MODE    LOCAL-PATH         REMOTE-PATH       STATUS 
2 10.99.0.2       upload  BtrfsDisk/rs2.txt  BackupBtrfsDisk/  in sync

The remote device shows a dynamic entry in the opposite direction:

#   REMOTE-ADDRESS  MODE      LOCAL-PATH                REMOTE-PATH       
1 D 10.99.0.1       download  BackupBtrfsDisk/          BtrfsDisk/rs2.txt

IPsec dynamic entries

With a password, both devices get a dynamic IPsec peer and policy named file-sync-<address of the other device> (/ip/ipsec/policy/print where dynamic on the host):

Flags: D - DYNAMIC, A - ACTIVE
Columns: PEER, TUNNEL, SRC-ADDRESS, DST-ADDRESS, PROTOCOL, ACTION, LEVEL
#   PEER                 TU  SRC-ADDRESS   DST-ADDRESS   PRO  ACTION   LEVEL  
;;; file-sync-10.99.0.2
0 D file-sync-10.99.0.2  no  10.99.0.1/32  10.99.0.2/32  tcp  encrypt  require

Self-encrypting drives (SED)

INFO

This feature requires the Storage package.

For using SED, drives have to be Opal-compliant. Please consult the drive manufacturer's documentation to find out if a particular drive supports this feature before buying drives.

SED is not supported on setups using USB bridges; the disk must be attached directly (SATA or NVMe).

RouterOS marks supported drives with the o (TCG-OPAL supported, encryption not active) or O (TCG-OPAL supported and encryption active) flags:

Columns: SLOT, MODEL, SERIAL, INTERFACE, SIZE, FREE, FS, RAID-MASTER
#     SLOT   MODEL                  SERIAL           INTERFACE                   SIZE             FREE  FS    RAID
0 BMo sata1  Samsung SSD 860 2.5in  S3Z9NX0N414510L  SATA 6.0 Gbps  1 000 204 886 016  983 351 111 680  ext4  none
1 BMo sata2  Samsung SSD 860        S5GENG0N307602J  SATA 6.0 Gbps  1 000 204 886 016  983 351 128 064  ext4  none
2 BMO sata3  Samsung SSD 860        S5GENG0N307604H  SATA 6.0 Gbps  1 000 204 886 016  983 351 128 064  ext4  none
3 BMO sata4  Samsung SSD 860 2.5in  S4CSNX0N838150B  SATA 6.0 Gbps  1 000 204 886 016  983 351 128 064  ext4  none

To enable self-encryption on a drive, set self-encryption-password:

/disk/set sata1 self-encryption-password=securepassword

Once set, the drive locks itself on power loss and requires the password every time it's connected; RouterOS supplies it automatically (the flag changes to O).

To disable self-encryption, unset the password:

/disk/unset sata1 self-encryption-password

or:

/disk/set sata1 !self-encryption-password

SMB

RouterOS includes a built-in SMB server for file sharing over SMB/CIFS protocols, supporting SMB2.1, 3.0, and 3.1.1. Users can configure server settings, shares, and user permissions through /ip/smb, /ip/smb/shares,...

SMB

RouterOS includes an SMB server for sharing folders of the router with network clients, and an SMB client that mounts remote SMB shares as disks. Both are part of the base system; the Storage package is not needed.

SMB server

Sub-menu: /ip/smb Packages required: system

SMB server provides file sharing access to configured folders of the router, allowing network clients to browse, read, write, and manage files stored on the router's storage media over the SMB/CIFS protocol. This enables the router to function as a simple network-attached storage (NAS) device for local network sharing of files, backups data, or router configuration backups files.

WARNING

RouterOS only supports SMB2.1, SMB3.0, and SMB3.1.1. SMB1 is not supported due to security vulnerabilities.

SMB is not supported on SMIPS devices.

The server starts on its own once the first share is added (enabled=auto is the default; see /ip/smb for the settings), it can also be limited to specific interfaces and renamed.

Shares

Sub-menu: /ip/smb/shares

/ip/smb/shares configures the share names and directories accessible over SMB. If the directory provided in the configuration does not exist, it will be created automatically. Access can be limited per share with valid-users / invalid-users, enforced encryption with require-encryption (recommended for macOS clients), and read-only access with read-only.

Users

Sub-menu: /ip/smb/users

/ip/smb/users sets up the users that can access the router's SMB shares. Each user has a name, a password, and a read-only restriction (default: yes) that applies across all shares. A default guest user is created automatically; it has read-only access to the shares without a password. Disable it unless anyone in the network may read the shares.

Example

To make a folder of the router available through SMB:

  1. Create a user:

routeros /ip/smb/users/add read-only=no name=mtuser password=mtpasswd

  1. Create the folder and the share. When the folder exists, clients can open the share:

routeros /file/add name=backup type=directory /ip/smb/shares/add directory=backup name=backup

  1. Disable the guest user, so that only mtuser can open the share:

routeros /ip/smb/users/disable guest

The server starts when the first share is added (enabled=auto); /ip/smb/set enabled=yes starts it in any case. Check the settings:

/ip/smb/print
     enabled: auto       
      status: enabled    
      domain: MSHOME     
     comment: MikrotikSMB
  interfaces: all

/ip/smb/users/print
Flags: X - DISABLED; * - DEFAULT; r - READ-ONLY
Columns: NAME
#     NAME  
0 X*r guest 
1     mtuser

The default share pub is disabled:

/ip/smb/shares/print
Flags: X - DISABLED; * - DEFAULT
Columns: NAME, DIRECTORY, REQUIRE-ENCRYPTION
#    NAME    DIRECTORY  REQUIRE-ENCRYPTION
0 X* pub     /pub       no                
1    backup  /backup    no

A Linux client connects with, for example, smbclient //192.168.88.1/backup -U mtuser. SMB1 clients cannot connect.

SMB client

Sub-menu: /disk

The SMB client mounts a remote SMB share as a disk on the router. It supports the SMB2.1, SMB3.0, and SMB3.1.1 dialects; SMB1 is not supported.

Configuration example

/disk/add type=smb smb-address=10.0.2.2 smb-share=share1 \
    smb-user=smbu smb-password=<password>

The share is mounted as smb-<address>-<share>, here smb-10-0-2-2-share1, and its files appear in /file like the files of any other disk.

SSHFS

SSHFS allows mounting a folder from a remote SSH server as a local disk in RouterOS, using the sshfs type of /disk. The mount is configured with the remote address, user credentials, and path, and appears in /file...

SSHFS

SSHFS (SSH Filesystem) mounts a remote folder over SSH as a local disk on the router. It is configured with /disk/add type=sshfs, and the remote directory then appears under /file like other mounted storage, so files can be browsed and copied locally. SSHFS is part of the base system; the Storage package is not needed. The remote side can be any SSH server with SFTP, including another RouterOS device.

RouterOS tracks each sshfs item under /disk with the slot automatically derived from the address and path, for example sshfs-192-168-88-1--srv-files for address 192.168.88.1 and path /srv/files, and it exposes the mount as sshfs://<user>@<address>:<port>//<path>.

Configuration example

/disk/add type=sshfs sshfs-address=192.168.88.1 sshfs-port=22 \
    sshfs-user=user sshfs-password=superSecret sshfs-path=/srv/files

After the item is added, the router connects in the background. While it connects, state in /disk/print detail is mounting; if the connection fails, state shows the error, for example state="connectHandler: Host is unreachable". A mounted item has the M flag:

Flags: M - MOUNTED
Columns: SLOT, FS, MOUNT-POINT
 #   SLOT                              FS     MOUNT-POINT                     
11 M sshfs-10-99-0-2--BackupBtrfsDisk  sshfs  sshfs-10-99-0-2--BackupBtrfsDisk
12   sshfs-10-99-0-9--srv-files        sshfs

Once mounted, the remote folder shows up as a directory in /file under the mount point (/file/print).

The entry can be adjusted with /disk/set, for example to change the port:

/disk/set [find where type=sshfs] sshfs-port=2222

Remove the mount with /disk/remove <slot>.

Authentication uses the user/password of the remote SSH server (sshfs-user / sshfs-password). sshfs-local-user is read-only on the router and indicates the local RouterOS user the mount runs under (for example admin).

Tmpfs

A tmpfs is a folder in RAM for temporary files such as packet captures and downloads. Its size is capped, and its contents are lost on reboot.

Tmpfs

A tmpfs is a folder in RAM. RouterOS shows it as a disk, for example tmp1, and files go into it like into any other disk. Use it for files that are needed only for a while and should not wear out or fill the flash: packet captures, files that a script downloads and imports, and other temporary files. Tmpfs is part of the base RouterOS package and works on every device that has the /disk menu, which SMIPS devices do not have.

WARNING

The contents of a tmpfs are lost when the router reboots or loses power. Copy the files you want to keep to the flash, a USB disk or a computer.

Create a RAM folder

Add a folder that can hold up to 100 MB:

/disk/add type=tmpfs tmpfs-max-size=100M

[admin@MikroTik] > /disk/print
Flags: M - MOUNTED
Columns: SLOT, MOUNT-POINT, MODEL, INTERFACE, SIZE, FREE, USE, FS
#   SLOT  MOUNT-POINT  MODEL  INTERFACE         SIZE         FREE  USE  FS
0 M tmp1  tmp1         tmpfs  ram        100 003 840  100 003 840  0%   tmpfs

The first folder gets the slot name tmp1, the next one tmp2. The slot name is the start of the file path, for example tmp1/capture.pcap, and other commands refer to the folder by it.

Sizes use decimal units: 100M is 100 000 000 bytes. The size in /disk/print is rounded up to whole 4 KiB memory pages, so the folder shows 100 003 840. tmpfs-max-size is the most the folder can grow to; RAM is used only by the files stored in it.

Check what the folder shares

On routers whose default configuration turns on automatic disk sharing, a new tmpfs is shared as soon as it is created. Check the settings of your router first:

/disk/settings/print

The default configuration of the hAP ax², for example, sets auto-smb-sharing=yes, auto-media-sharing=yes and auto-media-interface=bridge. The folder then gets an SMB share for the read-only guest user, who needs no password, and a DLNA media server on bridge. When /ip/smb is set to enabled=auto, the share also starts the SMB server. The SMB server listens on all interfaces (interfaces=all), and only the firewall limits who reaches it; the default firewall allows the LAN. Anyone who reaches the SMB server can read the files in the folder as guest, packet captures included, unless the guest user is disabled in /ip/smb/users.

When automatic sharing is on, create the folder with sharing turned off. The setting stays after a reboot:

/disk/add type=tmpfs tmpfs-max-size=100M smb-sharing=no media-sharing=no

The flags s (SMB sharing) and m (media sharing) in /disk/print show which folders are shared. Here tmp1 was created with the automatic sharing and tmp2 with the previous command:

[admin@MikroTik] > /disk/print
Flags: M - MOUNTED; s - SMB-SHARING; m - MEDIA-SHARING
Columns: SLOT, MOUNT-POINT, MODEL, INTERFACE, SIZE, FREE, USE, FS
#     SLOT  MOUNT-POINT  MODEL  INTERFACE         SIZE         FREE  USE  FS
0 Msm tmp1  tmp1         tmpfs  ram        100 003 840  100 003 840  0%   tmpfs
1 M   tmp2  tmp2         tmpfs  ram        100 003 840  100 003 840  0%   tmpfs

The SMB share of a folder is a dynamic entry in /ip/smb/shares:

[admin@MikroTik] > /ip/smb/shares/print
Flags: D - DYNAMIC; X - DISABLED; * - DEFAULT
Columns: NAME, DIRECTORY, REQUIRE-ENCRYPTION, VALID-USERS
#     NAME  DIRECTORY  REQUIRE-ENCRYPTION  VALID-USERS
0  X* pub   /pub       no
1 D   tmp1  /tmp1      no                  guest

Stop sharing a folder that is already shared:

/disk/set tmp1 smb-sharing=no media-sharing=no

Stop sharing new disks and folders automatically:

/disk/settings/set auto-smb-sharing=no auto-media-sharing=no

To share files on purpose, with your own users, see SMB and DLNA media server.

Keep packet captures in RAM

A packet capture can grow fast. Write it to the tmpfs instead of the flash, and keep file-limit (in KiB) below the folder size: 50000KiB is about 51 MB, which fits in the 100 MB folder.

/tool/sniffer/set file-name=tmp1/capture.pcap file-limit=50000KiB \
    filter-interface=ether1
/tool/sniffer/start

Stop the capture when it has the packets you need:

/tool/sniffer/stop

Download tmp1/capture.pcap before the router reboots, with the Files menu in WinBox or WebFig (see Manage files in WinBox) or with scp from your computer:

scp admin@192.168.88.1:tmp1/capture.pcap .

For filters and live streaming, see Packet sniffer.

Check how full the folder is

The FREE and USE columns of /disk/print show how much of the folder is used. They update a few seconds after a write. List the files in the folder:

[admin@MikroTik] > /file/print where name~"^tmp1"
Columns: NAME, TYPE, SIZE, LAST-MODIFIED
# NAME               TYPE        SIZE     LAST-MODIFIED
0 tmp1               disk                 2026-10-01 08:35:03
1 tmp1/capture.pcap  .pcap file  19.8KiB  2026-10-01 08:35:08

When the folder is full, writes to it fail. For example, /tool/fetch stops with failure: cannot download: file too large, no space left on disk and does not keep the partial file.

Change the size or delete the folder

A new size applies at once, also to a mounted folder:

/disk/set tmp1 tmpfs-max-size=200M

Delete the folder together with all files in it. RouterOS does not ask for confirmation:

/disk/remove tmp1

Technical details

Size limit

Without tmpfs-max-size (it reads 0), the folder can grow to about half of the router's RAM, for example 464 MB on a router with 1 GB of RAM. RouterOS adds up the maximum sizes of all tmpfs folders, counting a folder without tmpfs-max-size as half of the RAM, and refuses a new size when the total is more than the router can provide:

failure: too much memory requested for tmpfs/ramdisk

Memory use

An empty tmpfs reserves no RAM. The files in it use RAM and lower free-memory in /system/resource. Files that fill the RAM can make the router run out of memory, so keep tmpfs-max-size well below the free memory.

After a reboot

The /disk entry and its settings stay in the configuration. After a reboot, RouterOS mounts the folder again under the same slot name, empty. Automatic SMB and DLNA shares of the folder come back with it, and a folder set to smb-sharing=no and media-sharing=no stays unshared.

Not a block device

A tmpfs is a file system, not a block device, so it cannot be formatted:

failure: cannot format nfs/smb/tmpfs/sshfs file systems

For RAM that works as a block device, for example as a RAID member, use a Ramdisk.

For the parameters, see the /disk CLI reference.
