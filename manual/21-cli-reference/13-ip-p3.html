ip/hotspot/profile

Type: Directory

The /ip/hotspot/profile menu lists the server profiles. A profile holds the settings that HotSpot servers share: the address and DNS name of the login page, the login methods, the HTML directory, and the RADIUS settings. See the HotSpot guide.

Flag / Name / Description

  • ***** default — The default profile. It cannot be removed.

Argument / Type / Description

  • name string — Name of the profile.
  • hotspot-address ipAddr — IP address of the HotSpot service, which is the address of the login page.
  • dns-name string — DNS name of the login page. The router resolves this name to the HotSpot address for the clients. Empty - the login page uses the IP address.
  • html-directory file — Directory with the HotSpot pages. Default: hotspot, or flash/hotspot on a router that has a flash folder in its file list.
  • html-directory-override file — Directory with your own HotSpot pages. If it is set and exists, it is used instead of html-directory. On a router that has a flash folder in its file list, keep the directory in flash and set the path with the folder, for example flash/hs-custom: files outside flash are lost on reboot.
  • install-hotspot-queue bool — Whether to create a dynamic simple queue for the HotSpot interface of each server with this profile. The queue uses the hotspot-default queue type. Default: no.
  • rate-limit string — Rate limit in the form rx-rate[/tx-rate] [rx-burst-rate[/tx-burst-rate] [rx-burst-threshold[/tx-burst-threshold] [rx-burst-time[/tx-burst-time] [priority] [rx-rate-min[/tx-rate-min]]]]]. rx is what the router receives from the user (upload), tx is what it sends to the user (download). For example, 512k/2M limits upload to 512 kbps and download to 2 Mbps. The limit applies to all users of the servers with this profile together.
  • http-proxy composite { address: ipAddr , port: num [0 .. 65535] } — Address and port of a proxy server for the HTTP requests of the clients. 0.0.0.0:0 - no proxy.
  • smtp-server ipAddr — Server to which the SMTP connections (TCP port 25) of the clients are redirected. 0.0.0.0 - no redirect.
  • login-by ubit (mac, cookie, http-chap, https, http-pap, trial, mac-cookie) — Login methods that the servers with this profile accept. Default: cookie,http-chap. - http-chap - user name and password on the login page; the password is sent as an MD5 hash with a challenge - http-pap - user name and password on the login page; the password is sent as plain text - https - user name and password on the login page over HTTPS; needs ssl-certificate - cookie - automatic login with a browser cookie from an earlier login - mac - automatic login when a user with the MAC address of the device as its name exists - mac-cookie - automatic login by the MAC address of a device that has logged in before - trial - login without an account for a limited time
  • mac-auth-mode enum (mac-as-username | mac-as-username-and-password) { mac-as-username:0, mac-as-username-and-password:1 } — What is sent for a mac login: mac-as-username - the MAC address as the user name, with mac-auth-password as the password; mac-as-username-and-password - the MAC address as both.
  • mac-auth-password string — Password for mac logins. Use it when the RADIUS server rejects users with an empty password.
  • http-cookie-lifetime time — Time for which the cookie of the cookie login method is valid. Default: 3d.
  • ssl-certificate enum (none) { none:0 } — Certificate for the https login method. It has to be valid for the dns-name of the profile. Default: none.
  • split-user-domain bool — Whether to split a user name given as user@domain or domain\user into the user name and the domain. Default: no.
  • trial-uptime-limit time — Time for which a trial user has access. Default: 30m.
  • trial-uptime-reset time — Time after which a device can use the trial again. Default: 1d.
  • trial-user-profile enum () — User profile from /ip/hotspot/user/profile for trial users. Default: default.
  • use-radius bool — Whether to authenticate users that are not in /ip/hotspot/user on a RADIUS server. The server is set in /radius with service=hotspot. Default: no.
  • radius-accounting bool — Whether to send accounting records for the sessions to the RADIUS server. Default: yes.
  • radius-interim-update alt { symbolic-names: enum (received) { received:0 } , time-interval: time } — Interval of the accounting updates. received - the interval that the RADIUS server sends is used.
  • nas-port-type enum (ethernet | cable | wireless-802.11) { ethernet:15, cable:17, wireless-802.11:19 } — Value of the NAS-Port-Type attribute sent to the RADIUS server. Default: wireless-802.11.
  • radius-default-domain string — Domain for the RADIUS requests of this profile. Set the same value as domain of a server in /radius to use a separate RADIUS server for the profile.
  • radius-location-id string — Value of the WISPr-Location-ID attribute sent to the RADIUS server.
  • radius-location-name string — Value of the WISPr-Location-Name attribute sent to the RADIUS server.
  • radius-mac-format enum (XX:XX:XX:XX:XX:XX | XXXX:XXXX:XXXX | XXXXXX:XXXXXX | XX-XX-XX-XX-XX-XX | XXXXXX-XXXXXX | XXXXXXXXXXXX | XX XX XX XX XX XX) { XX:XX:XX:XX:XX:XX:0, XXXX:XXXX:XXXX:1, XXXXXX:XXXXXX:2, XX-XX-XX-XX-XX-XX:3, XXXXXX-XXXXXX:4, XXXXXXXXXXXX:5, XX XX XX XX XX XX:6 } — Format of the MAC address of the client in the RADIUS requests. Default: XX:XX:XX:XX:XX:XX.

ip/hotspot/user

Type: Directory

The /ip/hotspot/user menu lists the users that the HotSpot authenticates from the router itself, with their limits and counters. See the HotSpot guide.

Flag / Name / Description

  • ***** default — The default entry, default-trial. It holds the counters and limits of trial users.
  • X disabled — The user is disabled.
  • D dynamic — The user is dynamic, for example a trial user.

Argument / Type / Description

  • server enum (all) { all:0 } — HotSpot server on which the user can log in. Default: all.
  • name string — User name. For the mac login method, the MAC address of the device.
  • password string — Password of the user.
  • otp-secret string — Secret for the time-based one-time passwords of the user.
  • address ipAddr — IP address that the device of the user gets through the HotSpot address translation. The user can still log in from any address.
  • mac-address macAddr — MAC address from which the user can log in. 00:00:00:00:00:00 - any MAC address.
  • profile enum — User profile from /ip/hotspot/user/profile. Default: default.
  • routes string — Routes that are added while the user is logged in, in the form dst-address gateway metric, for example 192.168.1.0/24 192.168.0.1 1.
  • email string — E-mail address of the user. Informational.
  • limit-uptime time — Total time for which the user can be logged in, over all sessions. When it is reached, the user is logged out and cannot log in. 0s - no limit.
  • limit-bytes-in num — Number of bytes that the user can send, over all sessions. When it is reached, the user is logged out and cannot log in. 0 - no limit.
  • limit-bytes-out num — Number of bytes that the user can receive, over all sessions. When it is reached, the user is logged out and cannot log in. 0 - no limit.
  • limit-bytes-total num — Number of bytes that the user can send and receive together, over all sessions. When it is reached, the user is logged out and cannot log in. 0 - no limit.

Read-only Argument / Type / Description

  • uptime time — Time for which the user has been logged in, over all sessions.
  • bytes-in num — Bytes received from the user, over all sessions.
  • bytes-out num — Bytes sent to the user, over all sessions.
  • packets-in num — Packets received from the user, over all sessions.
  • packets-out num — Packets sent to the user, over all sessions.

ip/hotspot/user/profile

Type: Directory

The /ip/hotspot/user/profile menu lists the user profiles. A profile holds the settings that users share: the rate limit, the timeouts, the number of devices, the address list, and the login and logout scripts. See the HotSpot guide.

Flag / Name / Description

  • ***** default — The default profile. It cannot be removed.

Argument / Type / Description

  • name string — Name of the profile.
  • address-pool enum (none) { none:0 } — IP pool from which the users of the profile get their address through the HotSpot address translation. Default: none.
  • session-timeout time — Time after which a user is logged out. The user can log in again. 0s - no limit.
  • idle-timeout super { idle-timeout: alt { symbolic-names: enum (none) { none:0 } , time-interval: time } } — Time without traffic from a logged-in user after which the user is logged out. Default: none.
  • keepalive-timeout super { keepalive-timeout: alt { symbolic-names: enum (none) { none:0 } , time-interval: time } } — Time for which the device of a logged-in user can be unreachable before the user is logged out. Default: 2m.
  • status-autorefresh alt { symbolic-names: enum (none) { none:0 } , time-interval: time } — Refresh interval of the status page. Default: 1m.
  • shared-users enum (unlimited) { unlimited:0 } — Number of devices that can be logged in with the same user name at the same time. Default: 1.
  • add-mac-cookie bool — Whether to create a MAC cookie for the users of the profile, for the mac-cookie login method. Default: yes.
  • mac-cookie-timeout time — Time for which a MAC cookie is valid. Default: 3d.
  • rate-limit string — Rate limit in the form rx-rate[/tx-rate] [rx-burst-rate[/tx-burst-rate] [rx-burst-threshold[/tx-burst-threshold] [rx-burst-time[/tx-burst-time] [priority] [rx-rate-min[/tx-rate-min]]]]]. rx is what the router receives from the user (upload), tx is what it sends to the user (download). For example, 512k/2M limits upload to 512 kbps and download to 2 Mbps. The router creates a dynamic simple queue with this limit for each logged-in user.
  • insert-queue-before super { queue: enum (bottom | first) { bottom:0xffffffff, first:0 } } — Position of the dynamic simple queue of a user in the queue list: first, bottom, or the name of a queue before which it is placed.
  • parent-queue super { queue: enum (none) { none:0 } } — Parent of the dynamic simple queue of a user. Default: none.
  • queue-type super { queue: enum } — Queue type of the dynamic simple queue of a user.
  • address-list multi { address-list: string } — Firewall address lists to which the address of each logged-in user is added.
  • incoming-filter string — Firewall filter chain for the packets from the users of the profile. Add a jump rule from the hotspot chain to this chain.
  • outgoing-filter string — Firewall filter chain for the packets to the users of the profile. Add a jump rule from the hotspot chain to this chain.
  • incoming-packet-mark string — Packet mark for the packets from the users of the profile.
  • outgoing-packet-mark string — Packet mark for the packets to the users of the profile.
  • on-login alt { script: string } — Script that runs when a user of the profile logs in. It can use the variables $user, $username, $address, $"mac-address", and $interface.
  • on-logout alt { script: string } — Script that runs when a user of the profile logs out. In addition to the on-login variables it can use $cause, $"uptime-secs", $"bytes-in", $"bytes-out", $"bytes-total", $"packets-in", $"packets-out", and $"packets-total".
  • transparent-proxy bool — Whether to send the HTTP requests of the logged-in users of the profile through the HotSpot proxy. Default: no.
  • open-status-page enum (http-login | always) — When to open the status page after login: always - also after a mac login; http-login - only after a login on the login page.
  • advertise bool — Whether to show advertisement pages to the users of the profile. Default: no.
  • advertise-url multi { url: string } — URLs of the advertisement pages. After the last one, the list starts again.
  • advertise-interval multi { time-interval: time } — Intervals between the advertisements. After the list ends, the last value is used.
  • advertise-timeout alt { symbolic-names: enum (immediately | never) { immediately:0, never:0xffffffff } , time-interval: time } — Time to wait for the advertisement to be shown before the network access of the user is blocked: a time, immediately, or never.

identity

Identities are configuration parameters that are specific to the remote peer. The main purpose of identity is to handle authentication and verify the peer's integrity.

ip/ipsec/identity

Type: Directory

Identities are configuration parameters that are specific to the remote peer. The main purpose of identity is to handle authentication and verify the peer's integrity.

Flag / Name / Description

  • D dynamic — Whether the item was created dynamically.
  • X disabled — Whether an item is disabled.

Argument / Type / Description

  • peer enum — Peer name.
  • auth-method enum (pre-shared-key | digital-signature | eap | eap-radius | pre-shared-key-xauth | rsa-key | rsa-signature-hybrid) — Authentication method: - digital-signature - authenticate using a pair of RSA certificates; - eap - IKEv2 EAP authentication for the initiator (peer with a netmask of /32). Must be used together with eap-methods; - eap-radius - IKEv2 EAP RADIUS passthrough authentication for the responder (RFC 3579). A server certificate in this case is required. If a server certificate is not specified then only clients supporting EAP-only (RFC 5998) will be able to connect. Note that the EAP method should be compatible with EAP-only; - pre-shared-key - authenticate by a password (pre-shared secret) string shared between the peers (not recommended since an offline attack on the pre-shared key is possible); - rsa-key - authenticate using an RSA key imported in the keys menu. Only supported in IKEv1; - pre-shared-key-xauth - authenticate by a password (pre-shared secret) string shared between the peers + XAuth username and password. Only supported in IKEv1; - rsa-signature-hybrid - responder certificate authentication with initiator XAuth. Only supported in IKEv1.
  • eap-methods multi { array-id, method: enum (eap-tls | eap-ttls | eap-peap | eap-mschapv2) } — All EAP methods require a whole certificate chain including intermediate and root CA certificates to be present in System/Certificates menu. Also, the username and password (if required by the authentication server) must be specified. Multiple EAP methods can be specified and are used in the specified order. Supported EAP methods: - eap-mschapv2; - eap-peap - also known as PEAPv0/EAP-MSCHAPv2; - eap-tls - requires additional client certificate specified under certificate parameter; - eap-ttls.
  • mode-config enum (none) — Name of the configuration parameters from mode-config menu. When the parameter is set mode-config is enabled.
  • notrack-chain string — Adds IP/Firewall/Raw rules matching IPsec policy to a specified chain. Use together with generate-policy.
  • my-id alt { string: composite { type: enum (fqdn | user-fqdn | key-id) , data: string } , address: composite { type: enum (address) , data: alt { ipv6: ip6Addr , ip: ipAddr } } , other: enum (auto | dn) } — On the initiator, this controls what ID_i is sent to the responder. On the responder, this controls what ID_r is sent to the initiator. In IKEv2, the responder also expects this ID in received ID_r from the initiator. - auto - tries to use correct ID automatically: IP for pre-shared key, SAN (DN if not present) for certificate based connections; - address - IP address is used as ID; - dn - the binary Distinguished Encoding Rules (DER) encoding of an ASN.1 X.500 Distinguished Name; - fqdn - fully qualified domain name; - key-id - use the specified key ID for the identity; - user fqdn - specifies a fully-qualified username string, for example, "user@domain.com".
  • remote-id alt { string: composite { type: enum (fqdn | user-fqdn | key-id) , data: string } , address: composite { type: enum (address) , data: alt { ipv6: ip6Addr , ip: ipAddr } } , auto: enum (auto | ignore | dn) } — This parameter controls what ID value to expect from the remote peer. Note that all types except for ignore will verify remote peer's ID with a received certificate. In case the peer sends the certificate name as its ID, it is checked against the certificate, else the ID is checked against Subject Alt. Name. - auto - accept all IDs; - address - IP address is used as ID; - dn - the binary Distinguished Encoding Rules (DER) encoding of an ASN.1 X.500 Distinguished Name; - fqdn - fully qualified domain name. Only supported in IKEv2; - user fqdn - a fully-qualified username string, for example, "user@domain.com". Only supported in IKEv2; - key-id - specific key ID for the identity. Only supported in IKEv2; - ignore - do not verify received ID with certificate (dangerous). * Wildcard key ID matching is not supported, for example, remote-id="key-id:CN=*.domain.com"
  • match-by enum (remote-id | certificate) — Defines the logic used for peer's identity validation. - remote-id - verifies the peer's ID according to remote-id setting. - certificate verifies the peer's certificate with what is specified under remote-certificate setting.
  • key enum () — Name of the private key from the keys menu. Applicable if RSA key authentication method (auth-method=rsa-key) is used.
  • remote-key enum () — Name of the public key from the keys menu. Applicable if RSA key authentication method (auth-method=rsa-key) is used.
  • secret string — Secret string. If it starts with '0x', it is parsed as a hexadecimal value. Applicable if pre-shared key authentication method (auth-method=pre-shared-key or auth-method=pre-shared-key-xauth) is used.
  • certificate multi { array-id, certificate: enum } — Local certificate. Applicable if digital signature authentication method (auth-method=digital-signature) or EAP (auth-method=eap) is used.
  • remote-certificate enum (none) { none:-1 } — Certificate for authenticating the remote side (validating packets; no private key required). If a remote-certificate is not specified then the received certificate from a remote peer is used and checked against the CA in the certificate menu. A proper CA must be imported in a certificate store. If remote-certificate and match-by=certificate are specified, only the specific client certificate will be matched. Applicable if digital signature authentication method (auth-method=digital-signature) is used.
  • username string — EAP or XAuth username.
  • password string — EAP or XAuth password.
  • generate-policy enum (no | port-override | port-strict) — Allow this peer to establish SA for non-existing policies. Such policies are created dynamically for the lifetime of SA. Automatic policies allow, for example, to create IPsec secured L2TP tunnels, or any other setup where remote peer's IP address is not known at the configuration time. - no - do not generate policies; - port-override - generate policies and force policy to use any port (old behavior); - port-strict - use ports from peer's proposal, which should match peer's policy.
  • policy-template-group enum — Policy template group to use for generated policies. If none of the templates match, Phase 2 SA will not be established.

Type: Directory

INFO

Policy order is important. It works similarly to firewall filters where policies are executed from top to bottom (priority parameter is removed).

All packets are IPIP encapsulated in tunnel mode, and their new IP header's src-address and dst-address are set to sa-src-address and sa-dst-address values of this policy. If you do not use tunnel mode (i.e., you use transport mode), then only packets whose source and destination addresses are the same as sa-src-address and sa-dst-address can be processed by this policy. Transport mode can only work with packets that originate at and are destined for IPsec peers (hosts that established security associations). To encrypt traffic between networks (or a network and a host) you have to use tunnel mode.

  • local-port super { ! , port: num [0 .. 65535] } — Port of the proxy the request arrived on. Use it when port in /ip/proxy lists several ports.
  • dst-host super { ! , host: string } — Host name of the request, for HTTPS requests the host of the CONNECT tunnel. The value must match the whole name and is not case-sensitive, so example.com does not match www.example.com. - Wildcards: * matches any characters and ? one character, for example *.example.com. - A value that starts with : is a regular expression, which can match any part of the name: :mail matches mail.example.com. Anchor it with ^ and $, for example :^www.
  • path super { ! , path: string } — Path of the requested URL, including the query string, for example /music/a.mp3?x=1. Wildcards and regular expressions work as in dst-host. - Wildcards must match the whole path including the query string, so *.mp3 matches /music/a.mp3 but not /music/a.mp3?x=1. - The path always starts with /, so the router refuses a value such as music/*, which could never match. - HTTPS requests have no path, so a rule with path never matches them.
  • method super { ! , method: enum (GET | HEAD | POST | PUT | CONNECT | OPTIONS | DELETE | TRACE) } — HTTP method of the request: GET, HEAD, POST, PUT, CONNECT, OPTIONS, DELETE or TRACE. Clients of the proxy request HTTPS pages with CONNECT. The methods are defined in RFC 9110.
  • action enum (allow | deny) — What the proxy does with the response to a matching request. - allow (default) - Store the response when it can be cached. - deny - Do not store the response. /ip/proxy/inserts and /ip/proxy/lookups count such requests as denied.

ip/proxy/connections

Type: Directory

Open connections of the web proxy. Each connection from a client and each connection to a server is a row. The proxy keeps connections to servers open after a response and uses them for later requests. For an overview, see Web Proxy.

Flag / Name / Description

  • S server — server. A connection from the proxy to a server.
  • C client — client. A connection from a client to the proxy.

Read-only Argument / Type / Description

  • src-address alt { ip4: ipAddr , ip6: ip6Addr } — Address of the client whose request the connection serves.
  • dst-address alt { ip4: ipAddr , ip6: ip6Addr } — Address of the server.
  • last-protocol enum (HTTP/1.0 | HTTP/1.1 | FTP) { HTTP/1.0:1, HTTP/1.1:2, FTP:3 } — Protocol of the last request on the connection: HTTP/1.0, HTTP/1.1 or FTP.
