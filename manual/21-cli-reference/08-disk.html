disk

RouterOS directory reference for /disk.

disk

Conditions: !smips Type: Directory

Flag / Name / Description

  • X disabled — The device is disabled and is not used.
  • A acquired — acquired
  • E empty — The slot is empty, with no disk present. After eject, the slot stays empty until the disk is rescanned with scan or replugged.
  • B block-device — The device is a block device, that is, it can be used as storage: formatted or used in a RAID array. Devices without this flag only describe the disk layout.
  • M mounted — The device is mounted and its files appear in /file.
  • F formatting — The device is currently being formatted.
  • S swap-enabled — Swap is enabled on the device (swap=yes); the device is used as swap space, for example by containers.
  • f raid-member-failed — A member of the RAID array is in failed state.
  • r raid-member — The device is a member of a RAID array.
  • c encrypted — The device is encrypted, for example with type=crypted (dm-crypt).
  • g guid-partition-table — The device has a GUID partition table (GPT).
  • p partition — The device is a partition of a disk.
  • t nvme-tcp-export — The device is exported as an NVMe-over-TCP target.
  • i iscsi-export — The device is exported as an iSCSI target.
  • s smb-sharing — The device is shared through the built-in SMB server.
  • n nfs-sharing — The device is shared with the NFS server.
  • m media-sharing — The device is shared through the DLNA media server.
  • L self-encrypted-and-locked — self-encrypted-and-locked
  • O self-encryption-enabled — TCG-Opal self-encryption is active on the drive.
  • o self-encryption-supported — The drive supports TCG-Opal self-encryption, but it is not enabled.

Argument / Type / Description

  • type enum (raid | nvme-tcp | iscsi | nfs | smb | partition | tmpfs | ramdisk | crypted | sshfs | file | hardware) — Type of the item: - hardware - a physical disk attached to the router, for example in a USB, SATA or NVMe slot. - partition - a partition on a hardware disk (see parent). - file - a file mounted as a block device (loop), for example a swap file or a mounted .iso / .squashfs image. - tmpfs - a folder in RAM, see Tmpfs. - ramdisk - part of RAM used as a block device, see Ramdisk (storage package). - raid - a RAID array built from several disks, see RAID (storage package). - crypted - a dm-crypt encrypted block device, see Encrypted storage (storage package). - nvme-tcp - a disk mounted over NVMe over TCP, see NVMe over TCP (storage package). - iscsi - an iSCSI target mounted as a disk, see iSCSI (storage package). - nfs - an NFS share mounted as a disk, see NFS (storage package). - smb - an SMB share mounted as a disk, see SMB (storage package). - sshfs - a remote folder mounted over SSH.
  • slot string — Name of the disk item, normally based on where the device is physically connected, for example nvme1 or usb1. The name is assigned automatically and can be set manually. Other commands and parent refer to the disk by this name.
  • parent enum () — Parent device of the item. On a type=partition item it selects the hardware disk the partition is created on, for example add type=partition parent=nvme9 ...; on type=crypted it is the drive or partition that is encrypted.
  • mount-point-template string — Template of the mount point, the folder under which the file system appears in /file. The following variables are replaced: - [slot] (default) - the slot name. - [model] - the device model. - [serial] - the device serial number. - [fw-version] - the device firmware version. - [fs-label] - the file system label. - [fs-uuid] - the file system UUID. - [fs] - the file system type. Variables can be combined, for example [model]-[fs]. An empty template is rejected, and unset mount-point-template restores the default [slot]. The default for newly added disks is set by default-mount-point-template in settings. See Disks.
  • mount-filesystem bool — Whether the device's file system is mounted, so its files are available in /file. mount-filesystem=no unmounts the file system, which is required before /disk check or /disk repair. Default: yes.
  • mount-read-only bool — Whether the mounted file system is read-only. Default: no.
  • compress bool — Whether the device's file system is mounted with compression. Only supported on btrfs file systems; RouterOS reports compression only available for btrfs when it is set on other file systems. Default: no.
  • partition-number num — Number of the partition on the parent disk, for example partition-number=1 for the first partition.
  • partition-offset num — Start offset of the partition on the disk, in bytes. Use it to adjust where the partition begins.
  • partition-size num — Size of the partition in bytes. When it is not set, the partition takes the remaining space on the disk. See Disks.
  • raid-type enum (0 | 1 | 4 | 5 | 6 | linear) { 0:0, 1:1, 4:4, 5:5, 6:6 } — RAID level of the array: - 0 - striping: data is spread evenly over all disks, no fault tolerance, best performance. - 1 - mirroring: the same data is written to all disks, best fault tolerance. - 4 - block-level striping with parity stored on a dedicated disk. - 5 - block-level striping with distributed parity, survives one disk failure. - 6 - block-level striping with double parity, survives two disk failures. - linear - the disks are joined into one large disk without redundancy. See RAID.
  • raid-device-count num — Number of devices (disks) in the RAID array, set when the array is created.
  • raid-max-component-size num — Maximum size of an individual device in the RAID array.
  • raid-chunk-size enum (64K | 128K | 256K | 512K | 1M | 2M | 4M) { 64K:64, 128K:128, 256K:256, 512K:512, 1M:1024, 2M:2048, 4M:4096 } — Size of the chunks (stripes) written across the disks of the array, for example 1M.
  • raid-master enum (none) — RAID block device a disk belongs to. Set it together with raid-role on the member disks to add them to an array created with add type=raid .... On the RAID item itself it is none.
  • raid-role num — Position of the disk within the RAID array, set with raid-master, starting from 0, or spare to mark the disk as a hot spare.
  • raid-member-failed bool — Marks a drive as failed in the RAID array. Used when a non-failed drive needs to be replaced.
  • nvme-tcp-export bool — Whether the device is exported as an NVMe-over-TCP target, so other devices can mount it. Default: no. See NVMe over TCP.
  • nvme-tcp-server-port num — Port on which the NVMe-over-TCP server accepts connections from initiators. See NVMe over TCP.
  • nvme-tcp-server-nqn string — NVMe Qualified Name (NQN) of the exported device, used by initiators to connect. See NVMe over TCP.
  • nvme-tcp-server-allow-host-name string — Hostnames allowed to connect to the NVMe-over-TCP server, for host-based access control. See NVMe over TCP.
  • nvme-tcp-server-password string — Password the NVMe-over-TCP server requires from initiators. See NVMe over TCP.
  • nvme-tcp-address ipAddr — IP address of the NVMe-over-TCP target (host) to mount, on the nvme-tcp client. See NVMe over TCP.
  • nvme-tcp-nqn string — NVMe Qualified Name (NQN) of the target on the server to mount, on the nvme-tcp client. See NVMe over TCP.
  • nvme-tcp-host-name string — Hostname the nvme-tcp initiator (client) identifies itself with; used for identification and authentication on the server. See NVMe over TCP.
  • nvme-tcp-password string — Password used to authenticate the NVMe-over-TCP connection to the server. See NVMe over TCP.
  • nvme-tcp-port num — Port the NVMe-over-TCP target listens on for connections from initiators. Default: 4420. See NVMe over TCP.
  • iscsi-export bool — Whether the device is exported as an iSCSI target. Default: no. See iSCSI.
  • iscsi-server-port num — Port the iSCSI server listens on. See iSCSI.
  • iscsi-server-iqn string — iSCSI Qualified Name (IQN) of the iSCSI server, by default iqn.2000-02.com.mikrotik:<slot>. See iSCSI.
  • iscsi-port num — Port the iSCSI target listens on for connections from initiators. Default: 3260. See iSCSI.
  • iscsi-address ipAddr — IP address of the iSCSI target (host) to mount, on the iscsi client. See iSCSI.
  • iscsi-iqn string — iSCSI Qualified Name (IQN) of the target to mount, on the iscsi client. See iSCSI.
  • nfs-sharing bool — Whether the device is shared with NFS, so network clients can mount it. Default: no. See NFS.
  • nfs-address ipAddr — IP address of the NFS server to mount, on the nfs client. See NFS.
  • nfs-share string — Folder to mount on the NFS server, on the nfs client. See NFS.
  • smb-sharing bool — Whether the device is shared through the built-in SMB server (/ip/smb) when it is mounted. With auto-smb-sharing=yes in settings it is enabled automatically. Default: no.
  • smb-server-user enum () — SMB user of the auto-created share of this disk; the default for new disks is taken from auto-smb-user in settings.
  • smb-server-password string — Password of the SMB user of the auto-created share.
  • smb-server-encryption bool — Whether connections to the SMB share of this disk must be encrypted.
  • smb-address ipAddr — IP address of the SMB server to mount, on the smb client. See SMB.
  • smb-share string — Name of the share to mount on the server, on the smb client. See SMB.
  • smb-user string — SMB user to authenticate with, on the smb client. See SMB.
  • smb-password string — Password of the SMB user, on the smb client.
  • smb-encryption bool — Whether the connection to the remote SMB share is encrypted, on the smb client.
  • media-sharing bool — Whether the device is shared through the DLNA media server (/ip/media) when it is mounted. With auto-media-sharing=yes in settings it is enabled automatically. Default: no.
  • media-interface iface_enum { none } — Interface the DLNA media server uses for the share of this disk, set together with media-sharing=yes.
  • tmpfs-max-size num — Maximum size of a tmpfs folder, in decimal units (100M is 100 000 000 bytes). The folder uses RAM only for the files stored in it. When the size is not set (it reads 0), the folder can grow to about half of the RAM. RouterOS adds up the maximum sizes of all tmpfs folders, counting a folder without tmpfs-max-size as half of the RAM, and refuses a new size when the total is more than the router can provide (too much memory requested for tmpfs/ramdisk). The size in print is rounded up to whole 4 KiB memory pages. A new value applies at once, also to a mounted folder. The contents of a tmpfs are lost on reboot or power loss. See Tmpfs. Default: not set.
  • ramdisk-size num — Size of the RAM block device created with type=ramdisk, rounded up to a multiple of 16 KiB. The RAM is not reserved when the ramdisk is added. A reboot or power loss clears it: the ramdisk stays, but empty and without a file system, so format it again. Needs the rose-storage package. See Ramdisk.
  • crypted-backend enum (none) — The drive or partition to encrypt with type=crypted. See Encrypted storage.
  • encryption-key string — The key used to decrypt the crypted device. See Encrypted storage.
  • self-encryption-password string — Password that enables TCG-Opal self-encryption on a supported (SED) drive; unsetting it disables self-encryption. See Self-encrypting drives.
  • sshfs-address string — Address (IP address or hostname) of the SSH server to mount, for type=sshfs. See SSHFS.
  • sshfs-port num — Port of the SSH server to connect to, for type=sshfs (default: 22). See SSHFS.
  • sshfs-user string — User to log in to the remote SSH server with, for type=sshfs. See SSHFS.
  • sshfs-password string — Password of the remote SSH user, for type=sshfs. See SSHFS.
  • sshfs-path string — Path on the remote SSH server to mount, for type=sshfs. See SSHFS.
  • swap bool — Use the device as swap space. Swap is used only by containers, and its usable size is limited to 10 times the device's RAM. It applies to a whole disk or partition, or to a file with type=file. See Disks.
  • file-path file — Path and name of the file mounted as a block device with type=file, for example a swap file (swap=yes) or a mounted .iso / .squashfs image. Removing the disk item does not delete the file. See Disks.
  • file-size num — Size of the file, for example file-size=1G, when creating a type=file device.
  • file-offset num — Offset in the file at which the block device starts, for example file-offset=0.

Read-only Argument / Type / Description

  • slot-default string — Default slot name of the device, shown when no custom slot name is set.
  • fs-label string — Label of the file system. Formatting sets it automatically to <slot>-fs, unless a label is given to /disk format.
  • fs-uuid string — UUID of the file system, for example 58470fe2-....
  • fs enum (fat32 | ext4 | btrfs | xfs | nfs | smb | wipe | wipe-quick | tmpfs | exfat | ntfs | sshfs | squashfs | iso | discard | discard-secure | -) — File system of the device: ext4, btrfs, xfs, fat32, exfat and ntfs for local file systems, tmpfs for RAM folders, nfs, smb and sshfs for network mounts, and iso / squashfs for mounted images. - means the device has no recognised file system. The values wipe, wipe-quick, discard and discard-secure correspond to the file systems of /disk format.
  • model string — Model name of the device, for example TS1TUTE210T.
  • serial string — Serial number of the device.
  • fw-version string — Firmware version of the device.
  • size num — Total size of the device in bytes.
  • free num — Free space on the mounted file system in bytes.
  • total-inodes num — Total number of inodes of the file system.
  • free-inodes num — Number of free inodes of the file system.
  • use num — Used space of the file system in percent, for example 4%.
  • mount-point string — Mount point of the file system, the folder under which it appears in /file, driven by mount-point-template.
  • sector-size num — Sector size of the device, for example 512 bytes.
  • interface string — Interface the device is connected to, for example PCIe 2x8 GT/s or USB 2.00 480Mbps.
  • interface-speed num — Speed of the interface the device is connected to, for example 15.7Gbps.
  • raid-member-state string — State of the disk as a member of its RAID array, for example 0:in_sync; when the disk is not part of an assembled array, the details of the RAID superblock found on it are shown instead.
  • state string — State of a RAID array, for example clean.
  • last-seen string — Model and serial number of the disk that last occupied this slot, shown after the disk was ejected or removed, for example TS1TUTE210T J398770033.
  • raid-uuid string — UUID of the RAID array.
  • nvme-tcp-server-secret string — Secret the NVMe-over-TCP server uses to authenticate connections from initiators.
  • nvme-tcp-secret string — Secret used to authenticate the connection to the NVMe-over-TCP server.
  • sshfs-local-user string — Local RouterOS user the SSHFS mount runs under, for example admin. Read-only.
  • io-ops num — Total number of I/O operations on the device, as shown by monitor-traffic.
  • io-errors num — Total number of I/O errors on the device.
  • read-ops num — Total number of read operations.
  • read-ops-per-second num — Number of read operations per second.
  • read-bytes num — Total number of bytes read.
  • read-rate num — Rate of reads, for example in bytes per second.
  • read-merges num — Number of adjacent read operations merged.
  • read-time time — Time spent on read operations.
  • write-ops num — Total number of write operations.
  • write-ops-per-second num — Number of write operations per second.
  • write-bytes num — Total number of bytes written.
  • write-rate num — Rate of writes, for example in bytes per second.
  • write-merges num — Number of adjacent write operations merged.
  • write-time time — Time spent on write operations.
  • in-flight-ops num — Number of I/O operations currently in flight.
  • active-time time — Time the device was busy handling requests.
  • wait-time time — Time requests spent waiting in the queue.
  • discard-ops num — Total number of discard (trim) operations.
  • discard-bytes num — Total number of bytes discarded.
  • discard-merges num — Number of adjacent discard operations merged.
  • discard-time time — Time spent on discard operations.
  • flush-ops num — Total number of flush operations.
  • flush-time time — Time spent on flush operations.
  • temperature num — Temperature of the drive in Celsius, reported by S.M.A.R.T. (storage package). See the S.M.A.R.T. info guide and smart-info.
  • temperatures multi { array-id, slot: num } — Temperatures of the drive's sensors in Celsius, one entry per sensor slot.
  • critical-warning ubit (spare-space, temperature, reliability-degraded, read-only, volatile-backup-failed) — Bitmask of critical warnings the drive reports: spare-space (available spare is below available-spare-threshold), temperature (temperature out of range), reliability-degraded, read-only (the device entered read-only mode) and volatile-backup-failed.
  • available-spare num — Remaining spare blocks of the drive in percent, for example 100%. Below available-spare-threshold the drive reports a warning.
  • available-spare-threshold num — Threshold in percent below which the available spare space of the drive is reported as a warning.
  • percentage-used num — Estimated percentage of the drive's life used, based on how many spare blocks have been consumed.
  • host-read-bytes num — Total number of bytes read by the host from the drive.
  • host-write-bytes num — Total number of bytes written by the host to the drive.
  • host-read-cmds num — Total number of read commands the host sent to the drive.
  • host-write-cmds num — Total number of write commands the host sent to the drive.
  • controller-busy-time time — Total time the drive controller was busy with commands.
  • power-cycles num — Number of power cycles of the drive.
  • power-on-time time — Total time the drive was powered on.
  • unsafe-shutdowns num — Number of unsafe (unexpected) shutdowns of the drive.
  • unrecovered-integrity-errors num — Number of unrecovered media and data integrity errors of the drive.
  • warning-temperature num — Temperature in Celsius at which the drive starts reporting a warning.
  • warning-temperature-time time — Time the drive spent above warning-temperature.
  • critical-temperature num — Temperature in Celsius at which the drive reports a critical condition.
  • critical-temperature-time time — Time the drive spent above critical-temperature.

RouterOS directory reference for /disk/btrfs/filesystem.

disk/btrfs/filesystem

Conditions: !smips Syscap: storage Type: Directory

Flag / Name / Description

  • I missing-devs — One or more devices of the file system are missing, so the file system is degraded.
  • b balancing — A balance operation is running on the file system.
  • r replacing — A device replace operation is running on the file system.
  • s scrubbing — A scrub operation is running on the file system.

Argument / Type / Description

  • label string — Label of the Btrfs file system, used to address the file system in the btrfs menus, for example btrfsdisk.
  • default-subvolume enum — Subvolume that is presented as the root folder of the file system in /file. <FS_ROOT> (default) is the root of the Btrfs file system itself.

Read-only Argument / Type / Description

  • uuid string — UUID of the Btrfs file system.
  • total-devs num — Number of devices in the file system.
  • dev-ids multi { array-id, devid: num } — Numeric device IDs of the devices in the file system; needed by replace-device when a device is missing.
  • devs multi { array-id, dev: enum } — Disk slots of the devices in the file system, for example nvme8,nvme9.
  • spaces multi { array-id, space: string } — Space allocation of the file system, per device and per storage profile (data, system, meta, global-reserve), for example data,raid1:1.07GB nvme8:1.07GB nvme9:1.07GB, used:1%.
  • balance-status string — Status of the balance operation, for example done, or an error message such as BTRFS_IOC_BALANCE_V2 failed: ....
  • replace-status string — Status of the replace or device removal operation, for example done, or an error message such as BTRFS_IOC_DEV_REPLACE failed: File exists or BTRFS_IOC_RM_DEV_V2 failed: Resource temporarily unavailable.
  • scrub-status string — Status of the scrub operation, for example done.
  • write-errors multi { snapshot: num } — Write error counters, one value per device in the file system. Reset with reset-counters.
  • read-errors multi { snapshot: num } — Read error counters, one value per device.
  • flush-errors multi { snapshot: num } — Flush error counters, one value per device.
  • corruption-errors multi { snapshot: num } — Data corruption error counters, one value per device.
  • generation-errors multi { snapshot: num } — Generation mismatch error counters, one value per device.

balance-start

RouterOS command reference for /disk/btrfs/filesystem/balance-start.

disk/btrfs/filesystem/balance-start

Conditions: !smips Syscap: storage Type: Command

Argument / Type / Description

  • data-profile enum (single | dup | raid0 | raid1 | raid1c3 | raid1c4 | raid10) — Profile to convert the data chunks to: single stores chunks once (only sensible with a single device), dup stores them twice on the same device, the raid* profiles spread them across multiple devices. Change the profiles after add-device to turn a single-disk file system into a Btrfs RAID, for example data-profile=raid1.
  • metadata-profile enum (single | dup | raid0 | raid1 | raid1c3 | raid1c4 | raid10) — Profile to convert the meta (metadata) chunks to. Metadata is small compared to data, so dup (default for a single device) or raid1 are the common choices.
  • system-profile enum (single | dup | raid0 | raid1 | raid1c3 | raid1c4 | raid10) — Profile to convert the system chunks to; keep it the same as metadata-profile.
  • data-usage range — Only relocate data chunks that are at most this percentage full, for example data-usage=50 skips chunks that are more than half full. Balancing is faster but incomplete with a lower value.
  • metadata-usage range — Only relocate metadata chunks that are at most this percentage full.
  • system-usage range — Only relocate system chunks that are at most this percentage full.

subvolume

RouterOS directory reference for /disk/btrfs/subvolume.

disk/btrfs/subvolume

Conditions: !smips Syscap: storage Type: Directory

Flag / Name / Description

  • ***** default — The entry is the root subvolume of the file system, shown as <FS_ROOT>; it is created automatically with the file system.
  • S snapshot — The subvolume is a snapshot, created with the parent argument.
  • r read-only — The subvolume is read-only.
  • D dead — The subvolume is dead, for example it is being removed.
  • M mounted — The subvolume is mounted (mount=yes) under its mountpoint.

Argument / Type / Description

  • fs enum — Label of the Btrfs file system the subvolume belongs to, as shown in filesystem.
  • parent enum — Subvolume the new subvolume is created from. With parent, the new subvolume becomes a snapshot of the parent and shares its content at the time of creation. See Btrfs subvolumes and snapshots.
  • name string — Name of the subvolume. A path-like name, for example Snapshots/backup-10, places the subvolume inside another subvolume; top-level then shows the containing subvolume.
  • read-only bool — Whether the subvolume is read-only (r - READ-ONLY flag). Default: no.
  • mount bool — Whether the subvolume is mounted under its mountpoint (M - MOUNTED flag). Default: no.
  • mountpoint string — Mount point the subvolume is mounted under, relative to the file system mount point. Defaults to the name of the subvolume.

Read-only Argument / Type / Description

  • top-level enum — Top-level subvolume the subvolume is located in, for example Snapshots; <FS_ROOT> when the subvolume sits directly under the file system root.
  • fullname string — Full path of the subvolume within the file system, for example Snapshots/backup-10.
  • uuid string — UUID of the subvolume.
  • received-uuid string — UUID of the subvolume on the sender when the subvolume was received with a Btrfs transfer; empty for locally created subvolumes.
  • creation-time date — Date and time the subvolume was created.
  • subvolume-id num — Btrfs ID number of the subvolume.
  • generation num — Btrfs transaction generation of the subvolume.
  • dead bool — Whether the subvolume is dead (D - DEAD flag).
  • snapshot bool — Whether the subvolume is a snapshot (S - SNAPSHOT flag).
  • send-trans-id num — Btrfs transaction ID of the last send the subvolume was part of.
  • send-time date — Time the subvolume was last sent with a Btrfs transfer.
  • recv-trans-id num — Btrfs transaction ID of the receive that created the subvolume.
  • recv-time date — Time the subvolume was received with a Btrfs transfer.
  • snapshots multi { array-id, snapshot: enum } — Snapshots that were created from this subvolume.
  • path string — Path the subvolume was received into by a Btrfs transfer (file= on the receiver); empty for locally created subvolumes.

transfer

RouterOS directory reference for /disk/btrfs/transfer.

disk/btrfs/transfer

Conditions: !smips Syscap: storage Type: Directory

Argument / Type / Description

  • type enum (receive | send) — Direction of the Btrfs transfer: - receive - receive a Btrfs send stream at file, for example the destination side of a snapshot backup between two RouterOS devices. - send - send subvolumes (snapshots) of the file system fs to a remote RouterOS device over SSH. Transfers use the SSH user key authentication of /user/ssh-keys. See Btrfs subvolumes and snapshots for a working send/receive example.
  • fs enum — Label of the Btrfs file system the transfer operates on, as shown in filesystem.

disk/format

Conditions: !smips Type: Command

Argument / Type / Description

  • file-system enum (fat32 | ext4 | btrfs | xfs | wipe | wipe-quick | exfat | discard | discard-secure) — What filesystem to format the disk. - ext4 - Format with ext4; the default for most use cases. - fat32 - Format with FAT32, readable by almost any device. - exfat - Format with exFAT, for large files on memory cards and USB drives. - btrfs - Format with Btrfs (data checksums, snapshots, RAID); needs the Storage package. - xfs - Format with XFS; needs the Storage package. - discard - Discard all blocks of the disk (the equivalent of blkdiscard) without writing a file system. - discard-secure - Same, but with a secure discard that also erases the underlying data. - wipe - Overwrite all data on the disk so it cannot be recovered. - wipe-quick - Remove the file system without overwriting the data; fast, but data can be recovered with tools.

Read-only Argument / Type / Description

  • output string — Progress of the format: the mkfs command line and its output, a progress percentage or byte counter, and a final format done line.

  • disk enum (TOT) { TOT:0xffffffff } — The tested disk.
  • thread enum (TOT) { TOT:0xffffffff } — Thread this row belongs to; TOT aggregates all threads.
  • type enum (device | filesystem) — Test type as given when the test was started.
  • pattern enum (sequential | random) — Access pattern as given when the test was started.
