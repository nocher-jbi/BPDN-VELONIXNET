tool/sniffer/start

Type: Command

Starts the sniffer with the settings in /tool/sniffer. The filter arguments are the filter-* settings without the filter- prefix (interface, ip-address, port, ip-protocol), and vlan-id for filter-vlan. With filter arguments, the run uses only the filters given; the saved filters do not apply and do not change. While the sniffer runs, the router turns off IPv4 fast path, and with it FastTrack. The captured packets stay in memory after stop, for packet, protocol, host and connection, for 10 minutes or until the next start. See Packet sniffer.

Argument / Type / Description

  • interface object { interface: iface_enum } — Interfaces to sniff in this run.
  • mac-address object { mac-address-element: super { ! , mac-address-with-mask: composite { mac: macAddr , mask: [ macAddr] } } } — Up to 16 MAC addresses, or MAC addresses with a mask; a frame matches when its source or destination MAC address matches. Prefix an entry with ! to negate it.
  • src-mac-address object { mac-address-element: super { ! , mac-address-with-mask: composite { mac: macAddr , mask: [ macAddr] } } } — Up to 16 source MAC addresses, or MAC addresses with a mask. Prefix an entry with ! to negate it.
  • dst-mac-address object { mac-address-element: super { ! , mac-address-with-mask: composite { mac: macAddr , mask: [ macAddr] } } } — Up to 16 destination MAC addresses, or MAC addresses with a mask. Prefix an entry with ! to negate it.
  • mac-protocol object { mac-protocol-element: super { ! , protocol: alt { mac-protocol: enum () , protocol-number: num [ .. 65535] } } } — Up to 16 MAC (L2) protocols, by name or number (0..65535), for example ip, arp, ipv6 or 802.2. Prefix an entry with ! to negate it.
  • ip-protocol object { ip-protocol-element: super { ! , ip-protocol: enum () } } — Up to 16 IP or IPv6 protocols, by name or number, for example icmp, tcp or udp. Prefix an entry with ! to negate it.
  • ip-address object { ip-address-element: super { ! , ip-address-with-mask: composite { ip: ipAddr , mask: [ num [ .. 32]] } } } — Up to 16 IPv4 addresses or prefixes; a packet matches when its source or destination address matches. Prefix an entry with ! to negate it.
  • src-ip-address object { ip-address-element: super { ! , ip-address-with-mask: composite { ip: ipAddr , mask: [ num [ .. 32]] } } } — Up to 16 source IPv4 addresses or prefixes. Prefix an entry with ! to negate it.
  • dst-ip-address object { ip-address-element: super { ! , ip-address-with-mask: composite { ip: ipAddr , mask: [ num [ .. 32]] } } } — Up to 16 destination IPv4 addresses or prefixes. Prefix an entry with ! to negate it.
  • ipv6-address object { ipv6-address-element: super { ! , ipv6-prefix: ip6Prefix } } — Up to 16 IPv6 prefixes; a packet matches when its source or destination address matches. Prefix an entry with ! to negate it.
  • src-ipv6-address object { ipv6-address-element: super { ! , ipv6-prefix: ip6Prefix } } — Up to 16 source IPv6 prefixes. Prefix an entry with ! to negate it.
  • dst-ipv6-address object { ipv6-address-element: super { ! , ipv6-prefix: ip6Prefix } } — Up to 16 destination IPv6 prefixes. Prefix an entry with ! to negate it.
  • port object { port-element: super { ! , port: enum () } } — Up to 16 ports, by number or by name such as ssh or telnet; a packet matches when its source or destination port matches. Prefix an entry with ! to negate it.
  • src-port object { port-element: super { ! , port: enum () } } — Up to 16 source ports, by number or name. Prefix an entry with ! to negate it.
  • dst-port object { port-element: super { ! , port: enum () } } — Up to 16 destination ports, by number or name. Prefix an entry with ! to negate it.
  • vlan-id object { vlan-element: super { ! , vlan: num [ .. 4095] } } — Up to 16 VLAN IDs (0..4095). Prefix an entry with ! to negate it.
  • direction enum (any | tx | rx) { any:0, tx:1, rx:2 } — Directions to capture in this run. - any (default) - Received and sent packets. - rx - Received packets. They are captured before the firewall, so packets that a firewall rule drops are still captured. - tx - Sent packets, captured after the firewall.
  • operator-between-entries enum (or | and) { or:0, and:1 } — How the entries of one filter are combined in this run. - or (default) - A packet matches a filter when it matches any of the filter's entries. - and - A packet matches a filter only when it matches all of the filter's entries.
  • cpu object { cpu-element: super { ! , cpu: num } } — CPU cores that processed the packet. Prefix an entry with ! to negate it.
  • size object { size-element: super { ! , size-range: range [0 .. 65535] } } — Packet sizes or size ranges in bytes (0..65535), for example 1000-1500. Prefix an entry with ! to negate it.

tool/snmp-get

Type: Command

Retrieves one OID from an SNMP agent — for example to test that a router answers SNMP queries, as described in the SNMP guide. Use /tool/snmp-walk to retrieve a whole subtree at once.

Argument / Type / Description

  • oid object { oid: string } — The OID to read, for example 1.3.6.1.2.1.1.5.0.
  • next bool — When set, fetch the OID that follows the given one in the MIB tree (a GETNEXT instead of a GET).
  • address ipAddr — Address of the SNMP agent to query.
  • port num — UDP port of the agent. Default: 161.
  • tries num — Number of attempts before giving up.
  • try-timeout time — Timeout for each attempt.
  • version enum (1 | 2c | 3) — SNMP protocol version: 1, 2c, or 3.
  • community string — Community name. For v1/v2c the name is the password; for v3 it is the community that carries the matching security level.
  • security enum (none | authorized | private) { none:0, authorized:1, private:2 } — Security level, matching the community: none, authorized, or private.
  • authentication-password string — SNMPv3 authentication password (at least 8 characters).
  • authentication-protocol enum (MD5 | SHA1 | SHA256 | SHA384 | SHA512) — SNMPv3 authentication protocol: MD5, SHA1, SHA256, SHA384, or SHA512.
  • encryption-password string — SNMPv3 encryption password (at least 8 characters).
  • encryption-protocol enum (DES | AES | AES256) — SNMPv3 encryption protocol: DES, AES, or AES256.

Read-only Argument / Type / Description

  • oid string — OID of the value the agent returned.
  • type enum (null | integer | counter | gauge | timeticks | unsigned-integer | octet-string | opaque | object-id | ip-address | counter-64bit | no-such-object | no-such-instance | end-of-mib-view) — Value type as returned by the agent.
  • value string — Value the agent returned.

tool/snmp-walk

  • address ipAddr — Address of the SNMP agent to query.
  • port num — UDP port of the agent. Default: 161.
  • tries num — Number of attempts before giving up.
  • try-timeout time — Timeout for each attempt.
  • version enum (1 | 2c | 3) — SNMP protocol version: 1, 2c, or 3.
  • community string — Community name. For v1/v2c the name is the password; for v3 it is the community that carries the matching security level.
  • security enum (none | authorized | private) { none:0, authorized:1, private:2 } — Security level, matching the community: none, authorized, or private.
  • authentication-password string — SNMPv3 authentication password (at least 8 characters).
  • authentication-protocol enum (MD5 | SHA1 | SHA256 | SHA384 | SHA512) — SNMPv3 authentication protocol: MD5, SHA1, SHA256, SHA384, or SHA512.
  • encryption-password string — SNMPv3 encryption password (at least 8 characters).
  • encryption-protocol enum (DES | AES | AES256) — SNMPv3 encryption protocol: DES, AES, or AES256.

Read-only Argument / Type / Description

  • oid string — OID of the value the agent returned.
  • type enum (null | integer | counter | gauge | timeticks | unsigned-integer | octet-string | opaque | object-id | ip-address | counter-64bit | no-such-object | no-such-instance | end-of-mib-view) — Value type as returned by the agent.
  • value string — Value the agent returned.

tool/speed-test

Type: Command

Measures the link to another MikroTik router in one run: ping round-trip time, jitter and loss, then TCP and UDP throughput in both directions, through the bandwidth test server of the remote router (/tool/bandwidth-server). The test runs five parts of test-duration each, with a pause of about a second between them, and shows the CPU load of the routers next to the throughput results. The remote router needs the server enabled, a user in a group with the test and winbox policies, and a firewall that accepts TCP port 2000 and the server's UDP ports. Needs the bandwidth-test device-mode feature. For examples, see Speed Test.

Argument / Type / Description

  • address address (flags=46viD) — IPv4 or IPv6 address of the remote router, which runs the bandwidth test server. Use its address on the path you want to measure, for example its tunnel address to test a VPN.
  • connection-count num — Number of TCP connections the TCP parts of the test use, 1..255. The session list of the remote server shows it as tcp-connection-count. Default: 20, or the number of CPU cores of the router that runs the test when it has more than 20 (for example 64 on a 64-core router).
  • test-duration time — Length of each of the five parts of the test, at least 5 seconds. The router pauses for about a second between the parts, so the default test takes about 55 seconds. Default: 10s.
  • user string — User name on the remote router. Its group needs the test and winbox policies, as the default read and full groups have. Without user, the command sends no user name, and every throughput line shows authentication failed unless the server has authenticate=no. The address setting of the user does not limit bandwidth test logins; allowed-addresses4 and allowed-addresses6 of the server limit which routers can connect.
  • password string — Password of user on the remote router.

Read-only Argument / Type / Description

  • status string — Part of the test that is running: - ping - Pings for latency, jitter and loss. - tcp download - TCP from the remote router to this router. - tcp upload - TCP from this router to the remote router. - udp download - UDP from the remote router to this router. - udp upload - UDP from this router to the remote router. - done - The test has ended.
  • time-remaining time — Time until the test ends.
  • ping-min-avg-max string — Shortest, average and longest round-trip time of the pings. The ping part sends ICMP echo requests, 20 per second.
  • jitter-min-avg-max string — Variation of the round-trip time between pings: smallest, average and largest.
  • loss string — Lost pings in percent, followed by lost and sent pings, for example 0% (0/100).
  • tcp-download string — TCP throughput from the remote router to this router, with local-cpu-load, the CPU load of this router. Shows authentication failed when the remote server refuses the user.
  • tcp-upload string — TCP throughput from this router to the remote router, with local-cpu-load and remote-cpu-load, the CPU load of this router and of the remote router. Shows authentication failed when the remote server refuses the user.
  • udp-download string — UDP throughput from the remote router to this router, with local-cpu-load and remote-cpu-load. Shows authentication failed when the remote server refuses the user.
  • udp-upload string — UDP throughput from this router to the remote router, with local-cpu-load and remote-cpu-load. Shows authentication failed when the remote server refuses the user.

torch

tool/torch

Type: Command

Shows the traffic that passes one interface right now, grouped into flows by addresses, protocol, ports and DSCP, with the rate of each flow in both directions. Torch sees packets before the firewall, and turns IP fast path off while it runs. It runs until stopped with Ctrl-C or until duration ends. For examples and how to read the output, see Torch.

Argument / Type / Description

  • interface iface_enum — Interface to watch. The name can be given without interface=, for example /tool/torch bridge.
  • src-address super { ! , src-address: ipPrefix } — Show only flows whose src-address is in this IPv4 prefix. src-address of a flow is the address on the far side of the interface, whose traffic the interface receives. Default: any.
  • dst-address super { ! , dst-address: ipPrefix } — Show only flows whose dst-address, the other end of the flow, is in this IPv4 prefix. Default: any.
  • src-address6 super { ! , src-address6: ip6Prefix } — IPv6 prefix for src-address, the far side of the interface. Default: any.
  • dst-address6 super { ! , dst-address6: ip6Prefix } — IPv6 prefix for dst-address, the other end of the flow. Default: any.
  • mac-protocol enum (any) { any:3 } — Show only flows of this MAC protocol, for example ip. Default: any.
  • ip-protocol enum (any) { any:256 } — Show only flows of this IP protocol, for example tcp. Default: any.
  • port enum (any) { any:0 } — Show only flows with this port as src-port or dst-port, one port or any. The filter applies to flows that have ports: flows without ports, such as ICMP, still appear. Default: any.
  • vlan-id alt { number: num [ .. 4095] , enum: enum (any) { any:0xffff } } — Show only frames with this VLAN ID, 0..4095, or any. Tagged frames on the parent interface get a VLAN-ID column also without this filter. Default: any.
  • dscp num — Show only flows with this DSCP value, 0..63, for example 46 for Expedited Forwarding. Default: any.
  • cpu num — With any, adds a CPU column: one row for each CPU that handled packets of a flow.

Read-only Argument / Type / Description

  • cpu num — CPU that handled the packets of the row. Shown with cpu=any.
  • vlan-id num — VLAN ID of the flow. Shown for tagged frames on the parent interface; on the VLAN interface itself the frames are untagged and the column does not appear.
  • mac-protocol enum () — MAC protocol of the flow, for example ip.
  • ip-protocol enum () — IP protocol of the flow, for example tcp, udp or icmp.
  • dscp num — DSCP value of the flow.
  • src-address alt { ip: ipAddr , ipv6: ip6Addr } — Address on the far side of the interface: the side whose traffic the interface receives, also when the router started the conversation.
  • src-port enum () — Port on the src-address side, for TCP and UDP flows, shown with its service name.
  • dst-address alt { ip: ipAddr , ipv6: ip6Addr } — The other end of the flow.
  • dst-port enum () — Port on the dst-address side, for TCP and UDP flows, shown with its service name, such as 2000 (btserv).
  • tx num — Rate of the traffic the interface sends towards src-address, in bits per second.
  • rx num — Rate of the traffic the interface receives from src-address, in bits per second.
  • tx-packets num — Packets per second the interface sends towards src-address.
  • rx-packets num — Packets per second the interface receives from src-address.

traceroute

tool/traceroute

Type: Command

Traces the path to a host: sends probes with a growing TTL and lists the routers that answer, with loss and round-trip statistics for each hop. The trace repeats every second until you stop it, until count rounds are done or until duration ends. For examples and how to read the results, see Traceroute.

Argument / Type / Description

  • address address (flags=46viD) — IP or IPv6 address, or DNS name, of the destination. A name is resolved by the router's DNS resolver. See address flags.
  • port num — Destination UDP port of the probes with protocol=udp. Every probe uses the same port. Default: 33434.
  • size num — Size of each probe as a whole IP packet, in bytes, including the IP header. Default: 28, which is an IPv4 probe without payload.
  • dscp num — DSCP value set in the IP header of the probes.
  • do-not-fragment switch — Sets the Don't Fragment flag in the IP header of the probes. With a large size, the router with a smaller link on the path answers with fragmentation needed from <address>.
  • use-dns bool — Show the host names of the hops instead of their addresses. The names are looked up with reverse DNS queries through the router's DNS resolver; a hop without a reverse DNS record keeps its address. Default: no.
  • count num — Number of rounds to run. Without count, the trace repeats every second until you stop it. Default: unlimited.
  • max-hops num — Highest TTL to try: when the destination does not answer, the round ends after this many hops. Default: 30.
  • protocol enum (icmp | udp) — Type of the probes. - icmp (default) - ICMP echo requests. The destination answers with an echo reply. - udp - UDP datagrams to port. The destination answers with an ICMP port unreachable message.
  • src-address alt { ipv6-address: ip6Addr , ip-address: ipAddr } — Source address of the probes. Routing rules that match the source address apply to the probes. Default: the pref-src of the route, otherwise the address of the outgoing interface.
  • timeout time — How long each probe waits for its answer before the next probe is sent. Default: 1s.
  • vrf enum — VRF whose routing table the probes use. Only VRFs are accepted; a routing table created for policy routing is refused. Default: main.
  • interface iface_enum — Interface to send the probes out of. When no route through the interface covers the destination, the router treats the destination as directly connected there and sends ARP requests for it.

Read-only Argument / Type / Description

  • address object { address: alt { name: string , address: ip6Addr } } — Address of the router that answered for this hop, or its host name with use-dns=yes. Empty when no probe to the hop got an answer.
  • loss num — Percentage of the probes to this hop that got no answer.
  • sent num — Number of probes sent to this hop.
  • last num — Round-trip time of the last answer from this hop. The printed table shows timeout when the last probe got no answer.
  • avg num — Average round-trip time of the answers from this hop.
  • best num — Shortest round-trip time of the answers from this hop.
  • worst num — Longest round-trip time of the answers from this hop.
  • std-dev num — Standard deviation of the round-trip times of this hop: how much they vary from round to round.
  • status string — Error the hop answered with instead of time exceeded, for example network unreachable from 203.0.113.1 (no route, or a firewall reject with the default message), host unreachable from 203.0.113.1, packet filtered from 203.0.113.1 (a firewall rejects the probe as administratively prohibited) or fragmentation needed from 203.0.113.6 (with do-not-fragment, the probe is larger than the next link's MTU). The round ends at such a hop. Empty when the hop answers normally.
  • error string

packet-template

RouterOS directory reference for /tool/traffic-generator/packet-template.

tool/traffic-generator/packet-template

Type: Directory Builds the packet content of a stream from header parameters: MAC, VLAN, IPv4/IPv6, UDP and TCP fields, plus the payload. Many header values are assumed when they can be derived; assumed values are read-only and are re-derived when the template is edited. See the Traffic Generator guide.

Argument / Type / Description

  • name string — Descriptive name of the packet template.
  • header-stack multi { header: enum (mac | vlan | ip | udp | raw | ipv6 | tcp) { mac:1, vlan:2, ip:3, udp:4, raw:5, ipv6:6, tcp:7 } } — Sequence of headers in the generated packet: mac (Ethernet, 14 bytes), vlan (802.1Q tag, 4 bytes), ip (IPv4, 20 bytes), udp (UDP, 8 bytes), raw (arbitrary bytes as a hex string), ipv6 (IPv6, 40 bytes), tcp (TCP). Most header types may appear several times; there can be at most two IP headers and one UDP header per packet. Sequence limitations follow protocol rules (for example a VLAN header can follow only a mac header or another VLAN header).
  • port enum — Name of the port (from the port menu) the packets are sent out through. Mutually exclusive with interface; the port can also be set in the stream.
  • interface iface_enum — Interface the packets are sent out through. Mutually exclusive with port; convenient for quick tests since a port entry is then created dynamically.
  • mac-src multi { array-id, array-id, mac-mask: composite { mac: macAddr , mask: [ macAddr] } } — Source MAC address(es), with optional masks, of the Ethernet header.
  • mac-dst multi { array-id, array-id, mac-mask: composite { mac: macAddr , mask: [ macAddr] } } — Destination MAC address(es), with optional masks, of the Ethernet header.
  • mac-protocol multi { protocol: alt { protocol-name: enum () , protocol-number: num [ .. 65535] } } — EtherType of the Ethernet frame, by name or by protocol number (0-65535).
  • vlan-priority multi { priority: num [ .. 7] } — VLAN priority (0-7) of the 802.1Q tag.
  • vlan-id multi { id: num [ .. 4095] } — VLAN ID (0-4095) of the 802.1Q tag.
  • vlan-protocol multi { protocol: alt { protocol-name: enum () , protocol-number: num [ .. 65535] } } — VLAN protocol, by name or by EtherType number (0-65535).
  • ip-dscp multi { dscp: num [ .. 255] } — DS Field value(s) (0-255) of the IPv4 header (DS Field holds the DSCP and ECN values).
  • ip-id multi { id: num [ .. 65535] } — IPv4 identification value(s) (0-65535).
  • ip-frag-off multi { frag-off: num [ .. 65535] } — IPv4 fragmentation offset(s) (0-65535).
  • ip-ttl multi { ttl: num [ .. 255] } — IPv4 time-to-live value(s) (0-255).
  • ip-src multi { array-id, array-id, ip-range: ipRange } — Source IPv4 address(es), with optional masks, of the IPv4 header.
  • ip-dst multi { array-id, array-id, ip-range: ipRange } — Destination IPv4 address(es), with optional masks, of the IPv4 header.
  • ip-protocol multi { protocol-name: enum () } — IPv4 protocol, for example tcp, udp or icmp.
  • ip-gateway ipAddr — Next-hop IPv4 address. When the sender and the receiver are the same device the next hop cannot be derived from ip-dst; when ip-gateway is set, the destination MAC is assumed from the resolved gateway.
  • udp-src-port multi { array-id, array-id, port-range: range [ .. 65535] } — UDP source port(s) or port range(s) (0-65535).
  • udp-dst-port multi { array-id, array-id, port-range: range [ .. 65535] } — UDP destination port(s) or port range(s) (0-65535).
  • udp-checksum multi { array-id, checksum: num [ .. 65535] } — UDP checksum value(s) (0-65535).
  • raw-header multi { raw-header: string } — Raw header bytes as a hexadecimal string.
  • ipv6-src multi { array-id, array-id, ipv6-mask: ip6Prefix } — Source IPv6 address(es), with optional masks, of the IPv6 header.
  • ipv6-dst multi { array-id, array-id, ipv6-mask: ip6Prefix } — Destination IPv6 address(es), with optional masks, of the IPv6 header.
  • ipv6-next-header multi { protocol: enum () } — IPv6 Next Header protocol.
  • ipv6-gateway ip6Addr — Next-hop IPv6 address; the destination MAC is assumed from the resolved gateway.
  • ipv6-traffic-class multi { traffic-class: num [ .. 255] } — IPv6 traffic class value(s) (0-255).
  • ipv6-flow-label multi { flow-label: num [ .. 0xfffff] } — IPv6 flow label value(s) (0-1048575).
  • ipv6-hop-limit multi { hop-limit: num [ .. 255] } — IPv6 hop limit value(s) (0-255).
  • tcp-src-port multi { array-id, array-id, port-range: range [ .. 65535] } — TCP source port(s) or port range(s) (0-65535).
  • tcp-dst-port multi { array-id, array-id, port-range: range [ .. 65535] } — TCP destination port(s) or port range(s) (0-65535).
  • tcp-syn multi { array-id, array-id, syn-range: range } — TCP sequence number value(s), can be a range.
  • tcp-ack multi { array-id, array-id, ack-range: range } — TCP acknowledgement number value(s), can be a range.
  • tcp-data-offset multi { data-offset: num [ .. 15] } — TCP data offset (0-15, in 32-bit words).
  • tcp-flags multi { flags: ubit (fin, syn, rst, psh, ack, urg, ece, cwr, ns, res0, res1, res2) } — TCP flag bits to set: fin, syn, rst, psh, ack, urg, ece, cwr, ns, res0, res1, res2.
