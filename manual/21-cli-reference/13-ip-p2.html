connection

List of the IPv4 connections that connection tracking holds. All properties are read-only. See Connection tracking.

ip/firewall/connection

Type: Directory

List of the IPv4 connections that connection tracking holds. All properties are read-only. See Connection tracking.

Flag / Name / Description

  • E expected — The connection was expected by a connection helper (/ip/firewall/service-port), for example the data connection of an FTP session.
  • S seen-reply — The destination has replied: the connection has seen packets in both directions.
  • A assured — The connection is assured: it is not removed early when the connection list is full.
  • C confirmed — The connection is confirmed: its first packet has left the router.
  • D dying — The connection is being removed because its timeout has ended.
  • F fasttrack — The connection is FastTracked.
  • H hw-offload — The connection is offloaded to hardware.
  • s srcnat — Source NAT is applied to the connection, including masquerade.
  • d dstnat — Destination NAT is applied to the connection, for example a port forward.
  • h uses-helper — A connection helper of /ip/firewall/service-port handles the connection.

Read-only Argument / Type / Description

  • protocol enum () — Connection protocol.
  • src-address ipAddr — Source IP address of the connection.
  • src-port num — Source port of the connection.
  • dst-address ipAddr — Destination IP address of the connection.
  • dst-port num — Destination port of the connection.
  • reply-src-address ipAddr — Source IP address that the reply packets have. With destination NAT, it differs from dst-address.
  • reply-src-port num — Source port that the reply packets have.
  • reply-dst-address ipAddr — Destination IP address that the reply packets have. With source NAT, it differs from src-address.
  • reply-dst-port num — Destination port that the reply packets have.
  • tcp-state enum (none | syn-sent | syn-recv | established | fin-wait | close-wait | last-ack | time-wait | close | listen) { none:0, syn-sent:1, syn-recv:2, established:3, fin-wait:4, close-wait:5, last-ack:6, time-wait:7, close:8, listen:9 } — State of the TCP connection, for example syn-sent, established or time-wait. The state selects the timeout of the entry.
  • icmp-type num — ICMP type.
  • icmp-code num — ICMP code.
  • icmp-id num — ICMP ID.
  • gre-protocol num — Protocol of the payload that GRE carries.
  • gre-version num — Version of the GRE protocol.
  • gre-key num — Contents of the GRE key field.
  • connection-type string — Type that a connection helper has set, for example ftp, tftp or pptp. Empty when connection tracking cannot determine the type, for example on a related connection that a helper created.
  • timeout time — Time after which the router removes the connection from the list if it sees no more packets of it.
  • connection-mark string — Connection mark that a mangle rule has set.
  • orig-packets num — Number of packets sent from the source address of the connection.
  • orig-bytes num — Number of bytes sent from the source address of the connection.
  • orig-fasttrack-packets num — Number of FastTracked packets sent from the source address of the connection.
  • orig-fasttrack-bytes num — Number of FastTracked bytes sent from the source address of the connection.
  • repl-packets num — Number of packets sent from the destination address of the connection.
  • repl-bytes num — Number of bytes sent from the destination address of the connection.
  • repl-fasttrack-packets num — Number of FastTracked packets sent from the destination address of the connection.
  • repl-fasttrack-bytes num — Number of FastTracked bytes sent from the destination address of the connection.
  • orig-rate num — Current data rate from the source address of the connection.
  • repl-rate num — Current data rate from the destination address of the connection.

tracking

Settings and state of connection tracking. See Connection tracking.

ip/firewall/connection/tracking

Type: Settings Directory

Settings and state of connection tracking. See Connection tracking.

Argument / Type / Description

  • enabled enum (auto | yes | no) { auto:0, yes:1, no:2 } — Whether connection tracking works. - auto (default) - Connection tracking is off until the router has an enabled filter, mangle or NAT rule, separately for IPv4 and IPv6. RAW rules alone do not start it. - yes - Connection tracking works for IPv4 and IPv6, also without firewall rules. - no - Connection tracking is off. Firewall rules that need it, such as rules with connection-state and the masquerade rule, get the I flag and match no packets.
  • tcp-syn-sent-timeout time — Timeout of a TCP connection for which the router has seen the first SYN packet and no reply. Default: 5s.
  • tcp-syn-received-timeout time — Timeout of a TCP connection after the reply to the first SYN packet, until the handshake is complete. Default: 5s.
  • tcp-established-timeout time — Timeout of an established TCP connection that is idle. Default: 1d.
  • tcp-fin-wait-timeout time — Timeout of a TCP connection after the first FIN packet. Default: 10s.
  • tcp-close-wait-timeout time — Timeout of a TCP connection in the close-wait state, while it is closing. Default: 10s.
  • tcp-last-ack-timeout time — Timeout of a TCP connection in the last-ack state, while it is closing. Default: 10s.
  • tcp-time-wait-timeout time — Timeout of a TCP connection in the time-wait state, after both sides have closed it. Default: 10s.
  • tcp-close-timeout time — Timeout of a TCP connection in the close state. Default: 10s.
  • tcp-max-retrans-timeout time — Timeout of a TCP connection in which packets are retransmitted and not acknowledged. Default: 5m.
  • tcp-unacked-timeout time — Timeout of an established TCP connection while sent data is not yet acknowledged. Default: 5m.
  • loose-tcp-tracking bool — What the router does with a packet from the middle of a TCP connection that matches no entry of the connection list. - yes (default) - The router creates an entry from the packet, and the connection continues. - no - The packet is invalid.
  • liberal-tcp-tracking bool — Whether TCP tracking is liberal (the kernel parameter nf_conntrack_tcp_be_liberal). With no, a TCP segment outside the window of its connection makes the packet invalid. With yes, the router accepts out-of-window segments. This can let through malformed packets that the connection-state=invalid matcher would otherwise catch, and increases the exposure to certain evasion techniques. Enable it only to troubleshoot or to work around a known issue. Default: no.
  • udp-timeout time — Timeout of a UDP connection that is not a stream: it has seen packets in one direction, or a single request and reply. Default: 30s.
  • udp-stream-timeout time — Timeout of a UDP connection with packets flowing in both directions. Such an entry has the A (assured) flag. Default: 3m.
  • icmp-timeout time — Timeout of an ICMP connection, for example a ping. Default: 10s.
  • generic-timeout time — Timeout of connections of the protocols that connection tracking has no own timeout for, for example IPIP. Default: 10m.

Read-only Argument / Type / Description

  • active-ipv4 bool — Whether connection tracking works for IPv4 at the moment.
  • active-ipv6 bool — Whether connection tracking works for IPv6 at the moment.
  • max-entries num — Number of entries that the connection list can hold. It depends on the amount of RAM. The router does not create a list of the maximum size when it starts: the list grows when needed while free RAM is available, up to 1048576 entries.
  • total-entries num — Number of connections in the list, IPv4 and IPv6 together.
  • total-ip4-entries num — Number of IPv4 connections in the list.
  • total-ip6-entries num — Number of IPv6 connections in the list.

  • static switch — Switch of print: list only the static rules, which are the rules that were added to the configuration.
  • dynamic switch — Switch of print: list only the dynamic rules, which are the rules that the router adds itself.

A packet is not passed to the next firewall rule. - add-dst-to-address-list - add the destination address to the address list specified by the address-list parameter. - add-src-to-address-list - add the source address to the address list specified by the address-list parameter. - jump - jump to the user-defined chain specified by the value of the jump-target parameter. - log - add a message to the system log containing the following data: in-interface, out-interface, src-mac, protocol, src-ip:port->dst-ip:port, and length of the packet. After a packet is matched it is passed to the next rule in the list, similar to passthrough. - passthrough - if a packet is matched by the rule, increase the counter and go to the next rule (useful for statistics). - return - passes control back to the chain from where the jump took place. - drop - drop the packet. - reject - reject the packet and send an ICMP response. - tarpit - capture and hold the connection open. - fasttrack-connection - fasttrack the connection.
  • jump-target enum () — Name of the target chain to jump to. Applicable only if action=jump.
  • reject-with enum (icmp-network-unreachable | icmp-host-unreachable | icmp-protocol-unreachable | icmp-port-unreachable | icmp-net-prohibited | icmp-host-prohibited | tcp-reset | icmp-admin-prohibited) { icmp-network-unreachable:0, icmp-host-unreachable:1, icmp-protocol-unreachable:2, icmp-port-unreachable:3, icmp-net-prohibited:5, icmp-host-prohibited:6, tcp-reset:7, icmp-admin-prohibited:8 } — Specifies the ICMP error to be sent back if the packet is rejected. Applicable if action=reject. - icmp-network-unreachable - sends an ICMP port unreachable message. ICMP type 3, code 0 - icmp-host-unreachable - sends an ICMP port unreachable message. ICMP type 3, code 1 - icmp-protocol-unreachable - sends an ICMP port unreachable message. ICMP type 3, code 2 - icmp-port-unreachable - sends an ICMP port unreachable message. ICMP type 3, code 3 - icmp-net-prohibited - sends an ICMP address prohibited message. ICMP type 3, code 9 - icmp-host-prohibited - sends an ICMP address prohibited message. ICMP type 3, code 10 - tcp-reset - sends a TCP segment with the RST flag set. - icmp-admin-prohibited - sends an ICMP address prohibited message. ICMP type 3, code 13
  • hw-offload bool — Enables or disables FastTrack hardware offloading. Supported only on switches with FastTrack offloading and when action=fasttrack-connection is set.
  • tcp-flags super { !, , flags: multi { array-id, array-id, flag: super { ! , flag: enum (fin | syn | rst | psh | ack | urg | ece | cwr) { fin:0, syn:1, rst:2, psh:3, ack:4, urg:5, ece:6, cwr:7 } } } } — Matches the specified TCP flags: - ack - acknowledging data. - cwr - congestion window reduced. - ece - ECN-echo flag (explicit congestion notification). - fin - close connection. - psh - push function. - rst - reset connection. - syn - new connection. - urg - urgent data.
  • p2p super { ! , p2p: enum (fasttrack | gnutella | direct-connect | edonkey | bit-torrent | blubster | soulseek | winmx | warez | all-p2p) { fasttrack:0x01, gnutella:0x02, direct-connect:0x03, edonkey:0x04, bit-torrent:0x05, blubster:0x06, soulseek:0x07, winmx:0x08, warez:0x09, all-p2p:0xFF } } — Matches some unencrypted P2P protocols. Deprecated since mostly everything is encrypted and requires deep packet inspection to identify. IPv4 only.
  • connection-state super { ! , state: ubit (invalid, established, related, new, untracked) } — Interprets the connection tracking analytics data for a particular packet: - established - a packet that belongs to an existing connection. - invalid - a packet that does not have a determined state in connection tracking (usually severe out-of-order packets, packets with wrong sequence/ack number, or in case of resource over usage on the router). An invalid packet will not participate in NAT (as only connection-state=new packets do), and will still contain the original source IP address when routed. You should drop all connection-state=invalid packets in the firewall filter forward and input chains. - new - the packet has started a new connection or is otherwise associated with a connection that has not seen packets in both directions. - related - a packet that is related to, but not part of an existing connection, such as ICMP errors or a packet that begins an FTP data connection. - untracked - a packet that was set to bypass connection tracking in firewall RAW tables.
  • connection-nat-state super { ! , state: ubit (srcnat, dstnat, ein-snat, ein-dnat) } — Matches connections that are source-natted, destination-natted, or both. The connection-state=related connections' connection-nat-state is determined by the direction of the first packet, and if connection tracking needs to use dst-nat to deliver this connection to the same hosts as the main connection, it will be in connection-nat-state=dstnat even if there are no dst-nat rules at all. ein-snat and ein-dnat are source and destination nated connections when endpoint-independent NAT is used.
  • tls-host super { ! , tls-host: string } — Matches HTTPS traffic based on TLS SNI hostname. Accepts GLOB syntax for wildcard matching. The matcher will not be able to match the hostname if the TLS handshake frame is fragmented into multiple TCP segments.
  • connection-limit super { ! , limit: num , [netmask] ,num } — Matches connections per address or address block after a given value is reached. You should use this together with connection-state=new and/or with tcp-flags=syn because the matcher is very resource-intensive.
  • layer7-protocol super { ! , protocol: enum } — Layer7 filter name defined in the layer7 protocol menu.
  • realm super { ! , realm: num } — Matches the routing realm. IPv4 only.
  • protocol super { ! , protocol: enum () } — Matches the particular IP protocol specified by protocol name or number.
  • src-address super { ! , range: ipRange } — Matches packets whose source is equal to the specified IP or falls into the specified IP range.
  • dst-address super { ! , range: ipRange } — Matches packets whose destination is equal to the specified IP or falls into the specified IP range.
  • fragment super { fragment: bool } — Matches fragmented packets. The first (starting) fragment does not count. If connection tracking is enabled there will be no fragments as the system automatically assembles every packet. IPv4 only.
  • psd super { weight-threshold: num , [delay-threshold] ,time , [low-port-weight] ,num , [high-port-weight] ,num } — Attempts to detect TCP and UDP scans. Parameters are in the following format: WeightThreshold, DelayThreshold, LowPortWeight, HighPortWeight. - WeightThreshold - total weight of the latest TCP/UDP packets with different destination ports coming from the same host to be treated as port scan sequence. - DelayThreshold - delay for the packets with different destination ports coming from the same host to be treated as possible port scan subsequence. - LowPortWeight - the weight of the packets with privileged destination port (<1024). - HighPortWeight - the weight of the packets with a non-privileged destination port. IPv4 only.

hotspot

The /ip/hotspot menu lists the HotSpot servers of the router. One server runs on one interface. Use /ip/hotspot/setup to create a server together with the configuration that it needs. See the HotSpot guide.

ip/hotspot

Type: Directory

The /ip/hotspot menu lists the HotSpot servers of the router. One server runs on one interface. Use /ip/hotspot/setup to create a server together with the configuration that it needs. See the HotSpot guide.

Flag / Name / Description

  • X disabled — The server is disabled.
  • I invalid — The server is invalid, for example its interface does not exist.
  • S HTTPS — The server profile uses the https login method.

Argument / Type / Description

  • name string — Name of the HotSpot server.
  • interface alt { interface: iface_enum , interface: iface_enum } — Interface on which the server runs. To serve several ports, use a bridge interface, not a bridge port.
  • address-pool enum (none) { none:0 } — IP pool for the addresses of the clients. The server uses it to give a valid address to a client whose own address does not fit the network. none - the addresses of the clients are not changed.
  • profile enum — Server profile from /ip/hotspot/profile with the login methods, the HTML directory, and the RADIUS settings.
  • idle-timeout alt { symbolic-names: enum (none) { none:0 } , time-interval: time } — Time without traffic after which a host that is not logged in is removed from /ip/hotspot/host. Default: 5m.
  • keepalive-timeout alt { symbolic-names: enum (none) { none:0 } , time-interval: time } — Time for which a host that is not logged in can be unreachable before it is removed from /ip/hotspot/host. Default: none.
  • login-timeout alt { symbolic-names: enum (none) { none:0 } , time-interval: time } — Time after which a host that has not logged in is removed from /ip/hotspot/host. Default: none.
  • addresses-per-mac enum (unlimited) { unlimited:0 } — Number of IP addresses that one MAC address can use on this server. Default: 2.

Read-only Argument / Type / Description

  • ip-of-dns-name ipAddr — IP address to which the dns-name of the server profile resolves for the clients.
  • proxy-status string — State of the HotSpot service of this server, for example running.

active

The /ip/hotspot/active menu lists the logged-in users. Remove an entry to log the user out.

ip/hotspot/active

Type: Directory

The /ip/hotspot/active menu lists the logged-in users. Remove an entry to log the user out.

Flag / Name / Description

  • R radius — The session is authenticated by a RADIUS server.
  • B blocked — The network access of the user is blocked until the advertisement is shown.

Read-only Argument / Type / Description

  • server enum — HotSpot server on which the user is logged in.
  • user string — User name.
  • domain string — Domain of the user, if it is split from the user name.
  • address ipAddr — IP address of the device.
  • mac-address macAddr — MAC address of the device.
  • login-by string — Login method of the session, for example http-chap, mac-cookie, or trial. admin - the session is created with /ip/hotspot/active/login.
  • uptime time — Time since login.
  • session-time-left time — Time after which the user is logged out, from session-timeout or limit-uptime.
  • idle-time time — Time since the last traffic from the user.
  • idle-timeout time — Idle timeout that applies to the session.
  • keepalive-timeout time — Keepalive timeout that applies to the session.
  • bytes-in num — Bytes received from the user in this session.
  • bytes-out num — Bytes sent to the user in this session.
  • packets-in num — Packets received from the user in this session.
  • packets-out num — Packets sent to the user in this session.
  • limit-bytes-in num — Bytes that the user can still send.
  • limit-bytes-out num — Bytes that the user can still receive.
  • limit-bytes-total num — Bytes that the user can still send and receive together.
  • advertisement enum (disabled | sleeping | pending | pending,block) { disabled:0, sleeping:1, pending:2, pending,block:3 } — State of the advertisement for this user.

ip-binding

The /ip/hotspot/ip-binding menu sets how the HotSpot treats single devices: let them through without login, block them, or translate their address. See the HotSpot guide.

ip/hotspot/ip-binding

Type: Directory

The /ip/hotspot/ip-binding menu sets how the HotSpot treats single devices: let them through without login, block them, or translate their address. See the HotSpot guide.

Flag / Name / Description

  • X disabled — The binding is disabled.
  • P bypassed — The binding has type=bypassed.
  • B blocked — The binding has type=blocked.

Argument / Type / Description

  • mac-address macAddr — MAC address of the device.
  • address ipRange — IP address or address range of the devices.
  • to-address ipAddr — IP address to which the address of the device is translated.
  • server enum (all) { all:0 } — HotSpot server to which the binding applies. Default: all.
  • type enum (regular | bypassed | blocked) { regular:0, bypassed:1, blocked:2 } — What the HotSpot does with the device: - regular - the device logs in as usual; its address is translated to to-address - bypassed - the device has network access without login - blocked - the packets of the device are dropped
