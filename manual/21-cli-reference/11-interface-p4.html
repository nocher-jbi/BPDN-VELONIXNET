Trunking in the Cloud Router Switches provides static link aggregation groups with hardware automatic failover and load balancing. IEEE802.3ad and IEEE802.1ax compatible Link Aggregation Control Protocol is not supported. Up to 8 Trunk groups are supported with up to 8 Trunk member ports per Trunk group. CRS Port Trunking calculates transmit-hash based on all of the following parameters: L2 src-dst MAC + L3 src-dst IP + L4 src-dst Port.

  • I invalid

Argument / Type / Description

  • name string — Name of the Trunk group.
  • member-ports multi { array-id, port: enum } — Member ports of the Trunk group.

gre

Generic Routing Encapsulation (GRE) is a tunneling protocol originally developed by Cisco to encapsulate a wide variety of network layer protocols over an IP network.

interface/gre

Type: Directory

Generic Routing Encapsulation (GRE) is a tunneling protocol originally developed by Cisco to encapsulate a wide variety of network layer protocols over an IP network.

Flag / Name / Description

  • X disabled — Whether an item is disabled.
  • R running — Whether the interface is running.

Argument / Type / Description

  • name string — Name of the tunnel.
  • mtu num — Layer3 maximum transmission unit of the tunnel. Default: auto — the router subtracts the 24-byte GRE/IP overhead from the outgoing interface MTU (actual-mtu is 1476 on a 1500-byte interface).
  • local-address ipAddr — IP address used for the local tunnel end. If set to 0.0.0.0, the IP address of the outgoing interface is used.
  • remote-address address (flags=4Dv) — IP address of the remote tunnel end.
  • keepalive super { keepalive-interval: time [1 .. ] , [keepalive-retries] [ ,num [1 .. ]] } — The keepalive parameter sets how often the router checks the remote end of the tunnel: the router sends GRE echo probes to the remote end every KeepaliveInterval seconds, repeated up to KeepaliveRetries times. The minimum interval is 1 second and a 0-second setting is rejected. If the configured time and retries fail (the remote end does not answer the probes), the tunnel loses the running flag, about interval x retries after the last answered probe — about 100 s with the default. Without keepalive (unset), no probes are sent and the tunnel keeps the running flag even when the remote end stops answering; the tunneled traffic is then dropped until the remote end responds again. By default keepalive is set to 10 seconds and 10 retries. Parameters are written in the following format: KeepaliveInterval,KeepaliveRetries where KeepaliveInterval is the time interval and KeepaliveRetries is the number of retry attempts.
  • dscp num — DSCP value of the packet. Inherited means the DSCP value is inherited from the tunneled traffic.
  • clamp-tcp-mss bool — Controls whether to change the MSS size for received TCP SYN packets. When enabled, the router changes the MSS size for received TCP SYN packets if the current MSS size exceeds the tunnel interface MTU (taking into account the TCP/IP overhead). The received encapsulated packet still contains the original MSS, and only after decapsulation the MSS is changed.
  • dont-fragment bool — Whether to include the DF bit in related packets. Default: no — yes is rejected on RouterOS 7, only no and inherit are valid. - no - fragment if needed. - inherit - use the DF flag of the original packet.
  • ipsec-secret string — When a secret is specified, the router adds a dynamic IPsec peer to remote-address with a pre-shared key and policy (by default phase2 uses sha1/aes128cbc).
  • allow-fast-path bool — Whether to allow FastPath processing. Must be disabled if IPsec tunneling is used.

Read-only Argument / Type / Description

  • actual-mtu num — Actual maximum transmission unit of the tunnel.
  • current-remote-address ipAddr — Current IP address of the remote end.

ipip

IPIP (IP-in-IP) is a tunneling protocol defined in RFC 2003 that carries IPv4 packets inside an outer IPv4 header. The outer header uses IP protocol 4, which the firewall matches as protocol=ipencap.

interface/ipip

Type: Directory

IPIP (IP-in-IP) is a tunneling protocol defined in RFC 2003 that carries IPv4 packets inside an outer IPv4 header. The outer header uses IP protocol 4, which the firewall matches as protocol=ipencap.

Flag / Name / Description

  • X disabled — Whether an item is disabled.
  • R running — Whether the interface is running.
  • D dynamic — Whether the interface was created dynamically.

Argument / Type / Description

  • name string — Interface name.
  • mtu num — Layer 3 maximum transmission unit of the tunnel. Default: auto, which sets actual-mtu to the MTU of the underlying interface minus 20 bytes for the outer IPv4 header. A fixed value overrides this calculation.
  • local-address ipAddr — IP address on the router used by the IPIP tunnel. The remote router must reach this address as its remote-address.
  • remote-address address (flags=4Dv) — IP address of the remote end of the IPIP tunnel. The router must have a route to this address that does not use the tunnel itself.
  • keepalive super { keepalive-interval: time [1 .. ] , [keepalive-retries] [ ,num [1 .. ]] } — Sends keepalive probes to the remote endpoint and keeps the running flag only while the peer answers. The interface running flag is removed after KeepaliveRetries consecutive unanswered probes. Parameters are written in the following format: KeepaliveInterval,KeepaliveRetries where KeepaliveInterval is the time interval between probes and KeepaliveRetries is the number of retry attempts. Default: 10s,10. The interval must be at least 1 second and the retry count at least 1. The remote end must answer RouterOS keepalive probes; peers such as a Linux ipip tunnel do not, so unset the property for them. Unsetting keepalive disables dead-peer detection: the running flag stays set when the peer stops answering.
  • dscp num — DSCP value set in the outer header of tunnel packets. Default: inherit, which copies the DSCP value from the tunneled packet. A number marks the outer packets with that value instead.
  • clamp-tcp-mss bool — Controls whether to change the MSS size for received TCP SYN packets. When enabled, the router changes the MSS size for received TCP SYN packets if the current MSS size exceeds the tunnel interface MTU (taking into account the TCP/IP overhead). The received encapsulated packet still contains the original MSS, and only after decapsulation the MSS is changed. Default: yes.
  • dont-fragment bool — Whether to set the DF bit in the outer header. - no - clear the DF bit, so the outer packet can be fragmented. Default. - inherit - use the DF flag of the tunneled packet.
  • ipsec-secret string — When a secret is specified, the router adds a dynamic IPsec peer to remote-address with a pre-shared key and a transport-mode policy for the tunnel packets, using the default IPsec proposal. Keepalive packets are protected too. Both ends need the same secret. Requires allow-fast-path=no; setting the secret while FastPath is enabled fails with cannot enable fastpath together with ipsec yet.
  • allow-fast-path bool — Whether to allow FastPath processing. Default: yes. Must be disabled if IPsec tunneling is used. With FastPath, packets of an established flow can bypass the firewall, so the rule counters do not show every packet.

Read-only Argument / Type / Description

  • actual-mtu num — Actual maximum transmission unit of the tunnel: the largest inner packet the tunnel accepts. With mtu=auto it follows the MTU of the underlying interface minus the outer header size, and becomes smaller when IPsec is enabled.
  • current-remote-address ipAddr — Current IP address of the remote end.

interface/l2tp-server

Type: Directory

An interface is created for each tunnel that is established to the given server. There are two types of interfaces in the L2TP server's configuration: - Static interfaces are added administratively if there is a need to reference the particular interface name (in firewall rules or elsewhere) created for the particular user. - Dynamic interfaces are added to this list automatically whenever a user is connected and its username does not match any existing static entry (or in case the entry is active already, as there cannot be two separate tunnel interfaces referenced by the same name).

Dynamic interfaces appear when a user connects and disappear once the user disconnects, so it is impossible to reference the tunnel created for that user in the router configuration (for example, in the firewall), so if you need persistent rules for that user, create a static entry for him/her. Create MACsec interfaces on Ethernet links and inspect their Secure Channel (SC) and Secure Association (SA) statistics. Interfaces can carry a comment, and new interfaces are enabled by default. RouterOS uses matching static CAK and CKN values on both peers; automatic dot1x key provisioning is not available. The tx-sc-* and rx-sc-* rows are aggregate counters for each SC, while the tx-sa-* and rx-sa-* rows are arrays for individual SA slots. See MACsec for configuration, MTU, negotiation, and troubleshooting.

MACVLAN interfaces add virtual interfaces with their own MAC addresses on a parent interface. Several MACVLAN interfaces can share one parent.

Flag / Name / Description

  • X disabled — Whether an item is disabled.
  • R running — Whether the interface is running.

Argument / Type / Description

  • name string — Interface name.
  • mac-address macAddr — MAC address of the interface. When not set, RouterOS generates an address and stores it in the configuration, so it stays the same after a reboot.
  • mtu num — Layer 3 maximum transmission unit. Default: 1500. The value cannot be higher than the parent interface's MTU; if the parent's MTU is lower, set mtu when creating the interface.
  • interface iface_enum — Parent interface. Any interface with a MAC address can be used, including an Ethernet, VLAN or bond interface. An active bridge port cannot be used: creation fails with failed to create device and the log reports a busy parent.
  • mode enum (private | bridge) { private:1, bridge:4 } — Controls communication between MACVLAN interfaces on the same parent. bridge: the interfaces can communicate (default). private: they cannot; with either interface set to private, communication between them stops.
  • arp enum (disabled | enabled | proxy-arp | reply-only | local-proxy-arp) { disabled:0, enabled:1, proxy-arp:2, reply-only:3, local-proxy-arp:4 } — Address Resolution Protocol mode. disabled: the interface does not use ARP. enabled: it uses ARP (default). proxy-arp: the router answers ARP requests on behalf of other interfaces. local-proxy-arp: it answers on the same interface. reply-only: the interface replies only for static entries in the IP/ARP table and does not learn dynamic entries.
  • arp-timeout alt { arp-timeout: enum (auto) { auto:0 } , arp-timeout: time } — How long an ARP record is kept after no packets are received from the address. auto uses the value from /ip/settings, which is 30s by default. Default: auto.
  • arp-accept bool — Whether to accept gratuitous ARP (GARP) frames from devices that are not already in the ARP table. no: new entries are not created; yes: new entries are created. Default: no.
  • loop-protect enum (default | off | on) { default:0, off:1, on:2 } — Enables loop protection on the interface. default works as turned off. Default: default.
  • loop-protect-send-interval time — How often loop protect packets are sent on the interface. Default: 5s.
  • loop-protect-disable-time time — How long the interface is disabled when a loop is detected. 0 disables it forever. Default: 5m.

Read-only Argument / Type / Description

  • l2mtu num — Layer2 maximum transmission unit.
  • loop-protect-status enum (off | on | disabled) { off:1, on:2, disabled:3 } — Current loop protect state: off, on, or disabled.

ovpn-server

An interface is created for each tunnel established to the specified server. There are two types of interfaces in the OVPN server configuration:

interface/ovpn-server

Type: Directory

An interface is created for each tunnel established to the specified server. There are two types of interfaces in the OVPN server configuration:

  • Static interfaces are added administratively when you need to reference a specific interface name (for example, in firewall rules or elsewhere) created for a particular user.
  • Dynamic interfaces are added to this list automatically when a user connects and their username does not match any existing static entry, or if the matching static entry is already active, since two separate tunnel interfaces cannot use the same name.

Dynamic interfaces appear when a user connects and disappear when the user disconnects. Therefore, it is not possible to reference the tunnel created for that user in router configuration (for example, in firewall rules). If persistent rules are required for a user, create a static entry. Otherwise, dynamic configuration is sufficient.

  • D dynamic — Whether the server interface was created dynamically.

Argument / Type / Description

Read-only Argument / Type / Description

  • mtu num — Current MTU of the connection.
  • client-address string — IP address of the connected client.
