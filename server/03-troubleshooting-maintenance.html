Server & Infrastruktur BPTR (Bahasa Indonesia)

Troubleshooting, Backup & Maintenance Docker

Checklist & perintah yang berguna saat ada laporan aplikasi (e-monev, program.jambiprov, awasi, TTE) tidak bisa diakses atau berjalan lambat.

1. Cek status container

docker ps                 # semua container yang SEDANG berjalan
docker ps -a               # termasuk yang berhenti/crash (kolom STATUS akan
                            # menunjukkan "Exited (kode) ..." kalau bermasalah)

Kalau sebuah container "Exited" padahal seharusnya selalu jalan (restart: unless-stopped di compose-nya), coba jalankan ulang:

docker start <nama-container>
# atau, dari folder compose-nya:
docker compose up -d

2. Baca log

docker logs --tail 200 <nama-container>
docker logs -f <nama-container>      # ikuti log realtime (Ctrl+C untuk berhenti)

Untuk backend Go, ada juga file log lama out_backend-apps.log dan folder outlog/ di backend/ (log dari sebelum aplikasi dipindah ke Docker) — biasanya tidak relevan lagi untuk debugging terkini.

3. Disk penuh / hampir penuh

df -h /                     # cek persentase disk terpakai
docker system df            # rincian pemakaian disk oleh Docker (image, container, volume, build cache)
docker builder prune -af    # aman dijalankan — hanya bersihkan build cache lama

PERINGATAN

Jangan jalankan docker system prune -a --volumes tanpa memeriksa dulu — perintah ini bisa ikut menghapus volume data (termasuk datafile/ milik backend yang berisi file upload) jika volume tersebut sedang tidak dipakai container manapun saat itu. Gunakan docker builder prune (hanya build cache) sebagai pilihan pertama yang aman.

4. Rebuild image gagal

Image emonev_web (PHP/Apache, berbasis Debian) pernah gagal di-rebuild karena perintah apt-get update di dalam Dockerfile-nya exit code 100 (kemungkinan masalah mirror/registry paket Debian yang dipakai image dasar tersebut sudah usang). Untuk container ini, perubahan konfigurasi Apache dilakukan lewat bind mount (mengubah file konfigurasi di host langsung), bukan dengan rebuild image. Jangan asumsikan semua image di server ini bisa di-rebuild dengan mulus — service berbasis Alpine (backend Go, Nuxt) umumnya lebih aman untuk di-rebuild dibanding image Debian/Ubuntu lama.

5. Backup database

Untuk e-monev (database monevdb), sudah ada skrip siap pakai:

/home/bptr/apps/bidang-monev/emonev/backup-mysql.sh
/home/bptr/apps/bidang-monev/emonev/restore-mysql.sh

Hasil backup harian tersimpan di folder .../emonev/backups. Untuk database programdb (dipakai backend program.jambiprov), lakukan dump manual lewat tunnel SSH (lihat bab Arsitektur Server BPTR) atau docker exec ke container database-db-program-1 langsung:

docker exec database-db-program-1 \
  mysqldump -u root -p programdb > programdb-backup-$(date +%Y%m%d).sql

Simpan hasil dump di luar server (unduh ke laptop/penyimpanan terpisah) — jangan hanya disimpan di disk server yang sama (kapasitas terbatas & berisiko hilang bersamaan jika server bermasalah).

6. Alat bantu lain

Portainer agent (portainer_agent, port 9001) berjalan di server untuk mendukung manajemen Docker lewat GUI Portainer, jika dipakai dari instance Portainer pusat (tidak ada Portainer server lokal di host ini, hanya agent-nya).

Kebiasaan shell yang perlu diperhatikan saat menjalankan perintah di atas lewat skrip: Mac memakai sed -i '' (bukan sed -i polos), dan shell zsh tidak melakukan word-splitting pada $variabel tanpa quoting seperti bash — perhatikan ini kalau menyalin perintah dari skrip lama ke terminal interaktif.
