Menjalankan & Deploy Aplikasi program.jambiprov.go.id

Aplikasi publik program.jambiprov.go.id (e-Proposal/e-POKIR Bappeda-PUPR) sebenarnya terdiri dari 4 service Docker terpisah yang semuanya berjalan di server BPTR, di folder /home/bptr/apps/bidang-program/.

INFO

Routing domain/subdomain di atas ke port-port tersebut diatur oleh reverse proxy di luar server BPTR (bukan nginx/Traefik lokal). Jika perlu mengubah pemetaan domain atau memperbarui sertifikat TLS, koordinasikan dengan pihak yang mengelola DNS/reverse proxy tersebut — bukan dilakukan di server ini.

Start / stop / restart

Ketiga front-end Nuxt (admin-panel, proposal, sinkron) dikelola bersama lewat satu docker-compose.yml di root folder bidang-program:

cd /home/bptr/apps/bidang-program

# jalankan / pastikan semua (ulang) berjalan
docker compose up -d

# hentikan semua
docker compose down

# restart satu service saja, misalnya admin-panel
docker compose restart admin-panel

Backend Go dikelola terpisah (compose sendiri):

cd /home/bptr/apps/bidang-program/backend
docker compose up -d        # start / pastikan jalan
docker compose restart      # restart
docker compose down         # hentikan

Melihat log realtime salah satu service (ganti nama container sesuai tabel di bab sebelumnya):

docker logs -f web-proposal
docker logs -f backend-apps-proporsi

Update/deploy: front-end (admin-panel, proposal, sinkron)

Ketiga app ini adalah repo Git terpisah di GitLab (gitlab.com/program-pupr/e-proposal/<admin-panel|proposal|sinkron>). Alur update kode & deploy ulang:

  1. Tarik perubahan terbaru di folder app yang bersangkutan: 
    cd /home/bptr/apps/bidang-program/proposal   # contoh: app proposal
git pull origin main    # atau nama branch yang dipakai
  2. Build ulang image & jalankan ulang container-nya saja (dari folder bidang-program, bukan dari dalam folder app): 
    cd /home/bptr/apps/bidang-program
docker compose build proposal
docker compose up -d proposal

PERINGATAN

Build Nuxt (npm install && npm run build) berjalan di dalam image Docker setiap kali di-build ulang — proses ini bisa memakan waktu beberapa menit dan sedikit RAM/CPU ekstra saat berlangsung. Lakukan di luar jam sibuk jika memungkinkan, dan pastikan tidak menjalankan build untuk ketiga app sekaligus secara bersamaan di server dengan RAM terbatas (7,6 GB).

Update/deploy: backend Go

Berbeda dari front-end, source code backend Go tidak ada di server sebagai git repo — yang ada di server hanyalah binary hasil compile (backend-apps.bin) + config.yaml. Source code dikembangkan di komputer developer, lalu di-build untuk Linux dan dikirim (scp) ke server:

# Di komputer developer (contoh, sesuaikan path source sebenarnya)
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -o backend-apps.bin
scp backend-apps.bin BPTR:/home/bptr/apps/bidang-program/backend/

# Di server
cd /home/bptr/apps/bidang-program/backend
docker compose build
docker compose up -d --no-deps backend

Folder datafile/ (data/file upload) adalah volume yang dipasang ke container (lihat docker-compose.yml), bukan ikut di-bake ke dalam image — ini sengaja, supaya rebuild image tetap ringan dan data upload tidak hilang setiap kali di-deploy ulang.

Database backend

Backend Go terhubung ke database-db-program-1 (MySQL 8, database programdb) lewat host.docker.internal port 3310. Kredensial koneksi disetel sebagai environment variable di dalam backend/docker-compose.yml — nilai ini sensitif, jangan disalin ke luar server (lihat peringatan kredensial di bab Arsitektur Server BPTR).
